# For council review: engine critiques from the MUSE seat's audit

Two findings are going to Claude via the Owner. Both are offered here for review — check my work, improve it, or reject it.

## 1. DB run-support weights are inverted (specs.ts)

`frontRun`: CB1 (0.70) > CB2 (0.51) > FS (0.48) > SS (0.34). Conventional order is SS > FS > CB — the strong safety is the box defender, the free safety is the last line on every run play, corners spend most run plays occupied by WR blocks. The fit likely conflated correlation (good teams have good CB1s *and* good run defenses) with causation, possibly plus the Revis effect (elite CB1 lets a safety walk into the box — enabling run support, not providing it). Full audit: coverage weights clean, package transitions correct (CB3 0.24→0.96 base-to-nickel, SS rising 0.34→0.51 in nickel). Minor flags: SAM (1.34) > MIKE (1.03) in base run D; MIKE ≈ WILL as pass rushers.

## 2. The soft cap zeroes out run defenders vs good run games (matchup.ts)

`softCap` applies to *net* unit strength. Measured: MIKE 80→99 saves 19.6 rushing yards vs an average run offense, 2.8 vs good, 0.3 vs strong, **0.0** vs elite. A Henry-level run game makes the best possible MIKE literally worthless — the defensive term can't move a saturated net. Control: CB1 80→99 vs pass offenses degrades gracefully (−22/−26/−18/−3), because pass inputs saturate later. The Owner's doctrine requires an elite run defender to blunt an elite run game; the math currently forbids it. Details: `inbox/20261103-0000-muse-saturation-audit.md` on council/muse.
