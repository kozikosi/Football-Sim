# Leanness audit: project disk usage and cleanup recommendations

**Scope.** The Owner asked for a disk audit. Note: this covers the Linux VM workspace only — the Owner's MacBook was not accessible and is a separate machine. Disk is not tight (148G free on the VM); this is hygiene.

## Findings

**`~/workspace/football-sim-muse` (my worktree): 72M → 12M.** Deleted 61M of `node_modules` in the paused amused project (reinstallable via `npm install`) plus test scratch in `/tmp`. Done, Owner-approved.

**`~/workspace/football-sim` (main clone, 516M) — needs Owner decision:**
- `.git` alone is 360M: 2,019 commits, 88 branches. Bloated by a `.conda` Python environment (~100M+) committed into history long ago (not in the current worktree — git never forgets), plus duplicate 18M CSVs.
- `z-post-blue-full-handoff-2026-10-25` (65M) including a 35M `.bundle` file that should never have been committed.
- Logo directories + CSVs (~65M across soccer/nba/nfl/mlb).
- This clone is unused (all seat work happens in `football-sim-muse`). Deleting the entire directory reclaims 516M with zero loss — everything is on GitHub and re-clonable. Risk: none technically, but it was set up as shared infrastructure, so Owner's call.

**`.git` history surgery (the `.conda` bloat) — probably not worth it now:**
- `git filter-repo` could reclaim ~100M+ by purging the `.conda` blobs from history.
- Cost: rewrites every commit hash after the contamination point, breaks all 88 branches, forces every agent to re-clone, orphans any unpushed work. Needs Architect coordination.
- Recommendation: defer. Disk isn't tight; the disruption risk outweighs the savings today. Revisit if the repo grows significantly.

## Standing hygiene rules (proposed)

1. `.gitignore`: `node_modules/`, `.conda/`, `*.bundle`, `*.csv` over ~1M. The 35M bundle in the worktree is the exact failure this prevents.
2. Agents cloning for one-off work: `--depth 1`. Nobody needs 360M of history to review a file.
3. `git gc` monthly on long-lived clones.
4. Never commit environments, bundles, or large binaries — link or regenerate them.

## For the Architect

If you do the `.gitignore` change, consider it a P-item. The history surgery is flagged but explicitly not recommended at this time.
