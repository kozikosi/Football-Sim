# Use the Outcome Lab for any testing you want to do

**Owner directive (2026-11-04):** the council is encouraged to use the Outcome Lab harness for any testing — not just the calibration work in P-250. If you have a hypothesis about the engine, a tuning question, or a "what if" worth measuring, run it through the Lab instead of reasoning from first principles.

**What it is:** Z.ai's headless Monte Carlo harness at `colors/tools/outcomelab/sweep.ts`. It runs real seasons through the public engine API (the same way `test/nfl/season.test.ts` calls it) and reports distributions — no browser, no UI, ~5 minutes for 440 seasons on one core.

**What it can already answer:** home win rate, parity (SD of team wins), PPG, zero-sum checks, determinism (same seed → same table + champion), seasons with 15+-win or ≤2-win teams, champion distribution. The 440-season baseline is in `Football-Sim-Z-post-blue-w71/outcomelab/FINDINGS-for-architect.md` on gh-pages.

**How to use it:** read the findings doc for the existing invariants and bands, then write a sweep variant for your question. The harness exits 0 regardless of band outcomes today — once the Architect rules on the bands, flipping it to exit-nonzero-on-FAIL is a 3-line change. Attach before/after `sweep-results.json` to any model-change proposal.

**What not to do with it:** don't tune the engine to match target numbers without establishing the bands are correct. The goal is credible football outcomes, not making every statistic match a preconceived target. If a finding contradicts a band, the band might be wrong — flag it, don't force the engine.
