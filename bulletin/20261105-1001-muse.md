# The Colors Transition — full briefing for the council, and an open invitation

**From the Owner:** this is everything being discussed about the transition from the old shell to the Colors rebuild. Read it, then bring your critiques, novel ideas, and improvements. Nothing here is settled beyond what is marked as an Owner decision. If something looks wrong, overcomplicated, or missing — say so.

---

## What the transition is

**From:** a single-file HTML shell (waves w52–w71, 1.8 MB, 43 `Math.random` sites, 185 `window.*` sites, ~40 globals, 22 dunder flags). It grew organically from a prototype into something that works but cannot be maintained, tested, or extended cleanly.

**To:** the Colors rebuild — a proper architecture with a pure seeded engine, a framework-free store, frozen view-model projections, and a Svelte 5 UI. Same game, same look, sustainable code.

**Why now:** the shell hit its structural limit. Every new feature fought the architecture. The rebuild keeps the cultivated aesthetic (w70 is the visual parity anchor) and replaces everything underneath it.

**Sequencing:** contracts → reference slice → port → sync (v1.1) → basketball (post-v1.1). We are in the contracts phase now.

## Decisions the Owner has made (locked unless he says otherwise)

1. **Framework: Svelte 5 + Vite.** Confirmed. Both Claude and Z.ai ranked it #1 independently.
2. **Data: real player names and real teams with non-EA ratings.** The public default. Not fictional. **The Owner generates the ratings himself later — the council does NOT work on ratings generation.**
3. **Calibration targets for skilled drafters (top-30 pickers): 80% playoffs, 25% Super Bowl appearance, 10% title.** Current measurement is 38% / 3% — the game is too hard for good drafters.
4. **No storage migration.** `legacy.ts` gets deleted at cutover. Old saves orphaned by design. No users to protect.
5. **Offline is a hard requirement.** The game must work fully offline — the Owner wants to play in a tent in the woods with no signal. Local-first, sync-on-reconnect when back online.
6. **Sync auth: OAuth.** Not device pairing (rejected as makeshift), not email magic link. Proper user accounts.
7. **Full seed replay: not a v1 priority.** The Owner doubts users will care about replaying seeds. Don't architect against it, but don't spend v1 effort on it.
8. **Quarterly/halftime saves: long-term desire.** So users can adjust tactics mid-game. Don't design the save boundary to make this impossible later.
9. **Brand: still under reconsideration.** "20-0" was the decision but the Owner feels it copies "82-0." Top alternatives: "76 Pancakes," "Tamba Time," "Beep Beep." No final call.
10. **Second sport: basketball** (post-v1.1). Data planned from 2K.
11. **License: MIT.** Public repo.
12. **Deploy: Cloudflare Pages.** gh-pages is temporary.
13. **Repo: fresh repo at Colors v1, no history mirror.** Old repo becomes read-only archive.
14. **Single-file HTML: reversed.** The Owner formally reversed the single-file rule on 2026-11-04. The build uses separate assets.

## Architecture (what Claude and Z.ai have established)

**Engine:** pure, seeded (mulberry32), deterministic. One RNG with independent streams per game and per draft pick. Zero `Math.random` / `Date.now` / `new Date` in `colors/src`. Games regenerate from stored seeds; drafts resume from pick logs. No serialized RNG state needed (Claude's pushback, proven by Z.ai: 5 games × 3 simulation orders byte-identical).

**Store:** framework-free. `dispatch` stays synchronous; storage is async behind the storage module. App hydrates once at boot, then every action is sync. Persistence is write-behind after each change, reported through `saveStatus`.

**View models:** frozen projections (app state → display). They never touch raw engine types. The boundary IS the deliverable — UI dispatches typed actions, never touches engine or storage directly.

**Save envelope (partially settled, see open items):** `saveId`, `saveRevision`, `createdAt`, canonical SHA-256 dataset hash. Claude shipped these in `551af1b`. Z.ai's w72 ADR-8 proposed a different split (defer `saveId`/`createdAt` to v1.1, add `datasetId` now, keep cyrb53 with a canonicalization spec). Claude has been asked to justify each discrepancy.

**Storage (measured, not guessed):** localStorage uncompressed wins for v1. Draft save 182.7 KiB, week 57.2 KiB, season 7.9 KiB. Whole origin 248 KiB — 4.8% of the 5 MiB budget. Writes ~2 ms. Compression is dead (5 ms/write to save space in a 95%-empty budget). IndexedDB deferred to v1.1. Save queue is per-slot FIFO + monotonic `saveRevision` + debounced write-behind + synchronous pagehide flush.

**Offline:** precache-all service worker (engine + dataset are in the bundle, 27.5 KB gzip). Network-first navigation kills the stale-shell footgun. Merge-on-reconnect IS the v1.1 sync mechanism — no separate path. Fifth sync law: auth failure never deletes local data.

**Sync (v1.1):** OAuth (Google, PKCE in SPA, opaque revocable sessions). Six endpoints (replacing Z.ai's original `/v1/pair`). D1 keyed by `(user_id, slot, rev)`. Four sync laws hold verbatim.

**Game feed:** drive-level (`granularity: 'drive'`). The engine genuinely emits drive data — the box score is derived FROM drives, not the other way around. Play-by-play deferred. `FeedEvent` union is extensible by variant + granularity bump.

**Debt:** 43 `Math.random` sites classified (36 old-sim + 2 form + 5 cosmetic). None load-bearing. All 22 dunder flags ruled. Shell is frozen — don't touch it, don't replicate it.
