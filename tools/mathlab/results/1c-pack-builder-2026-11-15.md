## What exists now
The Phase 1 lab's stratified pools of real penalty-free plays (nflverse 2016-2022, kickoffs 2018-2022) are baked into one JSON pack, loaded in TypeScript, and a full game (two halves, kickoffs, tries, crude overtime) runs on it as an event log with **keyed draws**. Team totals are a fold over that log. This is the lab's simulator ported node for node (`sim.py` to `game.ts`), with one plumbing change: every random choice is `draw(gameKey, eventIndex, tag)`, so a play replays alone and a counterfactual shares randomness with the original.

**The pack is not a copy of 258k plays.** A pool is a distribution over unique outcome tuples (cell, tuple, count rows). Sampling a cell uniformly over plays and sampling a tuple by its count are the same distribution, so the pack is exactly the lab's pools. Bin edges are pack data (`params.bins`), so Python and TypeScript cut a state into a cell with the same numbers. Rules (`trans` empirical or computed, `clock` dt_f or dt_pf, point values, minimum pool sizes) are `rules.values`; the product-world switch is a pack rule, not code.

## What changed in shared code
`core/pack.ts`: `ParamValue` widened from "scalar, or a flat list of scalars, or one level of object" to plain JSON of any depth (with `null`). The pools pack holds tables of rows and nothing narrower can describe them. No runtime change; the type is wider, `tsc` count unchanged.

## Differences from the lab that I chose (INFERRED harmless, VERIFIED by item 1)
Keyed draws instead of one stream; kickoff clock spent as `min(kick seconds, clock left)`, the lab's `max(0, hs - dt)`; a counted last-resort pool instead of an arbitrary first pool; points and tries are separate events (the fold sums both). Kept as the lab had them on purpose: kneel and spike handling, overtime (always the non-late clock, no defensive touchdowns, computed transitions), the call and record hierarchies and their minimum pool sizes (25, clock 20).

## Not built, and why
- **The lambda seam in the pooled nodes.** The 1b slice has it (tilt on the pass result, inert at 0). On a pooled node it needs a class-then-tuple sampler (tilt the outcome-class probabilities, then draw a tuple inside the class). That is a Phase 2 shape question, and Phase 2's GLM nodes replace the pools. I would build it with the GLM node, not before. UNKNOWN cost.
- **Era choice.** The pack is fit 2016-2022 so the held-out 2023-2025 report is honest. A current-era product pack (the Owner's ruling 1) is the same baker with different years: `python3 -I tools/mathlab/phase1/bake.py --train <years> --kick <years> --id <name> --date <date> --out <file>`. Which years is the Owner's call; I have not made one.
- **Cross-engine agreement** (Safari, Firefox) and browser throughput: UNKNOWN.
- **Penalty-free world still has no penalty node**, as the lab: penalized plays were deleted from the pool, so their outcomes are selected (the lab's caveat in finding 3 stands).
