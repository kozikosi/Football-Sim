## A. Seam neutrality: OLD tree vs NEW code under `tableValues()` (VERIFIED)
All 120 drafts are pick-for-pick identical to OLD in every mode (cpu, greedy@5, favorites@5): 1024.0 of 1024 identical, 40 of 40 drafts with 0 differences, identical team net-points spread, flexed counts and user net points. Also: `tools/mathlab/flexcensus.mjs` self-check (its own solver vs `optimalLineup` under the table, 32 real rosters) reports max |value diff| = 0, and the regenerated `results/flexcensus-2026-11-10.md` is byte-identical to the committed file.

**A defect this check caught (fixed before merge):** the first table-mode run showed `greedy@5` diverging (12 of 40 drafts identical). Cause: `wins` used to be an integer (weight x integer gap), so ties such as 300 x 10 and 150 x 20 were exact and fell through to the OVR tiebreak; as floats, `(w * c) * gap` differs in the last bit and float noise broke the tie. Fix: candidate `wins` is rounded to the same 1e-9 grid, which restores exact ties. Re-run: 40 of 40.

## Risks and limits
- **Determinism (INFERRED, not measured):** the draft's values now come through `matchup.ts` (`Math.exp`, `tanh`, `pow`), which may differ in the last bits between engines. Values and candidate wins are rounded to 1e-9, so a last-bit difference moves a value only if the true value sits within about 1e-17 of a rounding boundary (roughly 1e-8 per value). Saved drafts are unaffected (replay applies the stored log). `core/pmath.ts` (S2) and the pack bake are the real fix.
- **Import cycle:** `value -> ratings -> lineup -> valueprovider -> value` exists (ratings imports `EMPTY_OVR` from lineup). `WINS_PER_UNIT` is therefore a literal in `valueprovider.ts`, checked equal to `WEIGHT_UNIT_WINS / 20` by a test. A TDZ crash caught this in the witness test before merge.
- **Lab tools:** `flexcap`, `flexeval`, `flextune`, `flexcensus` varied the fitted weights through `FieldSlot.weight`; they now pass `tableValues()` explicitly. Only `flexcensus` was run (above); the other three were syntax-checked only (UNKNOWN: behaviour).
- Cost: measuring all 32 values takes about 20 ms per base, cached per provider.
