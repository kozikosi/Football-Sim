01The agent contract

How to use this document, and what is expected of every agent that picks up the project.

The one rule

When this document and your instinct disagree, this document wins. When this document and the user's latest message disagree, the user's message wins — and the document is wrong and must be corrected in the same session.

Division of labour

The owner keeps three things for himself and for the senior model: football philosophy, mathematical design, and architectural decisions. Local coding agents implement and test. That split is deliberate. An agent that "improves" the matchup model without being asked has broken the most valuable thing in the project.

Owner

Decides what the product is. Corrects direction. Owns taste and judgment calls. Never asked to review diff noise.

Senior model

Writes doctrine, tunes math, makes architecture calls, produces implementation briefs.

Coding agents

Implement against a brief, run the test protocol, report evidence. Never invent product direction.

How to take a task

  1. Find the task ID in §9. If it is not in §9, it is not authorised — ask before building.
  2. Read the task's whole entry, including why. The why is what lets you handle the cases the brief did not cover.
  3. Check the invariants in §8 before your first edit. If your change would violate one, stop and report.
  4. Work on a copy. Never edit the canonical file in place. Save the result as a new numbered file, and put OC in the <title> and in the <h1>.
  5. Run the protocol in §11. Evidence, not assertions.
  6. Report in the fixed shape below.

Required report shape

FILE      name and byte size of the file you produced
CHANGED   what changed, in plain language, grouped by task ID
NUMBERS   the measurements from §11 that apply to your tasks
BROKE     anything you could not fix, or made worse, stated plainly
NEXT      the single highest-value task from §9 you did not do

Never report success you did not measure

"Should work" and "I believe this fixes it" are not reports. If you could not run the check, say which check you could not run and why. A short honest report is worth more than a long confident one. This project has already been burned by an agent claiming validation scripts existed that did not.

02What this product is now

A repositioning, not a feature. Read this twice.

For most of the project's life it presented itself as a power-ranking model that happens to have a draft and a season attached. The weights panel was centre-screen. The page opened on a draft board. The headline read NFL Team Power Ranking Model.

That is over. The owner's direction, verbatim in spirit:

The season simulation should be the core of the project from now on, and should be so visually. The website should really present the season as the whole website, and the Madden rankings and all the other tabs and weights are just a small supplementary part. They could be small links either to the bottom corner or centred at the bottom. Owner directive · 19 Oct

So the product is a draft simulator whose payoff is the season you play. Not a rankings tool. Not six equal tabs. One experience with a small appendix.

What the product is

Is

  • A 32-team snake draft against believable CPU general managers
  • A 17-game season you actually play through
  • A playoff run with recaps that name names
  • A season review that reads like a real one
  • A draft board that explains its own recommendations

Is not

  • A team power-ranking calculator
  • A weights playground
  • A Madden ratings browser (that data is an input, not the product)
  • A stats encyclopaedia
  • Six co-equal destinations

The three things a first-time visitor must understand in ten seconds

1

What this is

A title, one line, and a single obvious button. No instructions paragraph.

2

What just happened

Immediately after the draft: your grade, and a large Play a Season action sitting directly above the draft ranking.

3

Where they are in the season

A persistent, unmissable season spine — week, record, next opponent — never buried in a tab.

Delete on sight

This paragraph currently sits at the top of the app and must not survive:

NFL Team Power Ranking Model
Adjust any weight on the left — every team's score and rank recalculates instantly. Missing depth-chart slots are filled with a default of 70 OVR. Click any team row for a detailed breakdown.

Madden and weights may only be referenced inside the supplementary appendix. Nowhere else.

The hard separation of weights and season

These are two different products that share a roster data set. They must never be presented as one system, and the season must never mention the weights.

Specific instruction

Do not reference weights, weight sliders, or position weights anywhere in the season views or the 100-season review. If a sentence exists there that mentions weights, delete it rather than rewording it. The 100-season review is about football outcomes, not about a ranking configuration.

04Design language

The owner asked for beauty and motion, with errors fixable later. This is the language to build it in.

The feeling

Broadcast booth, not spreadsheet. A live game has a spine: score, clock, down and distance, and something happening. The site should feel like it is being played, not read. Numbers should look like numbers on a scoreboard — condensed, tabular, confident. Prose should look like good sports writing — plain, unhurried, generous line height.

Non-negotiables

Motion that means something

  • Scores count up rather than appear
  • Bars grow from zero on reveal
  • Week cards slide in on advance
  • A pick flashes once, then settles
  • Nothing loops. No ambient animation.
  • All motion respects prefers-reduced-motion

Hierarchy that survives a phone

  • One primary action visible at any moment
  • Tabular numbers everywhere (font-variant-numeric: tabular-nums)
  • No horizontal scroll at 390px — ever, on any view
  • Nothing important below the fold on first paint

Token set to keep

The existing palette is good and should not be reinvented. Extend it rather than replacing it.

The blue means one thing

--accent belongs to the user's team. It is not a generic link colour, not a hover colour, not a highlight for "important". Every time it is used for something else, the user's ability to find their own team in a wall of text degrades. Audit any new use against that rule.

Typography

  • Scores and statistics: tabular figures, slightly condensed, one weight heavier than surrounding text.
  • Prose: same size as body text. Post-game narrative has repeatedly been reported as too small — do not shrink it to fit a panel; widen the panel.
  • Labels: small, uppercase, letter-spaced, low contrast. Never the same weight as content.
  • Rem base: currently 21px on desktop and 16px at the phone breakpoint — a 31% jump. Pick one scale and make the breakpoint adjustment deliberate rather than incidental.

Mobile draft board — the specific problem

Symptom

On a phone the draft board stacks into cards. Each card is too tall, and once you scroll past the first few, you can no longer tell which number is which. The stat categories are invisible at the point of use.

Measured on the Season-first cut at 390 px: a player row is 243–260 px tall (ten stacked label/value lines, 23 px each); the thead is display:none; roughly two and a half players fit on a 844 px screen; the "Fills" cell wraps to three lines and splits the word change across two. There is no horizontal scroll — the problem is vertical, and it is the worst experience in the product.

Required behaviour

  1. Compress the card. One compact primary row: name, position, team, OVR, and the one number that matters (Value here). Everything else is secondary and smaller.
  2. Keep the labels attached. A number without its label is not information. The label must be visible on the value it belongs to, not floating in a header that scrolled away.
  3. Sticky category band. While scrolling the list, a pinned strip shows the current sort and the column meanings, so the reader never loses the key.
  4. Sticky primary action. The recommended pick stays reachable at the bottom of the viewport with a large tap target.
  5. Progressive detail. Tap a card to expand the full metric set. Collapsed by default.

The old approach — a MutationObserver that walks every table and writes data-label onto cells — is a workaround. It is allowed to remain as a fallback, but new layouts should emit labelled markup at render time.

05Football philosophy

What the model believes about football. Every number downstream inherits these beliefs.

1

Units, not individuals

A team is nine units: quarterback, backfield, receivers and tight ends, run blocking, pass blocking, pass rush, run defence, coverage, and kicking. Games are decided between units, not between all-pro lists.

2

Value is marginal, not absolute

A player is worth what he adds over the replacement you could have had at that slot. The 70-overall baseline is the anchor. Never price a player by rating alone.

3

Position scarcity is real and large

Quarterback and edge are worth multiples of guard and safety. The weights encode this and must stay internally consistent with the draft board.

4

Fit is a penalty, not a bonus

Playing out of position costs rating. Flexing is a legitimate strategy, not an exploit — the owner has said so directly. Never "fix" it.

5

Plans are independent

Offence and defence choose separately, and coaches are graded against the opponent's expected plan, never the actual one. That is deliberate: grading against the actual plan would teach the model to read minds.

6

Variance is the product

Upsets are the reason the season is watchable. The model should be well calibrated, not deterministic. Never reduce noise to make results tidier.

7

Real NFL output is the calibration target

Scoring, yardage, sack rate, and win distribution should look like a real season. The 2025 win correlation is the standing test.

Where the model currently cheats, and why it matters

A game is produced by four separate random processes stitched together: unit production, final score, scoring events, then player stat splits. The box score, the quarter score, and the recap are all consistent with the same final score, but they are not caused by the same game. That is the root of nearly every narrative complaint the owner has raised, including a defensive touchdown that appears in prose and then vanishes from the score. §6 is the fix.

06The one-game doctrine

The largest structural change available, and the one that retires the most bugs at once.

Current state

unit ratings ──▶ expected yards ──▶ noise ──▶ FINAL SCORE
                                              │
                                              ├──▶ decompose into TDs/FGs/safeties
                                              │     └──▶ scatter across quarters (weights 1, 1.05, 1, 1.15)
                                              │
                                              └──▶ split totals into player stats

recap prose  ◀── reads the scattered events, invents names and drives

Because the scatter is random and the score is already fixed, a team can "trail by 14 at the half" purely because its points landed in the third and fourth quarters. A defensive touchdown can be narrated that never entered the score. A walk-off score can be filed under the fourth quarter.

Target state

unit ratings ──▶ drive generator ──▶ ordered plays ──▶ everything else is a sum

  each drive:  field position ─▶ plays ─▶ outcome (TD / FG / punt / TO / safety)
  each play:   type, yards, personnel, defender, ball carrier, clock

  score    = sum of scoring plays
  box score= sum of all plays
  quarter  = bucketed by play clock
  recap    = a reading of the play list, in order

Under this doctrine, one source of truth exists and every view is a projection of it. The invariant becomes trivially checkable: the scoring plays must sum to the final score, and they must be in clock order.

Do this incrementally, not as a rewrite

A full drive generator is a large build. The minimum viable version keeps the existing matchup model for expected totals, then generates a play list whose sums are forced to match those totals. That is a bounded change and it fixes the ordering, the quarter assignment, the defensive score, and the walk-off placement in one move. Do not attempt a from-scratch engine rewrite.

Overtime — the specific rules

Current behaviour is wrong on two counts

  • The walk-off touchdown is rendered in the fourth quarter section of the timeline. It belongs in the overtime section.
  • It is narrated as sudden death ("the Cardinals never got the ball back"). Modern NFL overtime is not sudden death.

What to implement

  • Regular season overtime: ten minutes. Both teams are entitled to a possession unless the first possession ends in a touchdown. A field goal on the first possession does not end the game. If the score is still tied after both possessions, the game ends as a tie (or continues to a second period only if the rules in force say so — pick one rule set and state it in the Guide).
  • Postseason overtime: both teams get a possession regardless of whether the first ends in a touchdown.
  • The overtime period must have its own section in the timeline, with its own clock, and scoring there must never be filed under quarter four.
  • All overtime prose must be rewritten so it never claims the opponent "never got the ball" unless they genuinely did not.

Where a rule is simplified, say so plainly in the Guide ("simplified overtime"). Never claim you are modelling NFL overtime if you are not.

07Advanced stats taxonomy

What "generate advanced stats for every meaningful stat" actually means, and the one idea that makes it cheap.

Source material — received

The two documents the owner referenced arrived on 19 October 2026 as Sacks.webp and Sacksmol.webp in the repository root. They are Sack Index tables (career sacks per game divided by the league's sacks per game during the player's career, compiled by @jaydpauley) — a pass-rush reference, not a general taxonomy. The taxonomy below still stands on football first principles; the sack material is reconciled in the next subsection, and where the two disagree about sacks or pressure, the documents win.

The spine: every stat is expected versus actual

The simulation already produces expected values from the matchup model — expected rush yards, expected pass yards, expected turnovers. That is exactly what modern advanced stats are built on, and it is already in the building. So the rule is:

For every meaningful stat, report three numbers: what the model expected, what actually happened, and the difference. The difference is the player's contribution. This turns the whole app from a box score into an analytics page without inventing a single new simulation.

This yields, for free, the things real analytics sites sell: completion percentage over expected, rush yards over expected, and pressure rate over expected. No new randomness, no new model.

The Sack Index pass-rush calibration

The owner's two documents define one number worth adopting verbatim:

Sack Index = (sacks ÷ games) ÷ (league sacks per team-game over the same span). It removes the era and the league's overall sack rate, so a 1970s rusher and a 2020s rusher can be put on one line. A single season's index is naturally higher than a career's, because a career includes the decline years — compare like with like.

What the Season-first cut produces now

  • League rate: 2.17 sacks per team-game — inside the real band.
  • Sack leader over 100 simulated seasons: 14.8 average, 21 maximum; 0.03 seasons per league season with 20+.
  • Credit: 80.8% of sacks reach a player's line (953 credited against 1,179 team sacks in one measured season). The other 19.2% are discarded in buildDefenseDetail by an 18% continue meant to model a rotation.
  • The average leader's index is about .40, which is right while his raw total is about two sacks light — the league rate is slightly low and a fifth of the sacks never reach him.

Targets to assert, not to eyeball

  1. Credit ratio 1.000. Every sack names a player. A rotation sack goes to DL5 or LB4 by name, never nowhere. This alone lifts the leader to about 18.
  2. League 2.2–2.4 sacks per team-game.
  3. Leader 15–18 sacks, leader index .38–.45.
  4. 20+ sack seasons at 0.05–0.12 per league season — rare, not impossible.
  5. Interior rushers at 50–70% of an edge rusher's share at equal rating.
  6. Never compare raw sack totals across eras. Inside one season, raw sacks are fine; the moment the comparison crosses seasons, show the index.

Where it shows: the sack figure stays in the box score and the season line; the Sack Index joins the defensive-line leaderboard and the 100-season audit (mean leader index next to mean and max sacks). It is a context number, so it belongs on a details surface, not in a recap sentence.

Rules for shipping advanced stats

  1. Never invent a stat the simulation did not produce. If the play list cannot support it, do not display it. A missing stat is honest; a fabricated one is a lie.
  2. Advanced stats live on a details surface, never in the main recap or the main season line. The owner wants plain football language up front.
  3. Every advanced stat needs a one-line plain-English gloss on first appearance. "RYOE — how many more yards he gained than an average back would have behind the same blocking."
  4. Percentiles require a league context. Show "87th percentile edge rusher" only if a real league distribution was computed, not an assumed one.
  5. Do not let the stats layer change the simulation. It is a projection of the play list. If a stat needs a new input, that is an engine change and needs its own authorisation.

Regressions & new findings 19 Oct review

Found by reviewing the Season-first cut against this document. R1 is the most urgent because it makes a preview tell the reader about a game that has not happened.

R-1The division rematch tag must look backwards onlyreview · regression

Verified on a simulated season: a Week 2 division game with nothing played reads "Same division. They already met in Week 11: Bills lost 13–11." The tag now looks forward, which is worse than the "second meeting" bug it replaced. Cause: meetingInfo() keeps every other meeting and filters on x.played, not on whether it happened before this game.

Build: Filter on order, not on played state: regular season x.week < g.week; playoffs by round index; a playoff game may use regular-season meetings and earlier rounds. When nothing qualifies, say "first of N meetings" (N from the schedule), never "already met". Assert at Week 1–2 that no division tag contains the word met.

R-2Credit every sack to a playerreview · data defect

Measured: 1,179 team sacks against 953 credited player sacks in one season (80.8%). A box score that says three sacks can show player lines that add to two. It also depresses the sack leader to 14.8 and hides the top of the distribution the sack documents describe.

Build: Remove the 18% continue in buildDefenseDetail. Put the rotation share on DL5 and LB4 by name, with their own weights. Assert league-wide: sum of player sacks === sum of team sacks, to the last sack.

R-3The turnover paragraph must name the playersreview · P1-4 not done

Verified: "The Colts came out one turnover ahead, and how they happened is in the play-by-play above." The names exist one paragraph away, which is exactly what the owner asked to stop. The fallback is also wrong: statsNotes treats a defender's st.ff as a giveaway and pairs defenders to givers by array index.

Build: Make the head itself carry the giveaways: "Lamar Jackson was intercepted by Alontae Taylor in the first quarter" for a one-turnover game, and a comma list for more. The statsNotes fallback may only use passing st.int and st.fumLost, never ff, and may only name a defender who actually recorded the takeaway.

R-4Overtime must be possessions, not a synthetic scorereview · P1-3 partial

The engine still adds one 3- or 7-point event to the tied score, then narrates possessions it never simulated ("The Seahawks got their offensive possession, the Rams answered"). Under current rules a field goal on the first possession does not end the game, so the prose explains a sequence the model did not run.

Build: Two or three possessions with real outcomes: first possession ends in TD (game over), FG (opponent gets a possession that can tie, win with a TD, or lose), or nothing; then sudden death. Emit each possession as an event so the timeline and the narrative read from the same list. Regular-season ties stay possible; postseason cannot end level.

R-5Delete the duplicated document shell and refresh the labelsreview · hygiene

The file still opens with a second <!doctype html><html>…</body></html> wrapper around the real document (line 1 and the final line). Its :root{color-scheme:light} wins over the dark theme, so native controls render light on a dark page, and the nested document is invalid HTML. The h1 also still says "(OC v9)" (the build's own label).

Build: Delete both wrapper ends, leaving the real document lines. Move color-scheme onto the app's own :root and set it to dark with the light override kept. Replace the version label with a build number that matches the file. Keep the <title> in sync.

R-6550 ms of dead space before the draft boardreview · mobile

Measured at 390 px: four full-width selects and sixteen position chips sit above the first player, and the "Pick priority" panel is empty whenever the CPU is on the clock. The user scrolls two screens before seeing a player.

Build: One compact filter row (search + position + sort) with the rest behind a "Filters" disclosure; hide the priority panel when it has nothing to say; move the position chips under the same disclosure. Do this in the same pass as P0-5.

R-7The receiving leader is about 23% lowreview · calibration

The 100-season audit reports a receiving leader of 1,316 yards on average (max 1,520), while the modern NFL leader sits near 1,700 and the record is 1,964. No simulated season has reached 1,700. Passing volume and rushing totals are in band, so the shortfall is in the target distribution, not the offense.

Build: Measure the WR1 target and air-yard share across the league first. Then raise the top receiver's share of team targets rather than total passing yards, and re-run the 100-season audit until the leader averages 1,550–1,750 with a max above 1,800. Do not touch PT_PASS to do it.

R-8The 100-season run freezes the tab for 45 secondsreview · performance

Measured: 45.5 s of blocked main thread on a desktop Chromium, with no progress and no way to cancel. On a phone this reads as a crash.

Build: Yield between seasons (await new Promise(r=>setTimeout(r,0))) and paint "season 37 of 100" plus a Cancel button. Keep the full-detail path for the visible season; use the lite season for the sample. This is the T9 packet in MASTER_GUIDE.md.

P0-2Merge draft results into Seasonowner · directshipped

After 26 rounds the user lands on a results page with no obvious next step. The season is the payoff and must be one click away, above the ranking.

Build: On draft completion, the draft-results view becomes the Season tab's opening state. Play a Season renders immediately above the draft ranking, full width, visually primary. Remove the separate results tab.

P0-3Delete the rankings preambleowner · directshipped

The headline and instruction paragraph describe a different product and sit above the real one.

Build: Remove the h1 text "NFL Team Power Ranking Model" and the entire paragraph beginning "Adjust any weight on the left". The new headline names the draft simulator.

P0-4Remove weights from the season and the 100-season reviewowner · directshipped

Weights are a Madden-ranking configuration. The season does not use them. Mentioning them there implies a relationship that does not exist and has already caused confusion.

Build: Grep every season and 100-season string for weight, slider, ranking configuration. Delete rather than reword. Weights may appear only in the appendix.

P0-5Mobile draft board: compress and labelowner · directnot started

Cards are too tall and the stat categories become invisible on scroll, so the numbers lose meaning.

Build: Compact primary row (name, pos, team, OVR, Value here). Sticky category band showing the active sort and column meanings. Labelled values, never bare numbers. Sticky recommended-pick action with a large tap target. Tap to expand full metrics. Verify at 390px with zero horizontal scroll.

P0-6Auto-apply the recommended lineupowner · directshipped

A user who drafts inefficiently should not also be punished by playing an illegal or suboptimal lineup. The optimiser already exists and the CPU already uses it.

P0-7Remove the "Needs only" controlowner · directshipped

The draft board has outgrown it, and it introduces a hidden state where the board silently shows fewer players than exist.

Build: Delete the toggle. Fold its useful behaviour into the default sort: positions of need rank higher automatically. Remove any code path that renders a different list depending on it.

P0-8Delete the Guide preamble and the flexed-player sentencesowner · directshipped

The owner reports these as confusing and unhelpful: "The best flexed player out-values the best natural one even after the penalty…" does not teach a reader anything they can act on.

Build: Remove the "Guide: how this site works / Written for any football fan…" block entirely. Remove every instance of the "best flexed player out-values" sentence. If flex needs explaining, replace it with a single concrete example that names one player, one slot, and one number.

P1 — Narrative truth the recap must not lie

These are user-visible false statements. They damage trust more than any missing feature.

P1-1A defensive touchdown must persist in the scoreshippedowner · bug

Observed: the recap narrates "Bobby Okereke came up with the football — and it went the distance for a touchdown (Broncos 14–12)", but the Broncos' 14 did not survive — the quarter line ended 12–7 to the Chiefs. The prose and the score disagree.

Build: A scoring event emitted by the narrative layer must be the same object that contributes to the score. This is invariant 9. If the event exists in prose, it exists in the total.

P1-2Walk-off scores belong in overtimeshippedowner · bug

A walk-off touchdown is being filed under the fourth quarter.

Build: Give overtime its own timeline section with its own clock. Assert no overtime event carries q === 4.

P1-3Current NFL overtime rulespartialowner · direct

The model uses sudden death, which the NFL has not used for years, and narrates it as such.

Build: See §6. Both teams get a possession unless the first ends in a touchdown (regular season); postseason gives both teams a possession regardless. Rewrite all overtime prose. If simplified, label it simplified.

P1-4Turnovers must name the players involvedopenowner · direct

"The turnovers canceled out, 1 apiece" and "The Broncos came out one turnover ahead" carry no information. The owner wants to know who.

Build: Every turnover sentence names the player who forced it and the player who lost or intercepted it. Never a bare count. This applies to the summary line and to the timeline.

P1-5Label every scoring action by the team it helpedpartialowner · direct

In a bulleted quarter summary, the reader loses track of who benefited.

Build: Each line leads with the benefiting team. Keep the bullet-list rhythm but render without bullet glyphs — one line per action, generous spacing.

P1-6"Same division: a second meeting" must only appear on the second meetingpartialowner · bug

Observed on game two of the season, between teams that had not yet played. The label is derived from divisional membership, not from whether they have actually met.

Build: Compute the label from games already played, never from the schedule. If the two teams have not met, it is a division opener, not a rematch.

P1-7Head-to-head history in previewspartialowner · direct

The owner played the Colts in week three and again in the divisional round; the earlier meeting was never mentioned. Prior context is what makes a rematch feel like one.

Build: If the teams have played this season, add one sentence naming the week, the score, and one defining moment. Do it for regular season and playoffs. Reuse the stored recap, do not regenerate it.

P1-8"was not in this round" → "were not in this round"shippedowner · direct

Teams are plural in the owner's preferred register.

Build: Every team subject in a sentence takes a plural verb. Grep for the singular-verb pattern.

P1-9"and it went the distance" → "and he went the distance"shippedowner · direct

The return is made by a person.

Build: Grep the phrase. Audit similar pronoun slips in defensive-return narration.

P1-10A safety is not a two-point conversionopenGLM · verified

The two-point bucket is typed SAF unconditionally, so a successful 2-Pt Conv is credited to the opposing defence as a safety and adds to a defender's stat line.

Build: Split the bucket at decomposition time into SAF and CONV2 using a league-realistic ratio. Attribute CONV2 to the offence; attribute SAF to the defence. Update the timeline and box score.

P1-11Operator precedence in the late two-point swapopenGLM · verified

Verified at the current line: the second disjunct has no q < 4 guard because && binds tighter than ||. A fourth-quarter touchdown can be re-timed into an earlier slot, reordering the timeline.

Build: Collapse to a single predicate with the guard applied to both branches and a sanity check on clock order. Remove the duplicated term.

P1-12Attribution must not exceed the marginopenGLM · verified

The realised yardage channels are soft-capped, but the per-part swings used by the "how it was decided" paragraph are not. When a cap binds, the explanation can attribute more points than the game was won by.

Build: Compute the capped total, then rescale the parts proportionally so they sum to the realised channel. Assert invariant 11.

P2 — League integrity the numbers must be right

P2-1Real tiebreakersall three reviewers

Standings store only wins, losses, ties, and points. Ties break on head-to-head then point differential. Division record and conference record do not exist. Worse, a three-team head-to-head circle has no legal pairwise order, so the sort can hand a division to the team that lost it.

Build: Track division and conference record in freshStandings. Replace the comparator with a group-based sort: group by win percentage, resolve two-team ties by head-to-head, then division record, then conference record, then common games when at least four are shared, then point differential, then a terminal deterministic key. Never rely on insertion order.

P2-2CPU draft qualityowner · direct

Observed: Braden Smith drafted third overall; Will Reichard second overall. First-round picks should be believable, and a team that takes an unconventional position early must take the best player at it.

Build a round-dependent tolerance. The CPU's chosen player must be within tol(round) OVR of the best available at the targeted slot: R1–2 → 4, R3–5 → 6, R6–10 → 8, R11+ → 12. Round 1 additionally constrains the board to the top ~10 overall and requires every pick to be 90+. If a CPU takes a kicker, punter, or tight end in the first three rounds, it must take the highest-rated player at that position, and the reach must be explained by a real positional run. Replace the uniform deep "miss" with a bounded falloff of no more than ~12 candidates. Target: a careful user finishes top five; the CPU stays competent but beatable.

P2-3Post-draft first sentence compares to drafted teamsowner · direct

The first sentence of the draft recap compares the user's team to real NFL rosters. Those are different populations: the user's team was built by drafting against these 31 opponents.

Build: The opening comparison must be against the other 31 drafted teams only. Real-NFL comparison may appear later, clearly labelled.

P2-4League leaders: no horizontal scrollowner · direct

Reported on desktop and mobile.

Build: Fix the leaders table at both breakpoints. On phones it becomes stacked cards with visible labels. Verify 1440px and 390px.

P2-5Record caps never subtractGLM + Grok

Crossing a cap still replaces the total with cap − random(0–34), so season totals stop equalling the sum of game logs, and identical paces stall at different numbers.

Build: Refuse growth past the cap at accumulation time, deterministically. Never subtract. Display the capped value, do not mutate history.

P2-6Schedule fairnessGrok

Home games range to 6–12 and conference balance is unenforced, so schedule luck moves standings that the 100-season report treats as skill. If generation fails, Start Season throws with no message.

Build: Constrain home and away to 8–9 each. Keep a rough intra- versus inter-conference split. Catch generation failure and show a retry.

P3 — Craft when the above is done

P3-1Auto-save and resumeevery reviewer

There is no persistence at all. A finished draft and a week-12 season die on refresh.

Build: Versioned blob to localStorage after each pick and each week, inside try/catch. Offer Resume rather than auto-restoring. Include a discard path. Version the schema from day one.

P3-2Seeded simulationevery reviewer

Fifty-eight unseeded random calls. No season is reproducible, so no change is testable.

Build: One injectable PRNG with a visible seed. Narrative hashing stays deterministic and separate. The 100-season run may keep using the global RNG.

P3-3Draft gridreviewer

There is no way to see the draft as a whole: who took what, when.

Build: Round × pick grid on the results surface. Read-only, compressed, scrollable horizontally inside its own container.

P3-4Cancel long runs and surface errorsGrok

A 100-season run cannot be cancelled, and a swallowed exception leaves a frozen progress bar with no message.

Build: Cancel control on any long progress UI. Every long loop wrapped so a throw renders an error and a retry instead of a dead page.

P3-5Explain the board's own metricsreviewer + Tier 2

Wins, Value here, Priority, and Gone answer different questions and are routinely confused.

Build: One expandable explanation per pick, computed from the real numbers: quality, roster fit, wins added over the alternative, replacement risk, opportunity cost.

P3-6Accessibility floorreviewer

Sortable headers cannot be focused or activated by keyboard at all. Dialogs trap the user with no Escape.

Build: tabindex, role, aria-sort, Enter and Space on sortable headers. Escape and click-outside on dialogs. Names on icon-only controls. This is a floor, not an audit.

10Language & style

The prose is part of the product. These rules are enforceable by grep and should be.

RuleDetail
Plain football languageNo analytics jargon in the main recap. Advanced terms get a gloss on first use.
Critique only 85+Never criticise a player below 85 overall. Say nothing instead.
"2-Pt Conv"Never "two-point conversion", except inside the Guide.
No hedging fillerDelete "with no strong lean either way" everywhere.
No pre-game tense after the factNever "expected scoring" or "before kickoff" in post-game text.
Teams are plural"The Chiefs were", never "was".
People are people"he went the distance", never "it".
The user's team is blueReserved accent. Never reuse for anything else.
Name the actorsEvery turnover names who forced it and who lost it. Every score names who scored.
Stats near real recordsCaps stay, but they must never make totals inconsistent.

Make the style rules executable

Four of the rules above are one-line greps. Put them in the test runner so a regression fails the build instead of reaching the page: the banned hedge phrase, "two-point conversion" outside the Guide, "wasn't in this round", and "it went the distance". A rule that depends on memory is a rule that will be broken.

12Do not do

Things that have been decided, and should not be relitigated by a new agent.

Hard no

  • Split the distributed file. One file, opens by double-click, works offline.
  • Add a build step, bundler, CDN, or framework.
  • Add paid services, accounts, or a backend.
  • Busts, player progression, injuries, multi-year franchises.
  • Contracts, trades, commissioner tools, custom rulesets.
  • Web Workers, PWA, IndexedDB, TypeScript, Vite.
  • Invent player ratings, team assignments, or statistical outputs.
  • Change DEFAULT_WEIGHTS, FLEX, NATURAL_SLOT_MAP, or MC coefficients without explicit authorisation.

Do instead

  • Keep one deployable file; develop however you like, concatenate on release.
  • Use localStorage for persistence.
  • Spend the complexity budget on the season, not on league mechanics.
  • Treat a deeper CPU miss as the only permitted source of team spread.
  • Ask before touching the math; implement freely inside the brief.
  • Prefer deleting a confusing sentence over rewording it.

13Open questions

Where a wrong guess would change what gets built. Do not resolve these by assumption.

  1. Settled: overtime rule set. Keep regular-season ties possible and rare. The 100-season sample produces 0.34% ties; the NFL sits near 0.4%. No shootout, no coin-toss winner.
  2. Playing-time model. Some advanced stats (snap counts, pressure per rush, sack index) need a snap model that does not exist yet. Is a simplified per-game snap share acceptable? Current assumption: yes — a per-player share derived from slot and rating, used only for per-snap rates.
  3. Does the sack index reach the user? Current assumption: it joins the defensive-line leaderboard and the player season line, never a recap sentence.
  4. Does the appendix stay in the file, or become a separate page? Current assumption: same file, footer line.
  5. What happens to the draft tab after the season ends? Current assumption: it shows the completed draft read-only, with "start a new draft" as the only action.
  6. Which document is the source of truth? The root now holds AGENTS.md, MASTER_GUIDE.md, MASTER_DESIGN_DOCUMENT.md and this doctrine. They agree on the product and disagree on details (the guide still says Netlify; the repository deploys with GitHub Pages). Current assumption: this doctrine governs judgement, MASTER_GUIDE.md governs the packet sequence, and neither may contradict the other without an edit in the same session.
  7. What is NFL Draft Simulator - Season First.html? A 53 KB placeholder prototype with no player data, sitting in the root beside the real file. Move it to archive/ before an agent edits the wrong file.
