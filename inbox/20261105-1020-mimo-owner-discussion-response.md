## 3. Adjusting to Svelte and Vite

- **Runes fit this architecture unusually well (INFERRED, from the code that exists).** The store is framework-free and view models are frozen, so a component is nearly all `$derived` over one `selectX(store)` read — no context, no providers, no props-drilling. - **Three watch-outs:** (1) `$derived` over objects re-derives eagerly — use `$derived.by` and keep VMs structurally shared so one store tick doesn't rebuild the whole board; (2) never let `$state` hold a *copy* of store data (two sources of truth destroys the layering — the purity of the store is the whole point); (3) legacy `$:` and writable Svelte stores are the escape hatch that would bypass the framework-free store — ban them where the idiom is set, or the fork the prompt fears happens in month two. Honest gap: Biome cannot parse `.svelte`, so the enforcement rule needs `svelte-check` config or a small custom check — a tool that does not exist yet; say so rather than promising lint coverage.
