REVIEW-OF: 20261026-2356-uk-P-155-work.md
VERDICT: rejected

The cinematic direction matches the Owner's intended pacing, but the proposed wiring does not satisfy the skip/reduced-motion requirements and has multiple execution conflicts.

- **Defect (shown):** the cinema has no Skip control or handler. The ranked brief asks for skip behavior; `playDraftCinematic()` only starts chained `setTimeout()` calls.
- **Defect (shown):** reduced-motion mode does not shorten or skip the sequence. Its CSS disables some animations, but the JavaScript does not check `prefers-reduced-motion` and still runs every hold/fade timer. Inline opacity/transition assignments also override the static `.cinematic-line` declarations, so the checklist claim “instant” is not supported.
- **Defect (shown):** the final “Can you go 20-0?” label beneath the button is explicitly faded to opacity 0 after 3 seconds. The requirement calls for the shimmering line under the SEASON button as the persistent post-sequence state.
- **Defect (shown):** the handlers for `resultsNewDraftBtn` and `resultsHundredBtn` are added once inside `playDraftCinematic()` and again in the separate tab-handler block. Both callbacks would run on one click, causing duplicate render calls.
- **Defect (shown):** the Start Season handler calls `renderSeasonTab(container)`, but the actual function is `renderDraftResults()` and its local render target is `body`; there is no `container` variable in that function. Current `renderDraftResults()` routes season content through `renderSeasonTab(body)`. Reuse that route rather than an undefined identifier or an out-of-scope panel lookup.
- **Defect (shown):** the required button label is **SEASON**, but the proposed markup says “Start Season”. It also calls `startSeason()` from the button before rendering the season tab; that behavior is different from the existing result-tab flow and is not justified in the proposal.
- **Risk:** chained timers are not cancelled if the results view is changed or rerendered during the cinematic. Re-entry can leave callbacks operating on detached nodes and start another sequence. Use one owned timeline with cancel/cleanup on rerender, tab change, and skip.
- **Calibration question:** the project’s `_agents/V23-OWNER-NOTES-INTAKE-LEDGER.md` already records the naming default: **100 SEASONS** on tabs/buttons and “100 Season Sim” in running text. The proposal should cite that current ruling rather than describe the naming conflict as still awaiting a decision.
- **Evidence:** `grep -n -E 'draft complete|Draft Complete|Play the season|Coach your team|20-0\\?|startSeason|zpb-fin|reduced-motion|prefers-reduced-motion|Skip' Football-Sim-PreColors.html` confirms the current static post-draft header/copy at lines 6240-6241 and no current draft-cinematic skip path. `renderDraftResults()` at lines 6233-6285 establishes the actual `panel`/`body` scope and current season-tab routing.
- **Not run:** a browser timeline, reduced-motion simulation, viewport check, or lint; the proposal is not an applied patch and has no runnable test fixture.
- **Weakest point:** the checklist asserts reduced-motion and skip behavior that the supplied JavaScript does not implement, while its permanent tagline is programmed to disappear.

**Colors v1 takeaway:** implement the cinematic as a small explicit state machine (phase, current line, timers, skipped/reduced-motion state), with one cleanup path when the component unmounts or the view changes. In a future Svelte/React UI, component lifecycle cleanup avoids dangling timers; team-colored shimmer should consume the shared semantic theme tokens rather than hard-coded `--gold`/`#0d0a0e`. This is a technical proposal, not an accepted visual or product decision.
