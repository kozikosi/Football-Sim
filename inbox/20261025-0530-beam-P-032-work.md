--- D-012 math (3-4 trades DT2 for ILB2) ---

The Owner's directive: "the 3-4 replaces one defensive tackle with a second inside linebacker relative to the 4-3."

In the wins math:
- In 4-3: DT2 (DT slot, n=2 for DT team unit) is on the field. DT2's OVR contributes to DT team unit and DL team unit.
- In 3-4: DT2 comes off, ILB2 (MIKE/WILL slot) comes on. ILB2's OVR contributes to LB team unit and FRONT7/DEFENSE units. DT team unit drops to n=1 (DT1 only). LB team unit increases to n=4 (MIKE+WILL+SAM+ILB2).

Code impact:
- groupAvgForTeam() and groupAvgFromPool() (l.~580-620) compute team unit averages from roster slots. The `n` field in GROUP_DEFS specifies how many players to average. For 3-4, DT (n=2) would need n=1, and LB (n=3) would need n=4.
- But GROUP_DEFS is static (l.455). The `n` field doesn't change based on base. So the 3-4 base would need either: (a) a dynamic GROUP_DEFS that adjusts n based on base, or (b) the lineup editor marks DT2 as "inactive" in 3-4 and ILB2 as "active", and the averaging skips inactive slots.

Recommendation: option (b) — mark slots as active/inactive based on base; averaging skips inactive slots. This is simpler and doesn't require changing GROUP_DEFS.

Affected GROUP_DEFS entries:
- DT (n=2 → n=1 in 3-4): "Defensive Tackles (DT1+DT2)" → in 3-4, only DT1.
- LB (n=3 → n=4 in 3-4): "Linebackers (MIKE+WILL+SAM)" → in 3-4, MIKE+WILL+SAM+ILB2 (but ILB2 is a MIKE slot, so it's MIKE1+MIKE2+WILL+SAM).
- DL (n=4 → n=3 in 3-4): "Defensive Line (DT+Edge)" → DT1+DE1+DE2.
- FRONT7 (n=7 → n=6 in 3-4): DL(3)+LB(3) → DL(3)+LB(4)? No, FRONT7 = DL+LB = (DT+Edge)+LB. In 3-4: DT1+DE1+DE2 + MIKE1+MIKE2+WILL+SAM = 7. Same count, different composition.
- DEFENSE (n=13 → n=12 in 3-4): DL(3)+LB(4)+Secondary(6) = 13. Same.
- ZONE (n=8 → n=9 in 3-4): LB+Secondary = 4+6 = 10? No, ZONE = CB+MIKE+WILL+SAM+FS+SS = 6 in 4-3, 7 in 3-4 (extra MIKE). 

This is getting complex. The cleanest approach: don't change GROUP_DEFS n values. Instead, in the lineup editor, when 3-4 is selected, mark DT2 as "bench" (inactive) and add ILB2 (a second MIKE) as "active". The group averaging should skip inactive slots and include active ones. This requires the averaging code to check slot active/inactive state.

- flexRule (l.955): flex penalty calculation.

Edge cases:
- If a team has no DT2 (null in TEAM_DATA), the 3-4 trade is moot (DT2 already empty).
- If a team has no ILB2 (no second MIKE), the 3-4 is weaker (missing a LB).
- The flex table (l.1250) should show ILB2 as a slot in 3-4 mode, not in 4-3.
- The "Flex x (-y)" display should account for base-dependent slot availability.
