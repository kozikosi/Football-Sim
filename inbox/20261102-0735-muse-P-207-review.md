## Verdict: improved (sound contract, four gaps to close)

The contract is fundamentally right: envelope-over-opaque-payload, facade isolation from `colors/src/engine/**`, version stamps solving the resume-after-DB-update problem, typed load results, and the five questions for Z.ai are the right five. The gaps below are additions, not corrections.

### Gap 1 (substantive): the atomic stats-update mechanism is unspecified

Assessment §C: "Global stats are updated from this, once, atomically with the slot write." Contract §3: "Facade API takes and returns envelopes only."

If stats recording is two facade calls — `save(slot, envelope)` then `stats.update(delta)` — the `statsRecorded` flag alone does not give atomicity:
- Crash between the two calls (stats updated, envelope not saved): reload shows `statsRecorded=false` → double count.
- Crash in the reverse order (envelope saved with flag, stats not updated): stats permanently missed.

**Recommendation:** one sentence in the contract — either `save(slot, envelope, statsDelta?)` applies both writes in a single task, or the idempotency protocol is documented (e.g., stats deltas keyed by envelope id, applied idempotently on load). Z.ai's Phase 0 must pick one; the contract should require it.

### Gap 2 (small): achievements store has no facade API

Contract §2 requires "global stores (profile, settings, stats overall AND by franchise, achievements...)". Contract §D's facade list names `stats.read/update`, `settings`, `profile` — achievements has no read/update entry. Add `achievements.read/unlock` (or fold into the stats API explicitly).

### Gap 3 (small): soft-delete vs "next free slot" is ambiguous

`delete(slot)` is soft. Run-it-back "goes into the next free slot silently." Is a soft-deleted slot free? Does the slot selector show soft-deleted slots (for undo) or hide them? One line defining soft-delete semantics — visible-with-undo vs hidden-and-reusable — closes it.

### Gap 4 (small): `SlotMeta` shape undefined; "envelopes only" overstates

Contract §3: "Facade API takes and returns envelopes only" — but §D has `list() -> SlotMeta[]`, which is not an envelope. SlotMeta is the right idea (the Continue screen needs team, year, week, record without parsing payloads); it just needs its fields defined in the contract, and the "envelopes only" sentence softened to "envelopes and slot metadata."
