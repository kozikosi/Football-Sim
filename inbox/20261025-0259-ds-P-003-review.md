## Why rejected

1. **No contrast table, and the light accent fails it.** P-003's brief asks for the ratio of every text/background pair and a deeper gold only where small text fails. `--accent:#b8941f` is used for `button, .tabbtn, .posbtn, .resetbtn, a` — small text — at **2.68:1**. `#8f6a0e` (4.62:1) is the value that works; it is mentioned in the inbox file but not used in §31.
2. **Light mode cannot be built from §31 as written.** The `body` rule after the light-mode block is unconditional: `radial-gradient(…#1a1014 0%, #0d0a0e 60%)`. With light `--text:#2a1a20` that is **1.19:1**. The light branch must set its own body background (or use `var(--bg)`).
3. **A token swap cannot deliver "no orange / no blue panels".** The product keeps hard-coded colours outside the variables: the hero gradient (l.227, blue + orange), `--glow` blue (l.217), `#startSeasonBtn` orange gradient (l.250), `.mtag-riv` orange (l.128), `.mtag-div` blue/purple (l.127), the h1 gradient to `#9cc2ff` (l.231), `.tabbtn.active` and `.resetbtn` gold→`#6aa6ff` (l.246–247), `.dc-val` blue (l.268), `.sf90` amber (l.113–114). None is inventoried or replaced by §31.
4. **The "all numbers gold" rule targets classes that do not exist.** `.num`, `.ovr`, `.record-digit`, `.val`, `[data-num]`, `.player-name` are absent from Pre-Colors; the real numeric classes include `.dc-val` (blue today) and `.dc-wins`. The proposal needs the actual product selectors, not a generic set.
5. **`--accent2:#f5f0f0` breaks three text sites.** `.xf` (l.62), `.chip .star` (l.198) and `td.dc-gone` (l.270) use `var(--accent2)` as text → **1.09:1** on a light panel. In dark it is white text and fine; in light it is invisible. `--accent2` also partners gold in two bar gradients (l.51, l.95), so the replacement has to serve both roles or the uses must be split.
6. **Button states are not covered.** `button { color: var(--accent) }` over the product's `.resetbtn` gradient (l.247) gives gold on blue at **1.17:1**, and white on a gold button is **2.10:1**. The main Start Draft button needs an explicit background/text pair in both modes.
7. **Team tint line is not valid CSS.** `--tab-tint: rgba(teamPrimary, 0.04)` cannot be computed; it needs a channel triplet (`--team-primary-rgb`, as the prototype line 3 has and §31 omits) or `color-mix(in srgb, var(--team-primary) 4%, transparent)`. `--tab-tint` does not appear in §31 at all.
8. **Light mode is new work, not inherited.** The named north star is dark-only, so every light value needs measurement. The brief assumes that measurement; this file says "WCAG AA" in HOW TO CHECK but supplies none.
9. **Reduced motion is partial.** §31 stops the shimmer and panel transitions but not `heroBounce` (l.229–230) or the remaining product animations; hover `transform` still applies.
