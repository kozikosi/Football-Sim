## Findings

1. **Re-target, don't patch.** This spec targets the frozen Pre-Colors reference, where there is no palette helper, no Cinzel, and (per glyph) no shimmer plumbing. The palette source (`TEAM_COLORS`), the font path (embedded woff2), and the natural shimmer home (`.cp-shimmer*` / w89's existing shimmer handling) all exist in colors/ and cakepanz/. **The Architect should re-issue P-163's brief against colors/** (or, explicitly, against the wave if the Owner wants the preview in the live product), and the card spec then derives from `TEAM_COLORS` + the existing shimmer law (P-111/P-183) without invention. Pre-Colors keeps its Georgia and its neutral gold; it is frozen for exactly this reason.
2. **The artifact-string hunt repeats the P-160 disease.** "quarterback play +3.3 pass protection" is not in the reference; the Owner saw it somewhere — one command owed: `git grep -i -E 'quarterback play \+3\.3|pass protection:? ?\+3' origin/gh-pages` (and colors/ if it is built there already). If it is absent everywhere, the Owner's note is stale or paraphrased; the *removal* then means: no substring filtering (which kills real lines) — instead scope the removal to the artifact's exact shape once located.
3. **Font ruling, with measurements attached** (Owner needs exactly this to decide in one word): (a) Georgia fallback (status quo everywhere w89 shows Cinzel today) — zero bytes, off-brand on machines without the font; (b) embedded subset woff2 ×2 weights (the cakepanz precedent) — ~20–40 KB, exact identity offline, one-time subset step; (c) `font-display: swap` + preconnect — violates offline, out of order. **Recommend (b)**, with the subset cut to the preview screen's glyphs only (letters, figures, apostrophe, en-dash).
4. **Star emojis team-coloured and shimmering** is feasible only with the palette re-target (finding 1): star = TEAM_COLORS[team][0] at ≥90 OVR; shimmer = the existing 90+ shimmer law; `prefers-reduced-motion: reduce` must kill the twinkle (w89's global reduced-motion rule already collapses these — reuse it, don't add a parallel gate).
5. **Card-one-per-line**: consistent with P-152 (draft-board cards, REVIEWED ✓✓✓) and P-162's migration ladder; the playoff preview should reuse whatever card component wins P-162's ladder, not mint a third shape. UK's "one per line" requirement is honoured by either.
6. **"Playoff picture text in palette colours"** — partial by inheritance: wrap the panel in team-tint (`var(--zpb-t1)`-style) for the user's team (the colors/w89 team-remap machinery already recolors panels per team), but **do not** recolor the body copy of the preview prose per-line — one accent family per team (t1/t2/t3) with sufficient contrast is the Owner's palette discipline; the w89 zpb-remap already enforces it globally and the preview text should inherit, not paint. Contrast re-measure owed for any per-line colouring (the two live failures on record — 3.17:1 rose-ink on plum, 1.51/1.65:1 light gold2 on rose — show how this panel would fail silently).
