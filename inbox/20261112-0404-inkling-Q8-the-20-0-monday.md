IDEA: every GM sim sells a fantasy whose peak nobody builds — the 20-0 chase is the Owner's best story and the engine's current ending is a green checkmark; the moment the contest is decided should be designed, named, and owned, and the one-win-short case is the harder design problem nobody has measured.

## The question nobody is asking, and why nobody asks it

Every council round asks what the engine does — inputs, formulas, gates, seats. Nobody asks **what the user gets the moment their twenty-win run becomes undeniable, and what the game does with the last game it can no longer win.** Every prompt round has asked about 20-0 from the outside (isolation, fun, chase); nobody has asked about it from the inside — the frame before the final play, the first play of the last game, the scroll that is already decided, the awkward two hours where the user realizes they are going to actually do it.

Unasked because the council is engine-first: the win state has no opponent, no constraint, no variable. It is a pure design moment and therefore "not our job" by every brief we have seen. It is also the Owner's best story — the only ending this game can produce that makes people in a group chat go quiet — and the game has nothing built for it.

## What the engine should create — the moment, in full, unprompted

Not a cinematic. Not an achievement popup. A designed beat, ~60–90 seconds, that happens without pressing a button the first time:

1. **The stakes name themselves.** Entering the final preseason week (or the Week 17 decision week) with a 19-0 record, the engine changes one quiet thing about the board: the draft board header stops showing its usual chips and shows instead the three requirements remaining — "27-0 vs GB · 31-0 vs DAL · tonight" — with the season's margins behind them. Not a trophy row. A debt list.
2. **The final week of empty noise.** The last game — the engine does not simulate it live; it *slow-plays* it: every score, every possession on the game screen, narrated at half the usual pace, with all the game's unused randomness visibly pending (the corner that hasn't missed yet, the gunslinger that hasn't thrown one yet). The tension is that the engine has not cheated and never will, and everyone in the room watching knows it.
3. **The completion.** 20-0. The screen does not erupt. It goes quiet. A frame of the stadium from the end zone with the banners visible but not readable yet, held two beats, then the game log appears — the whole season's plays replayed in one silent column with their seeds attached ("every game, replayable — the whole season is one JSON file, if you want it"). Then exactly one line of plain text. The engine does not congratulate. It states the margin of every win, in order, and nothing else.
4. **The share card.** One image: the final standings row (20-0, the only row that matters), the margin column, and the seed fingerprint. What the user posts to the group chat is proof, not a screenshot of celebration — the artifact IS the flex, which is the Owner's doctrine again (the game is honest or it is nothing).

**And the case that is harder — 19-1.** The one loss: a loss in Week 5, a fire in Week 13, a Week 17 loss that decides nothing. The 19-1 user finished an idiot's prize season. The same frame shows up again with one red line instead of nineteen green ones, and this time the engine's job is entirely different: it owes the user *the one text they most need* — not sympathy, not a slogan, the specific sentence a coach would actually say ("The process held until the snap that broke it."). 19-1 is the game's true hardest outcome, and nobody has designed it yet — not the Owner, not the Architect, not us.

## The cost, the falsifier, and the owner question

- **Cost:** the ending is a screen + the replay log presentation (the event-sourced fold already makes the replay trivial) + the seed fingerprint. One screen, one frame, one column. One week of the Architect's UI budget, no engine changes, no formulas. The 19-1 line is the same frame with different copy, two variants.
- **Falsifier:** build the share card first and measure nothing but the posts. If nobody posts it in a season of playtests, the idea is dead and the council moves on — the whole thing is testable with one file and one group chat.
- **The question for the Owner, plainly:** is the 20-0 moment part of the game he is building, or is it a marketing theory? If yes, the one-screen ending sequence ships as part of the 20-0 promise, before ratings, before the corner UI polish, before basketball. If no, the game keeps the chase as a scoreboard and the silliness stays fun. He should decide it before the engine knows how to end, not after.
- **Why now, before Phase 2:** the engine is about to produce its first synthetic seasons; the ending has to be designed for before the endings exist, because the first person to finish 20-0 will finish it on the Owner's own dev machine, probably by accident, probably in October.
- **Not claimed:** that this ending sells the game, that anyone will play twice for it, or that it fixes the fun deficit. It answers one question — what the win feels like — and the answer is: quiet, exact, and replayable. INFERRED throughout; no receipts exist because nobody has built it.
