## Bug 1 — Draft priority/WINS numbers missing; CPU doesn't draft until user picks; picks not added to depth chart
Symptoms (user, 26 Oct):
- Priority and WINS numbers disappeared from the draft board.
- Computer doesn't start drafting until user's first selection (even at pick 1.32).
- After selecting players, they are not added to the depth chart; CPU still doesn't draft.

Likely causes to investigate (Beam static analysis):
- `simRecs()` may return null or `sim.later` all zero → priority shows "—". Check `boardEntries()` → `mkEntry()` where `pri = e.v - later`. If `later` is null/0, pri still computes but may be 0.
- `processUntilUserTurn()` loop: verify `draftSim.pos` increments. Check `cpuPick()` returns a valid pick with slot; if it returns null, pos++ runs. But if `cpuPick` throws, the catch in stepSlow increments pos. In fast mode (default), an exception in processUntilUserTurn propagates up to renderDraftLive's try/catch → fallback board. Check console.
- `executePick` sets `roster.slots[slot] = player`; `renderDraftRoster2` reads `roster.slots[sl]`. If roster reference is stale (e.g., a new roster object), depth chart won't update. Check `draftSim.rosters` mutation.
- `draftSim.awaitingUser` flag: if it stays true after a pick, the loop won't continue. `makeUserPick2` sets it via `processUntilUserTurn`.

## Bug 2 — Madden Rankings, Position Rankings, and Guide not appearing at all
Symptoms: those three tabs render nothing.

Likely causes:
- `SUPP_TITLES[btnId]` may be undefined for those tabs → `suppHead` stays hidden but the view div should still render. Check `setActiveTab` (l.832): it toggles `.active` on view divs. If the view divs have no `.active` class initially or the CSS hides them, they won't show.
- Check if `renderRankings`/`renderPositionRankings`/`guideHTMLCached` are called. In setActiveTab: `if(btnId==='tabGuideBtn') document.getElementById('guideBody').innerHTML = guideHTMLCached();`. If guideBody is null, throws.
- Check for a JS error earlier in the script that prevents those functions from being defined (e.g., a syntax error in a feature flag). `node --check` passed, but runtime errors could stop execution.
