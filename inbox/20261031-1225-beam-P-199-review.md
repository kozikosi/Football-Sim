The spec says "25% each, INFERRED". This is a simplifying assumption. In reality:

- The uniform 25% assumption smooths over real rotation patterns.
- The SPEC itself acknowledges this: "Rotation split: INFERRED. Uniform over 4 starters; reality: lowest-snap starters give up more."
This should be flagged as a known limitation, not a verified fact.

### 6. The 3-4 base mapping for DL5 is unresolved
The Owner's 29 Oct notes say: "In 3-4, OLB2 (SAM spot) rated as DT2 (300)". But the DL5 spec says "3-4 base mapping: OPEN". The SPEC doesn't explain how DL5 works in a 3-4 base where the defensive line is DE1, NT(=DT1), DE2 (only 3 linemen, not 4). In a 3-4, the "4 starters" (DE1, DE2, DT1, DT2) don't all exist — there's NT instead of DT2. The uniform 25% replacement assumption breaks down in 3-4. This is a real gap.

### 7. The "rotation AND heavy sets" note changes the model
The Owner's 29 Oct notes say: "DL5 = rotation AND heavy sets (x & short, goal line; more on aggressive defence)". This means DL5 isn't just a rotational player (33% of snaps) — it's also on the field in heavy sets (goal line, short yardage). This would increase DL5's snap share beyond 33% in certain situations. The spec's 33% average might undercount DL5's actual impact. The model should account for heavy-set snaps separately.

### 8. The snap count caveat (edge rushers labeled LB) affects the 33%
The script explicitly excludes players labeled as LB (3-4 edge rushers). This means the 33% is a LOWER BOUND — actual DL5 share could be higher if 3-4 edge rushers are counted as linemen. The spec acknowledges this ("DOCUMENTED") but doesn't adjust the number. The true DL5 share might be 35-40% when 3-4 edge rushers are included.

### 9. "Try to break E3d/E10 with a defect" — E3d is robust, E10 is fragile
- **E3d (FLEXDL5)**: The test checks that flex-dl5.json matches flex.json. If I change a penalty in flex-dl5.json, the test should fail. This is a good test — it catches drift.
- **E10 (pasted literals)**: The test checks that the pasted engine code reproduces the fit. If I change a weight literal (e.g., DL5 from 140 to 137), the test should fail. But the test might not catch subtle changes (e.g., changing DL5_SHARE from 0.33 to 0.34) if the derived weight still rounds to 140.
- **Potential break**: Change `DL5_SHARE` from 0.33 to 0.34. Derived weight = 0.34 × mean(DE1,DE2,DT1,DT2). If mean is ~424 (140/0.33), then 0.34 × 424 = 144.1 → rounds to 144, not 140. So the test would catch this. But if the change is small (0.33→0.331), the derived weight might still round to 140. So E10 has a tolerance of ~0.002 in DL5_SHARE.
