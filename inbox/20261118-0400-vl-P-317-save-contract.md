## S3/S4 (save contract) — three defects settled
**S3-1 cites `canonicalHash`, which exists nowhere except a comment (envelope.ts:19: "canonical SHA-256 of the player dataset...").** Strike it OR name the real primitive. **Recommendation: name SHA-256.** The comment itself defines it as "canonical SHA-256 of the player dataset" pointing at `core/hash.ts canonicalHash`; SHA-256 is the primitive, SHA-512/hash53 are not present anywhere. Strike "canonicalHash" as an identifier; replace with `dataVersion: string = sha256(dataset)`. Reason: the comment is the only source, and it says SHA-256. This is the Architect's call but SHA-256 is the evidenced choice.

**S4 framing out of date (async `StorageModule`/`createSaver` already exist).** Rewrite the framing against what exists: `core/storage-local.ts` is the async storage module; `serializeEnvelope`/`assertSlotMatchesKey` (F8) are the primitives; saves are enveloped per-slot keys (`sim:nfl:slot:A` etc.). The failure-modes section (F8 slot-miswrite assertion) is the best part — keep it.

**S4-2 pin one error channel.** Draft #2 recommends `Result`/`ParseResult` values, not rejection. **Agree.** Reason: the saves layer already returns `'draft: bad picks'`-style result strings (store.ts:79) and `serialize` returns a string — an explicit Result/ParseResult channel is consistent with the existing error style; silent rejection would drop slot-miswrite and corruption signals. Pin `Result<Ok, Err>` / `ParseResult` as the single error channel.
