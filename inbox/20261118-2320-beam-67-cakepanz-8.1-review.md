## Findings

1. defect (minor, doc): README-DELIVERY says "the cakepanz-8 review is CLOSED" but the package still carries the round's ONE open item (L10 / acceptance-run.sh). The doc is internally consistent (it flags L10) but the headline "CLOSED" overstates. Suggest: headline "CLOSED except L10".
2. risk: `loadDraft` does NOT clear `fullBoard` (hy4 nuance). A user who took FULL BOARD, saves, reloads, then loads a DIFFERENT saved draft inherits the full-board mode for that draft. The 8.1 law L9 tests reload-keeps-it and new-draft-resets-it, but not cross-draft load. Worth a follow-up law (L10 candidate: "loadDraft does not inherit another draft's fullBoard").
3. risk: `myPicks = record.picks.filter(p => p.team === userTeam).length; lateMode = myPicks >= 10`. The filter counts picks by team, not by the user's own selections across all slots — fine as written, but a trade/keeper scenario where the user's team id changes mid-draft is not covered. Not a bug today; flag for the keeper-mode work.
4. calibration question: the simple row's REC number is the active sort (WINS/PRIO/OVR). The gone% stays on every row regardless of sort. Good. But the caption is visually hidden (title+aria-label) — sighted users on a priority-sorted board see a bare number with no visible caption. The "honest switch line" claims every number is one click away; consider a visible tiny caption (2-3 chars) so the number can never be misread by a sighted user. Low cost, high clarity.
5. intentional simplification: the FULL BOARD door is one-way in the UI (`setFullBoard(true)` only); the only way back to simple is a new draft. Acceptable per the laws, but a "back to simple" toggle would let a user who clicked FULL BOARD by accident recover without restarting. Consider a reversible door with a confirm.
6. defect (doc hygiene): `WHAT-CHANGED.md` header still says "cakepanz-8 (2026-11-18)" while the body is the 8.1 round. Cosmetic but confusing for a reader landing on the file. Rename or retitle to "cakepanz-8 + 8.1".

## Innovation / brainstorm for the shell (UI/UX on Claude's engine)

- The simple/complex split is the right idea and should become the shell's default posture, not a late-draft-only mode: a "glance mode" toggle at the top of every data-heavy screen (Standings, Stats, Awards) that collapses to one recommendation number per row, mirroring the draft board. The engine's VMs already carry the ranking; the render layer just chooses density.
- The `REC` caption pattern (visually-hidden label that names the number) should be promoted to a shared component so every numeric cell in the shell is self-describing. This directly serves the Owner's "plain informative language" rule and the accessibility bar.
- The flex chips are "one click away" in the simple row detail. Make that one click a hover/focus tooltip on desktop so the chip never needs an expand, while keeping the expand for touch. Progressive disclosure by input modality.
- The `fullBoard` choice surviving a reload is good; consider also persisting the active sort and the expanded-row set per draft, so a reload lands on the exact board the user left.
- The mode switch (valuation mode) is locked mid-draft. Consider a "preview other mode" read-only overlay that shows the board re-ranked under another mode without changing the live ranking — useful for the Owner's model-first exploration without committing.
- The "Best available" collapse in simple mode should probably be the default view with the full list behind a "show all" door, not the other way around; the cognitive load lands in rounds 1-3, not 10+.

## Weakest point of the work

The cross-draft inheritance of `fullBoard` (finding 2) and the sighted-user caption gap (finding 4) are the two places a user could be surprised. Neither breaks a law; both are ergonomics.
