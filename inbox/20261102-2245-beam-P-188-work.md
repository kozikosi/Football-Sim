## 4. Proposed intake gate process (for the Architect)

Step 1: Owner sends a message (chat, note, or file).
Step 2: Architect saves verbatim to _agents/owner-notes/<date>-<slug>.txt (byte-for-byte, never edited).
Step 3: Architect reads the message and extracts every actionable item.
Step 4: Each item is either:
  (a) Added as a new PRIORITIES row (with source citation), OR
  (b) Added to an existing row as a sub-item, OR
  (c) Recorded in the intake ledger as "not actionable" (with reason), OR
  (d) Recorded in the intake ledger as "duplicate" (with pointer to existing row).
Step 5: Architect writes a ledger entry: _agents/V23-OWNER-NOTES-INTAKE-LEDGER.md gets a new section for that date, listing every cluster and its row(s).
Step 6: Any seat can verify by: (a) reading the verbatim note, (b) checking the ledger, (c) confirming the row exists in PRIORITIES.md.

## 5. Verification checklist for seats

1. Read the verbatim note: _agents/owner-notes/<date>-*.txt
