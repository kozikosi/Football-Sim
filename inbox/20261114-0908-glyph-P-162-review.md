## FINDINGS

1. **Anchor drift (defect in spec, previously noted):** Beam states `userStatsInner, line 3642`; actual in cited PreColors ref is **3651**. UK/VL already flagged this; Beam's work file remains uncorrected. Any implementation patch anchored to 3642 will fail loudly or target wrong context — spec must use function-name anchors (preferred) or corrected lines.
2. **Draft-board "bubbles" site underspecified (risk/calibration):** Beam lists "draft board bubbles" and `renderDraftBoard2`/`boardEntries` as targets, but `renderDraftBoard2` (1667+) builds table/cards views with sorting, slot pickers, sim metrics, gone/priority columns, and distinct entry rendering (`mkEntry`/`retarget`). "Align to card component" is not an exact WHERE/old→new for this surface. Spec needs concrete anchors for which draft-board elements become the shared card (player cell in table? card view tile?) and how board-only data (priority/gone/slot-fit/war) coexists with the required card fields.
3. **Field mapping ambiguity (calibration question):** Brief requires "#x Position" only (no "at", GP or dot). Beam proposes field 2 "Position + OVR (e.g. \"WR 87\")" and keeps rank in field 3 ("72.4 · #3"). Current ref shows Pos and OVR as separate columns and rank in Rating column — fine to restructure, but "#x Position" in Owner wording can read as rank-at-position label (e.g. "#3 WR"); spec should quote the exact intended display order/format to avoid wrong interpretation.
4. **90+ shimmer colour rule incomplete (risk):** Beam states "foil shimmer on OVR number (team colour)" and "palette colours (team primary) not white/neutral for the name and OVR" but also "user's player: border var(--accent), subtle accent bg". For non-user players shown in league leaders/awards, "team colour" requires a per-player/team palette source; ref has no obvious generic team-colour helper in these renderers (`honorLineHTML` uses accent only for user). Spec must define colour source for every surface (user team, other teams, draft pool) or it will be implemented inconsistently.
5. **Awards unification underspecified (defect/risk):** Regular awards carry `${a.why}` explanation rows/blocks and coach/team award variants; playoff awards (`P.sbMvp`, `P.mvp`, `P.rounds`, leaders, team) have different data shapes and currently no `a.why` blocks in the same form. "Same card component" and "award explanation text removed" need per-variant old→new: which award entities remain (title/badge), where stat line comes from for SB MVP/Postseason MVP/game-ball items, and how Coach of the Year/team awards render as "player card" when recipient is not a player row.
