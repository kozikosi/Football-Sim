## Findings

1. **Hard dependencies not landed (confirmed absent):** Cinzel Decorative, `textShimmer`, `foil-shimmer`/`foilShimmer`. The proposal's CSS/JS use all of them. Ship with fallbacks (system serif, plain opacity fade) or land P-111/P-183/P-117 first.

2. **"type"/"CPU draft" column removal is mis-targeted.** The proposal applies the change in `renderCompare()`, but renderCompare has no type/CPU-draft column (it's a starter-by-starter lineup table + unit comparison). The actual location is `entryRowsHTML()` (l.6196), which has `<td class="narr">${e.type}</td>` (3rd column, "You"/"CPU draft"). Remove that `<td>` and drop colspan 4→3 in the detail row. Also update the season-view "How your draft ranks" table (same entryRowsHTML call) — it will lose the type column too; acceptable. The "You" indicator should remain as a shimmering badge on the user's team cell (not a separate column).

3. **`metrics` must NOT be removed (proposal bug).** `generateDraftRecap(entry, metrics, log)` (l.1843) filters metrics for strengths/weaknesses. Removing `const metrics = computeDetailMetrics(myEntry.pool);` leaves metrics undefined → crash at render time. Keep metrics for generateDraftRecap; only remove the catRows table render (Unit Rankings section) and the metrics-based "Every Starter, Graded vs. the League" table if the Owner wants it gone. The proposal's "Overall Grade" line should keep the score/rank OR move it to the fade-in (finding 5) — not both removed silently.

4. **"How your draft ranks" placement mismatch.** The proposal puts the fade-in rank display inside `renderYourRosterTab()`, but the actual "How your draft ranks" (h3 + 32-team table) lives in the **season view** (l.6269-6274), under the Start Season button. The Owner says "fades in under button and shimmers, one decimal allowed" — that matches the season view (under the Season button), not Your Roster. Move the fade-in to the season view, after the Start Season button (P-155's cinematic action panel). Apply `toFixed(1)` there. Coordinate with P-155.

5. **Strengths/weaknesses graphic needs season data.** `renderStrengthsWeaknessesGraphic(user, S)` uses `S.unitRatings`/`S.unitRanks`/`S.league`, but at draft-results time `seasonState` is null (season not started until the user clicks Start Season). Either (a) compute unit ratings from `myEntry.slotmap` via `teamRatings()` at draft time (feasible, no season needed), or (b) move the graphic to the season review (post-season). The Owner's "Your Roster tab" wording favours (a). The proposal doesn't address this; flag. Also `UNIT_INFO` exists (l.1949) — OK.

6. **NFL user-team highlight: team-colour part needs getTeamColor (absent).** Highlighting by `isUser` already works (the user's row is the only isUser entry). The team-colour border/text needs P-004's `getTeamColor`. The "real team of the same name is neutral" is already satisfied because the real entry has isUser=false. But if the user's team name collides with a real team name, both rows render; only isUser is coloured. Good — no code change needed for the neutrality rule; only the colour value is missing.

7. **"Overall Grade" without colon + score removal.** Proposal changes `Overall Grade:` → `Overall Grade` and drops the `(${score}, #rank of 32 ...)` parenthetical (moved to fade-in). If the fade-in is in the season view (finding 4), the Your Roster tab loses the score entirely. Recommend keeping a compact score on the Your Roster tab too (e.g., "Overall Grade X (score, #rank)") to avoid an empty header. Architect decides.

8. **90+ shimmer in slotRows.** The proposal wraps the name in `<span class="player-name ${nameClass}">`. Current code: `${e.name}` (no span). Add the span with `nameClass` (shimmer for ≥90, vibrant for ≥85). Note: `e = normalizeSlotEntry(p)` must have `.ovr`; verified (used for effOvr). OK. But `shimmer`/`vibrant` classes need P-111's CSS (absent) — fallback to a plain colour.

9. **Horizontal lines removal.** The proposal removes `<hr>` from panels. There are no explicit `<hr>` in renderYourRosterTab/renderCompare (grep found none in those functions). The "horizontal lines" are likely CSS borders on `.panel`/tables. Removing them may make sections blur. Recommend scoping the removal to specific separators (e.g., between the slot table and depth chart) rather than all panel borders. Flag.

10. **Tab list must match P-155.** P-156's tabs (NEW DRAFT, 100 SEASONS, SEASON, VS. ACTUAL NFL, YOUR ROSTER, COMPARISON) match P-155's. Good. "Vs. 11. **Dropdown suffix removal.** Current: og1 'Your Team (name)', og2 'name (sim)', og3 'name (actual)'. Proposal removes suffixes and renames optgroups. Fine, low risk. But note: with suffixes removed, two teams with the same name (user's team vs. a sim team with the same franchise name) become indistinguishable. The Owner's request is to remove suffixes, so honour it, but the comparison tab's team selector may become ambiguous. Flag.
