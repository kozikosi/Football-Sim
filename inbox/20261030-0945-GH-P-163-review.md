The vertical key-player layout is a useful direction. In addition to the already-posted review findings, the proposed CSS and palette wiring use tokens that do not exist in the pinned Pre-Colors build, so the intended card surfaces and colors would silently fail.

- **Defect (shown):** the card markup uses `var(--card)`, `var(--muted-foreground)`, and `var(--primary)`, but Pre-Colors defines `--panel`, `--panel2`, `--sub`, `--text`, `--accent`, and related tokens instead. Undefined custom properties make the affected background/color declarations invalid (the cards become transparent and user-name color is not set). Reuse actual tokens or provide documented fallbacks.
- **Color requirement incomplete:** `renderPreviewPanel()` colors the generated preview with one `var(--foreground)` value, not team palette tokens; the separate team/player headings use their own colors. This both references an undefined token and does not implement a team-aware palette for the whole preview. Apply semantic team text/accent tokens by team while maintaining readable contrast.
- **Motion requirement:** the CSS addition uses an infinite animation and the inline player-star style starts it directly. Include `prefers-reduced-motion` handling and avoid leaving the inline animation active when reduced motion is requested.
- **Scope note:** the earlier review already identifies the broad matchup-line filter, missing team-color source, missing Cinzel font, and incorrect `TEAM_DATA.primary` lookup. The proposal still needs those corrections; this review does not repeat their full evidence.
- **Evidence:** `rg` on `Football-Sim-PreColors.html` confirms the available root tokens at lines 15-16 and no definitions for `--card`, `--muted-foreground`, `--foreground`, or `--primary`. The proposed snippets use all four.
- **Not run:** a browser preview, contrast audit, or reduced-motion emulation; this is a source review.
- **Weakest point:** palette token names depend on the eventual Colors v1 theme contract; keep the proposal semantic and avoid binding it to undeclared token names.

**Colors v1 takeaway:** W38's team theme should expose stable semantic tokens (team accent, readable team text, subtle wash) rather than leaking framework-specific names such as `--primary`. Components can then inherit the selected team's colors safely, while an accessible fallback remains defined.
