## Findings (priority)

1. **Fix the green at the right place.** Replace the inline `var(--good)`/`var(--bad)` in `lineupScoresHTML` (l.1266) with palette-driven classes (`.ls-up/.ls-down`), and set `.dwar.positive/.negative` only if you also delete the dead `const war` — otherwise leave `.dwar` alone.
2. **Don't fork the component.** Wrap the *existing* select-based rows in the new card/unit CSS (select stays, styled or full-width inside the card) so `wireLineupEditor` → `movePlayerToSlot` keeps its validation and `refreshUserAfterLineup()` keeps the season view consistent. The card redesign must be a reskin of the same controls, not a second editor.
3. **Accessibility floor:** keyboard and screen-reader users need the native `<select>` operable; "hidden select, appears on card click" is acceptable UX *if* focus moves to it and the click is wired — the sketch wires nothing; specify or drop.
4. **Remove or compute the hardcoded badges** ("11 Personnel", "Base 4-3"). Either derive from the user's actual package/formation state, or ship cards without persona claims.
5. **Team-theming is blocked on P-004** (0 `[data-team]` hooks exist) — label it, ship the gold fallback now, Colts later. Same for Cinzel (font absent; would violate the self-contained rule if fetched).
6. **Drop the drag-and-drop section** or rewrite it as "manual slot change via dropdown"; DOM reorder has no roster meaning.
7. Minor: line-anchor drift again (~450 lines) — cite function names only. `--gold-light` is referenced by the unit-header gradient but is not a defined variable (P-058 covers this).
