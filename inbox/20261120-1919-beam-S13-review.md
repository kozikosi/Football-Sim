# 4. Brainstorm — improving cakepanz / the UI-UX shell for Claude's engine

The cutover (colors/) is the destination. The shell's job after the merge is to be the thin UI over the frozen engine. Ideas, ordered by leverage:

A. **Make the shareable link the primary artifact, not the seed.** Today the URL carries `?seed=b36:…`. Add a "Copy draft link" button next to the seed code in the board header (one click, `navigator.clipboard.writeText(location.href)`), with a fallback that selects a hidden input for `file://` contexts (the file:// law). The seed code is already self-describing; the link is the shareable handle. Cost: ~15 lines, one battery law (URL round-trips through copy+paste). Highest leverage for a draft-simulator product.

B. **Keyboard-first draft.** The board already has `focus-visible` rings. Add: `↑/↓` to move the staged row, `Enter` to confirm, `u` to undo, `1–9` to jump to the nth available row. The suggestion ring (top 3) is the natural default focus target. This is the "speedrun the suggestions" affordance the Owner's ruling (C′1) already implies; the UI just doesn't expose it. Battery: a new L-row asserting keyboard confirm lands exactly one pick (reuse L22's guard).

C. **A "compare two drafts" view.** The Saves panel already round-trips records. Add a diff screen: pick two saves, show the pick-by-pick divergence (which slot diverged first, which player each took) plus the final team ratings. This is the natural consumer of the seam golden (N34) — the VM→JSON map already serialises boardVM; a second serialisation at a different seed gives the diff for free. This is the feature that makes the shareable seed worth sharing.

D. **Empty/error states as first-class.** Today the feed and the board assume a live draft. Add: (i) a "no draft yet" empty state on the board tab that points at Team Select (not a blank screen); (ii) a "draft failed to load" state when `LOAD` rejects (dispatchAsync's `state.error` — the engine already surfaces it); (iii) a "stale save" warning when a save's engine pin differs from the current pin (the pin is in the record; compare on load). (iii) is the one that matters most for the cutover, because the pin will move.

E. **Theme tokens, not hex.** DraftBoard uses `#c9a24b`/`#b3766a`/`#2c1e0c` literals in `.cp-go`. The shell already has `--gold2`/`--gold` tokens (focus-visible uses `var(--gold2)`). Move the gradient to tokens so dark/light and the Owner's palette land in one place. This is the "one name for one thing" rule (X5) applied to CSS.

F. **The feed's OT block is the model; extend it, don't re-invent.** The engine's `feed.ts` already separates regulation (time LEFT) from OT (time INTO overtime) with an `ot` summary block. The shell renders the mapper's shape. Keep it that way — but add a "game ball" highlight row at the top of the OT block (the engine computes `computeRegularSeasonAwards`/game ball). One row, one source.

G. **Deterministic replay for the shareable link.** A `?seed=b36:…` link replays the draft only if the engine pin matches. Stamp the pin into the URL too (`?seed=b36:…&pin=408410477`) and on mismatch show "this draft was built on engine 408410477; current engine is X — results may differ" instead of silently re-running. This is the honest version of "shareable draft" and it costs almost nothing (the pin is already in the record).

H. **Battery hygiene: a `ringPresentGuard()` helper** (see note 1 above) — extract so the next law can't reintroduce the F20 crash class. Also: the visual battery's W12/W13 laws assert on URL strings; consider asserting on the `history.replaceState` call count too, to catch a future refactor that writes the URL twice.

I. **The cutover's real risk is the duplicate engine.** MERGE-MANIFEST's single-source plan deletes the duplicate engine in colors/. The golden (N34) must MATCH through the colors/ paths after the merge — that's the first gate. Suggest adding a CI step (even a shell script) that runs `golden-seam.mjs` against both trees and fails on mismatch, so the single-source invariant is enforced on every commit, not just at cutover.

J. **Offline-first is a hard requirement (§3).** The shell is already self-contained (no CDN, no build step for the user). Verify the merged colors/ build stays self-contained — no `import` of a remote module, no fetch to a CDN.
