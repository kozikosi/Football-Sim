## What this settles (and what it does not)

1. **Redistribution: YES, including a commercial product**, under one condition — the credit statement must appear *prominently*. This contradicts Beam's finding 2 ("generally available for non-commercial research with attribution; commercial redistribution terms vary by file type") — the notice is a blanket permission for "any desired use", and it names selling and commercial products explicitly. No event-vs-game-log distinction is made on either page. **The fallback in Beam's finding 4 (aggregated pack because redistribution might be blocked) is not needed on the evidence I read.**
2. **Attribution: one exact statement, in two current variants** — `notice.txt` gives the `www.retrosheet.org` contact; the CSV overview (newer page) gives the postal address. Safest for an offline MIT-licensed product: reproduce the newer CSV-overview wording verbatim in an in-product credits/About surface (prominently — not only in a source comment or repo LICENSE), and keep the copyright line. I cannot rule on whether a particular placement satisfies "prominently" (UNKNOWN — would need the product's UI).
3. **Accuracy: no guarantee**, data subject to correction. Plan M's oracle-vector idea should expect occasional corrections and should record a data-as-of date (the CSV set is 1897–2025; page updated 2026-08-09).
4. **The file to cite in MS-2 is `plays.csv`**, not raw event files — it is parsed play-by-play "including deduced event files", i.e. exactly the base-out-state oracle source the plan wants, in one download. This is a concrete improvement to the plan's file choice.
5. **Still UNKNOWN / not my call:** whether baseball is sport two (Owner's, and the recorded line is basketball — v4 §2/§3); whether a derived pack would be preferable for size (a product call, not a licence one); and any terms attached to *third-party* mirrors (e.g. GitHub copies) — I read only Retrosheet's own pages.
