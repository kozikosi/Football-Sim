## Findings

### 1. File size exceeds 10 KB guideline
The mock-up is 22.9 KB. AGENTS.md §5 says "Mock-ups are static HTML ≤10 KB in your lane". This is in uk's inbox, not my lane, but the guideline exists for a reason (mock-ups should be lightweight). Recommend: trim to ≤10 KB or split into a CSS-only file + minimal HTML.

### 2. Bubbles are small, not "large" per brief
The brief says "large bubbles". The mock-up uses `.bubble{padding:10px 18px;font-size:0.75rem;}` — these are small pills. Recommend: increase to `padding:14px 24px;font-size:0.85rem;` for "large" bubbles.

### 3. Bubbles are not at the page bottom
The brief says "on one horizontal line at the bottom". The `.bubbles-row` is inside the coaching-philosophy panel (Section 2), not at the page bottom. The page bottom has `.bottom-line` with the flex guide and group scores. Recommend: move `.bubbles-row` to after the `.bottom-line` div, or make it a page-level element below the panel.

### 4. `fadeOut` keyframe defined but never used
The brief says "fade-in and fade-out on explanatory text". The mock-up defines `@keyframes fadeOut` but no element uses it. Only `fadeInUp` is applied (via `.fade-in` and `.fade-in-delay-*` classes). Recommend: apply fade-out to collapsible term definitions when they close, or to the "Why this style" reason box when a different style is selected.

### 5. `prefers-reduced-motion` only covers fade-in classes
The reduced-motion rule (line ~110 in mock-up) covers `.fade-in, .fade-in-delay-1..7` but not `.setup-card:hover` transforms or `.bubble:hover` transforms. Recommend: add `transition: none` to interactive elements under reduced motion.

### 6. `.rank.1`, `.rank.2`, `.rank.3` — fragile CSS class names
These selectors use classes like `rank 1`, `rank 2`, `rank 3` (HTML class="rank 1"). CSS selectors `.rank.1` are valid but fragile (class names starting with digits need escaping in some contexts). Recommend: use `.rank-r1`, `.rank-r2`, `.rank-r3` or data attributes.

### 7. Gold `#d4af37` used in both light and dark modes
The mock-up uses `--accent: #d4af37` in both `:root` and `@media (prefers-color-scheme: dark)`. The Owner's theme says "light mode needs a deeper gold for small text" (contrast audit Q-V23-2). The mock-up doesn't address this. Recommend: use a darker gold (e.g., `#8a6d1b` or `#7a5c15`) for small text in light mode.

### 8. Collapsible term definitions are hidden and non-functional
The `#terms-*` divs are `display:none` and only toggle via the bubble script. But there's no visual affordance (no chevron, no "click to expand" text). The bubbles say "Personnel Packages" etc. but it's unclear they're interactive. Recommend: add `cursor:pointer` is already there, but add a visual indicator (e.g., a small arrow or "+" icon).

### 9. "Selected ..." line — good but could show more context
The `.selected-line` shows "Selected: West Coast (Short, rhythmic passing; protects the QB) · 4-3 Balanced (Sound gap control; lets the front four hunt)". This is clear. But the brief says "Selected ..." line — the mock-up matches. OK.

### 10. "Group scores" uses placeholder data
The `.bottom-line .right` shows "Group scores: Offense 78.4 · Defense 74.1 · Special Teams 62.3". These are hardcoded placeholder values. For the product, these would come from `teamRatings()`. Flag as needing dynamic data.

### 11. No `lang` attribute issues
The mock-up has `<html lang="en">` — correct.

### 12. Accessibility: bubbles have `aria-expanded` and `aria-controls`
Good. But the collapsible divs don't have `role="region"` or `aria-labelledby`. Minor.

### 13. The mock-up doesn't include "New to flexing? Read this first" as a collapsible
The brief says "'New to flexing? Read this first' and 'Group scores' on one line at the bottom". The mock-up has both on `.bottom-line` (the "New to flexing? Read this first" is a link, and "Group scores" is text). But the original product has "New to flexing? Read this first" as a `<details>` element in the lineup section. The mock-up moves it to the bottom, which matches the brief. OK.

### 14. Missing: "no white text" enforcement in dark mode
The mock-up uses `color: var(--text)` on most elements. But `--text` in dark mode is `#f5f0f0` (off-white). The Owner's rule says "White text for names and sentences" — so off-white text is fine. But `#fff` (pure white) is not used anywhere. Good.

### 15. `.setup-card:hover::before` uses opacity transition
The hover effect on setup cards adds a top border gradient. This is nice but should respect reduced motion. Already noted in finding #5.

## Verdict summary
The mock-up is well-structured and addresses most P-177 brief points. But:
- Bubbles are small and not at the page bottom (2 brief requirements partially unmet).
- `fadeOut` keyframe defined but unused.
- File size exceeds 10 KB guideline.
- Gold contrast in light mode not addressed.
- Collapsible affordance unclear.
- Reduced-motion coverage incomplete.

RECOMMEND: improved (address the 15 points above, especially #2, #3, #4, #7 before the Architect builds).
