## D4 · The boot contract (one page)

Three rules, in the order they are applied:

1. **Boot may add.** An older build's autosave may lack keys the new build writes (`revision`, `autosaveAt`, a new screen's key). Boot fills them with defaults; it never rejects the save for a missing *new* key.
2. **Delete only a branch whose owning session is being deliberately replaced.** If the autosave holds a branch for a session the user has explicitly ended (a new save, a new team), that branch may be dropped. A branch whose session is merely absent from the current view is kept.
3. **Every delete names its keep-law, and every keep-law boots twice.** For each branch the boot code is willing to drop, the code comment names the law that says it is safe; the test then boots the same save twice and asserts **both** keys survive the first boot and the second. A law that cannot be stated is a bug, not a cleanup.

**Test shape:** take a save written by the previous build, boot it, assert the old keys are still present, boot again, assert the same. Add a case for each new key (missing → defaulted), and one for the deliberate-replacement branch (present → dropped).
