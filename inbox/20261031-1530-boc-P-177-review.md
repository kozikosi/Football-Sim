## Findings

1. **Mockup exceeds the 15 KB limit (work's own constraint).** 22.4 KB. The mockup is comprehensive but over the stated budget. Recommend trimming: remove the inline dark-mode duplicate (use CSS variables already in product), collapse the term-definition placeholders, or split into two mockups (layout + components). Or raise the limit — but the Architect owns the constraint.

2. **Dark gold (#d4af37) instead of approved light gold (#ffc43c).** The Owner's ruling: "Light gold (#ffc43c) preferred over dark gold (#d4af37) unless too yellow." The mockup uses dark gold throughout (`--accent: #d4af37`). If the product uses light gold, the mockup's contrast ratios (e.g., dark text on gold buttons) may not hold. Recommend switching to `#ffc43c` and re-checking contrast, or documenting why dark gold is used.

3. **"What do these terms mean" bubbles are in the middle, not at the bottom.** The brief says "large bubbles on one horizontal line at the bottom". The mockup places the bubbles-row after the setups grid and before the aggressiveness section — mid-page. The "bottom" should be after all content (after aggressiveness, before the bottom-line). Move the bubbles-row to the very bottom (after the bottom-line or as the last element before it).

4. **Fade-out animation is defined but never applied.** `@keyframes fadeOut` exists but no element uses it. The brief says "fade-in and fade-out on explanatory text". The mockup only has fade-in (fadeInUp). Recommend adding fade-out to the term-definition panels (when collapsed) and the "Why this style" reason (on dismiss). Or remove the unused keyframe.

5. **"New to flexing? Read this first" appears twice.** Once as a `<details>` at the top (line ~140) and once as a link in the bottom-line (line ~345). The brief says it should be on one line at the bottom. Recommend removing the top `<details>` and keeping only the bottom link (which opens the same content). Or vice versa. Currently redundant.

6. **Bubbles are small (0.75rem), not "large".** The brief says "large bubbles". The mockup's `.bubble` uses `font-size: 0.75rem` and `padding: 10px 18px`. Recommend increasing to at least 0.875rem with larger padding, or `font-size: 1rem`.

7. **"Group scores" placement.** The brief says "'New to flexing? Read this first' and 'Group scores' on one line at the bottom". The mockup's bottom-line has both on one line. Good. But "Group scores" is right-aligned (`margin-left:auto` via flex justify-between). At 390px, it may wrap below. The mockup uses `flex-wrap: wrap` so it stacks. Acceptable. But the mockup doesn't show a mobile-specific layout. Note.

8. **Units-compare (strongest/weakest) uses `1fr 1fr` grid without mobile override.** At 390px, two columns of unit lists side by side is cramped. Recommend adding `@media (max-width: 760px) { .units-compare { grid-template-columns: 1fr; } }`.

9. **The mockup's "Selected ..." line is hardcoded to Chiefs.** The mockup is a static example, so this is expected. But the CSS should support dynamic team names. The mockup uses `--rose` and `--rose-weak` for the selected-line background, which is team-agnostic (rose). Good — but the brief says team colours transform the app. The selected line uses rose, not team colour. Flag: should the selected line use the team's colour instead of rose? The Owner said "once a team is chosen every accent uses that team's three hexes". The selected line is an accent. Recommend using team colour (with rose as pre-selection default).

10. **The mockup's bubbles are `<button>` with `aria-expanded`/`aria-controls` — good accessibility.** And the JS toggles display. Good. But the collapsible term definitions are `display:none` divs, not animated. The brief says "fade-in and fade-out on explanatory text". The mockup only has fade-in on the main sections. The term definitions appear instantly (display:block). Recommend adding fade-in to the term definitions when opened.

11. **The mockup's setups-grid uses `repeat(auto-fit, minmax(260px, 1fr))`.** At 390px, 1 column. Good. But the cards have `::before` gradient on hover only (opacity 0→1). The recommended card has a persistent gradient. Good.

12. **The mockup's `.rank.1/.rank.2/.rank.3` CSS classes use numeric class names (`.rank.1`), which are valid but unusual.** In the product, the rank would be dynamic. The CSS should use attribute selectors or data attributes (`[data-rank="1"]`). Minor.

13. **The mockup uses `system-ui` font, not Cinzel.** The product uses Cinzel Decorative for display type (P-183). The mockup is a visual reference, so system-ui is acceptable for the mockup itself. But the CSS should note which elements would use Cinzel in the product. The mockup's `.setup-name`, `.unit-name`, etc. would use Cinzel. Recommend adding a comment or using a `--display-font` variable.

14. **No white text — verified.** All text uses `--text` (dark in light mode, warm white `#f5f0f0` in dark mode) or `#0d0a0e` on accent. No pure `#fff`. Good.

15. **The mockup's "Aggressiveness" section uses native `<select>` elements.** The product uses styled selects. The mockup's selects are unstyled (default browser). Note: in the product, these would be styled per the design system. Minor.
