## Innovation notes: the cakepanz UI/UX shell for Claude's engine

### What cakepanz has proven
The cakepanz pattern works: a Svelte 5 + Vite shell that consumes Claude's engine as a frozen snapshot, with a five-path re-pin protocol, a thin seam (M5: 68 import lines, 38 engine modules), and a law-and-falsifier discipline. The uniform-board round (cakepanz-9) proves the shell can absorb a major UX ruling (the Owner's "one board for all picks") without touching the engine.

### What the engine already computes but the shell doesn't surface

**1. The draft decision cost (pick value vs. next-best alternative).**
The engine's `goneOdds` already computes the probability each available player is gone by the next pick. The shell shows this as a tooltip. But the **decision cost** — the difference in wins/priority between the picked player and the next-best available — is computable from the board VM and would make every pick feel consequential. A subtle "value gained" or "value left" indicator (not a number, a gold/neutral visual) would close the loop the C'1 suggestion ring opens.

**2. The draft grade trajectory.**
The engine's `draftRecord` has every pick with its `wins` value. A post-draft "grade trajectory" — how the draft's cumulative value compares to the optimal available at each slot — is computable from the record. This is the "How your draft ranks" line (P-156), but as a visual arc rather than a single number. The Complete screen's wall-slip cascade is the perfect place for it: the roster print lands, then the trajectory draws.

**3. The season's "what if" — the counterfactual.**
The engine can simulate a season. The shell shows the result. But the Owner's "Can you go 20-0?" challenge is fundamentally a counterfactual: what if you had picked differently? The engine already has the data to re-simulate with a different draft record (the `simulateGame` function takes a lineup, not a draft). A "what if you had picked [next-best] instead" comparison — one click from the Complete screen — would be the most engaging feature the shell could add. It uses only data that exists.

### Shell improvements that don't need new engine data

**4. The draft board's "speedrun" path.**
C'1 (top-three suggestion ring) is the mouse path. The Owner's own speedrun instinct (from the chat logs) suggests a keyboard path: arrow keys to navigate the top-three, Enter to pick, D to open the detail. This is ~80 lines of Svelte, zero engine changes, and makes the board feel like a game rather than a form.

**5. The pick-complete pulse.**
C'3 (wall-slip cascade) is the Complete screen's entrance. The draft board itself has no feedback moment between picks. A 12ms `navigator.vibrate` (where available) + a brief gold pulse on the picked row would close the sensory loop. Zero dependencies, ~30 lines.

**6. The draft replay at Complete.**
The `draftRecord` has every pick in order. A "replay" — stepping through the draft pick-by-pick with the board state at each moment — is computable from the record. The Owner wants "all for cinematics." A replay card at Complete (pick 1 → pick 32, each with the picked player and the next-best alternative) would be the ceremony the draft deserves.

**7. The team-color contrast guardrail.**
SHELL-STATUS lists two open contrast failures (light gold2 1.51:1, dark text 3.17:1). These are Owner decisions. But a **test** that measures all 32 team palettes × two modes and fails the battery if any combination drops below 4.5:1 would be the cheapest insurance against future token/palette passes shipping unreadable screens. ~100 test lines, zero dependencies.

### What NOT to build

- **No drag-and-drop on the board** — the Owner ruled the DRAFT button is the efficient interaction.
- **No state library** — a snapshot engine needs a snapshot.
- **No UI kit** — they fight the w89 identity.
- **No virtual scroll** — 1.7k tiny rows render fine.
- **No analytics/telemetry** — ever.
- **No chart library until the Architect names the data seam** — a per-week win-probability series does NOT exist in the engine yet. A chart on non-existent data is empty axes.

### The framework tie-in

If the R-13 bench expands, it should measure a heavy-table + dashboard surface (Awards, Season, All-Teams, Playoffs), not the Draft Board — where the frameworks tie. The Draft Board is a list + DRAFT button; the dashboard is where Svelte vs Vue would actually differ.
