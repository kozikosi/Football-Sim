F2 — Validation levels not bound to phases. ACCEPTED.
  What: §8 lists micro/meso/macro with no phase binding. At Phase 1 (all λ=0) every team produces the same distribution, so the macro level (roster-quality-to-win slope ≡ 0) is degenerate by construction.
  Change: Bind micro/meso/macro to phases in §8; at Phase 1, gate only micro (team-total means) and scoring grammar (tie rate, exact-3, exact-7 spikes); macro (margin pmf GoF) moves to Phase 2.
  Where: design doc §8 at a0ddc584.
  Gates Phase 1: yes — same class as DS D2 (below), most operationally important.

F3 — softCap claim stated backwards. ACCEPTED.
  What: matchup.ts:87–91 softCap squashes log-rates into tight bands. Comment at line 84 says it bounds realism. But softmax saturation gives P∈[0,1] (already true of log-linear) and saturation limit is P→0/1 — unbounded log-odds response, the opposite of a realism bound.
  Change: Replace the realism-bound claim with a Phase-2 saturation-audit property gate + pre-agreed fitted-squash fallback.
  Where: colors/src/engine/matchup.ts:84–91 at a0ddc584; design doc §? at a0ddc584.
  Gates Phase 1: no (Phase-2 gate).

F4 — Derivative is noise-free, not exact. ACCEPTED.
  What: Toy computes derivative as warm-started central finite difference (±2 gap units, lines 138–142). Noise-free (solver tolerance 1e-9) but not mathematically exact — truncation error O(EPS²).
  Change: Reserve "exact" for the solver's noise-free property; state the ~10⁴-state scope and the h policy.
  Where: design doc §? (derivative section) at a0ddc584.
  Gates Phase 1: no (clarification only).

F5 — Identification-input consistency (gap distribution from stale flex snapshot). ACCEPTED.
  What: Gap distribution for dispersion matching comes from the lineup pipeline (Hungarian + flex table + rotation shares). Flex table changed twice this week, so λ matched against a stale gap snapshot is fitted to a spread the engine no longer produces.
  Change: Gap distribution generated by the same lineup code the simulator runs; re-derived whenever the flex table changes (design requirement 3: "Every constant has a named source").
  Where: design doc λ-fitting section at a0ddc584; Phase 0 kernel lineage.
  Gates Phase 1: yes — λ fitting depends on it.

F6 — Dual computation of snap counts forbidden. ACCEPTED.
  What: §5's "Snap counts are the sum of package probabilities times rotation shares" and the participation ledger are two computations of the same quantity, which requirement 2 forbids.
  Change: The participation log is the source; the analytic sum is the audit (one computes, the other checks).
  Where: design doc §5 at a0ddc584.
  Gates Phase 1: no (audit design).

D1 — Solver prices expected points; flex table is in wins. ACCEPTED.
  What: Toy state is (down, distance, yard line) with no score and no clock; value is net points to next score. Every flex-table number is in wins (slotWins20, 2/6/12 tiers). EP→win-probability conversion (needs score/clock or margin model) and per-game→per-season conversion are missing and unstated.
  Change: Price flex as a finite difference — two solves on the two lineups — in wins. Keep the derivative only as a linearisation check.
  Where: design doc flex-pricing section at a0ddc584.
  Gates Phase 1: yes — flex pricing is part of the engine design.

D2 — Phase 1 margin-pmf GoF gate cannot pass at λ=0. ACCEPTED.
  What: §8's totals bar includes "margin pmf passes a goodness-of-fit test on held-out seasons." Phase 1 is all λ=0 (neutral rosters → every team identical → simulated margin pmf contains only within-game variance; real pmf also has between-team quality component). A GoF test at 272 games × seasons rejects by construction.
  Change: Phase 1 gates mean-level totals + scoring grammar (tie rate, exact-3 and exact-7 margin spikes). Unconditional margin pmf GoF moves to Phase 2 (on the equal-team conditional).
  Where: design doc §8 gate table at a0ddc584.
  Gates Phase 1: yes — as written, the Phase 1 gate fails on a true baseline and would be read as "the engine does not work."

D3 — λ and θ not separately identified — freeze θ. ACCEPTED (see protocol note).
  What: Nothing in outcome data splits β = λ·θ; double θ and halve λ gives identical model.
  Change: Record frozen θ values in pack provenance next to fitted λ. Phase 1 protocol uses two-gap fit on β, not dispersion matching.
  Where: design doc λ-fitting section at a0ddc584; Phase 0 kernel pack provenance.
  Gates Phase 1: yes — λ estimation depends on it.

D4 — Dispersion matching biased upward. ACCEPTED (REPORTED, confirmed by second seat).
  What: sqrt(Var(y)/Var(g)) reads sqrt(λ² + Var(e)/Var(g)); bias +0.232/+0.427/+0.751 at noise ratios 0.5/1/2. Regression Cov/Var unbiased (+0.002/+0.002/+0.003).
  Change: Replace analytic dispersion matching with regression-based fit (two-gap sigmoid fit per protocol note). D4 needs one more re-run to confirm the 23–75% numbers.
  Where: design doc λ-fitting section at a0ddc584.
  Gates Phase 1: yes.

D5 — No macro/season calibration gate before cutover. ACCEPTED.
  What: §9's phases gate none of the §8 macro items; Lab anchors appear in no gate.
  Change: Add macro/season calibration gate before cutover.
  Where: design doc §9 at a0ddc584.
  Gates Phase 1: no (pre-cutover).

  Change: Phase 0 adapter re-implements the allocator via drive-granularity legacy events.
