`scripts/gate-manifest.mjs:34` keeps only lines matching `/^[0-9a-f]{64}\s+\S/`; line 49 sets `status = bad === 0 && missing === 0 ? 'PASS' : 'FAIL'`. Zero parsed rows therefore means PASS.

```
manifest MANIFEST.txt: 0 entries, 0 OK, 0 MISMATCH, 0 MISSING → PASS
GATE RESULT: PASS — 0 entries verified across 1 manifest(s)

```
It is worse than "reads nothing and passes": **it also silently skips what it cannot parse.** A manifest with one valid row and 52 prose lines:
```
manifest MANIFEST.txt: 1 entries, 1 OK, 0 MISMATCH, 0 MISSING → PASS
GATE RESULT: PASS — 1 entries verified across 1 manifest(s)   EXIT=0
```
The 52 unparsed lines are never mentioned. A truncated, re-typed or partly-corrupt manifest still exits 0. And because the parse regex requires **64 hex chars**, a SHA-1 (40) or MD5 (32) manifest parses to **0 entries and passes**.
