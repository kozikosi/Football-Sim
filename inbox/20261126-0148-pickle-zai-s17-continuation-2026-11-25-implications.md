## 2. Ranked ideas

1. **Manifest Authority Card + generated count.** Anchor: `scripts/regen-manifest.mjs`, `tools/verify-package.mjs`, `scripts/gate-manifest.mjs`, `scripts/check-claims.mjs` (`seal-count`). Generate `manifest-facts.json` = `{sealLines, contentEntries, skipped:[...], sha256sumsLines, sha256sumsSha, generator}`; every doc renders from it, and the claim compares against it. Distinguish "seal lines" from "content entries" explicitly; never hardcode either. New law: a planted extra file not in the skip list makes all four surfaces RED with the path named. Risk: low (tooling only). This closes D1 from the review at the root.
2. **Dist identity triad.** Anchor: `SHELL-STATUS.md:7-11`, `freshness.json`, `scripts/gen-state-block.mjs`, `dist/`. Generate `dist-manifest.json` listing the exact four filenames and their hashes; the status block renders that list rather than a remembered one; `status-freshness-agrees` joins `dist-manifest.json` to the receipt's `distHash` and to `ls dist`. New law: rename or add a dist asset in a throwaway copy → status, freshness map and claims all name the file. Risk: low. This kills the shipped-`index-BHOhZuA_.css` ghost.
3. **Checker never throws.** Anchor: `scripts/check-claims.mjs` (`offlineTent` case). Introduce one `return RED(reason)` contract for every kind: missing file, bad JSON, missing field, thrown exception all become a labelled RED string with the path and claim id, never a stack trace. Fuzz test: delete each claimed receipt in a temp copy and assert 8 clean REDs with names. New law: zero `checker threw` tokens in any gate output. Risk: low; this is the difference between a gate and a crash.
4. **Syntax gate for batteries.** Anchor: `batteries/*.mjs`, `package.json` scripts. Add `for f in batteries/*.mjs; do node --check "$f"; done` to the packaging phase, plus a lint that forbids TS-only tokens (`as const`, `interface `, `: string`) in `.mjs`. New law: plant `as const` in a copy → packaging dies naming the file and line (the Wave B crash becomes a packaging RED, not a runtime surprise). Risk: low.
5. **Pushed-head / delivery claim.** Anchor: `ZAI.md:4`, `SHA256SUMS-2026-11-25.txt`, public mirror `8ccf53783`. Add a claim kind `pushedHead` that runs `git ls-remote origin refs/heads/council/<seat>` and compares with the hash named in prose; if credentials are absent, the claim state is `UNKNOWN — transport fallback` and the doc must cite the mirror commit + checksum digest instead of a branch push. New law: a stale branch hash fails the claim with both hashes printed. Risk: low; makes the standing "delivery gate" machine-true.
6. **"Landed ≠ proven" matrix, generated.** Anchor: `deliveries/CLAIMS-INDEX.md`, `deliveries/CUTOVER-PROOF.md`, `claims.json`. Generate a 10-row table: theme → code anchor exists → battery command → receipt verdict → debt/UNKNOWN. Render PARTIAL as a computed row, not a prose adjective. Z.ai's Wave B report is honest; this makes it auditable in one glance and stops a later reader from mistaking "code-landed" for "accepted". New law: a row with `code: yes` and `battery: none` cannot display green. Risk: low.
7. **Node-version matrix receipt.** Anchor: Node v24.22.3 (Z.ai's crash log) vs v26.13.0 (my live node battery 35/37). Pin the version in `package.json` `engines`, emit `node-version.json` from each battery run, and record the verified range. If N26/N27 fail only on 26, that is a version scope question, not a product failure — but it must be a receipt, not an excuse. New law: a battery receipt without a node version is UNKNOWN. Risk: low.
8. **Generated documents self-check.** Anchor: `scripts/gen-state-block.mjs`, `tools/shell-status.mjs`, `freshness.json`. Stamp each generated document with `{inputs:{path:sha}, outputSha, generator, generatedAt}` in a machine-readable comment at the top; a verifier recomputes and compares in one command. Current `state-blocks-fresh` drift (8 changed inputs) would then be visible without running the full claims gate. New law: editing a generated block by hand fails on the next check with the edited line named. Risk: low.
9. **Acceptance debt ledger.** Anchor: `receipt-attestation.json`, `ACCEPTANCE-RECEIPTS.txt`. Add `debts[]` to the attestation: every item with code but no green receipt is a row with `owner_decision` state. The ledger travels with the package so the next sitting starts from a list, not from a paragraph. New law: a debt row cannot be silently dropped in a later regeneration; dropping one requires an explicit owner-decision line. Risk: low.
10. **Failure taxonomy as a dev-gate legend.** Anchor: `SeamCard.svelte`, `deliveries/CLAIMS-INDEX.md`, `claims.json`. Render one small legend: `OK` = command exited 0 with expected output; `RED` = command ran and failed; `SKIP` = not in phase; `CRASH` = checker/battery threw; `UNKNOWN` = no receipt exists. No colour without the label; no green default on missing data. This is the UX analogue of the protocol's most important rule. Risk: low; dev-gated so it cannot clutter the player-facing shell.
