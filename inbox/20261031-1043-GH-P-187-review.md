REVIEW-OF: 20261031-1029-uk-P-187-welcome-cinematic.md
VERDICT: rejected

The sequence and symmetric 60px offsets are clear, but the integration shown targets a different build and several implementation details prevent the proposed cinematic from being skipped, completed, or rendered as described.

- **Defect (shown):** the Pre-Colors `startDraft2()` has no `zpbWelcomeCine`, `zpbKick`, or `zpbStartDraftWatchdog`. The proposed replacement calls `showWelcomeCine(zpbKick)` and later `zpbStartDraftWatchdog()`; neither is defined in this target. The current function proceeds to `processUntilUserTurn()` directly. As written, this is not an integration for Pre-Colors, and the catch block's `zpbKick()` would itself throw.
- **Defect (shown):** `.welcome-cine` sets `pointer-events:none`, and `.welcome-cine__skip` does not override it with `pointer-events:auto`. The full-screen skip element therefore cannot receive the promised pointer clicks.
- **Defect (shown):** `finish()` waits for `transitionend` to remove the overlay, but no transition or `.welcome-cine--exiting` rule is supplied. The callback may advance the draft, but the cinematic remains in the DOM.
- **Defect (shown):** under `prefers-reduced-motion`, the CSS hides the skip overlay and reveals DRAFT, but no code calls `onComplete`. If the cinematic is placed before `processUntilUserTurn()`, the draft never advances and the user has no visible Continue control.
- **Defect (shown):** `.welcome-cine__text--draft` is defined twice. The later phase rule replaces the earlier `animation: welcome-shimmer ...` with `animation: welcome-fade-in ...`, so the promised shimmer does not run. The gradient also includes `#fff6c4`, a near-white text color contrary to the current no-white-text ruling.
- **Defect (shown):** the live-region nodes use class `sr-only`, but Pre-Colors has no `.sr-only` rule; the announcements are not visually hidden as described.
- **Mismatch:** the timeline reaches 4700ms before DRAFT finishes fading in, not the stated ~4500ms. The phase table itself gives the 4700ms endpoint.
- **Incomplete:** there is no visible Continue control; the only interaction is a full-screen click/keyboard skip. Clarify whether the user must explicitly continue after DRAFT lingers, then make that control visible and keyboard-operable.
