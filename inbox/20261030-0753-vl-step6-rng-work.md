## KEY FINDINGS FOR THE ARCHITECT

1. **poisson() (1922) is the linchpin.** It's a single function called ~10 times inside simulateGame. If rnd() wraps Math.random() globally, poisson becomes seeded automatically. If rnd() is opt-in per call site, poisson is the highest-value target.

2. **LAMBDA (2701) is deterministic given AG.fg/AG.td.** The FG/TD rates come from P-204/P-205 data (which I gathered). The randomness is only in the poisson draw around those rates — good news for seeded tests: same lambda, different seed → different but reproducible outcomes.

3. **Overtime (2321-2330) uses 3 Math.random() calls.** P-206 data (6.1% of games reach OT) sets the trigger probability; the OT winner/add/timing are random. Seeded OT needs all three.

4. **Draft sites (1015-1835) are separable.** They only run during draft simulation, not during season/game simulation. The Architect can seed them independently or leave them unseeded.

5. **UI/confetti (6456-6483) should NOT go through rnd().** Visual effects don't affect outcomes; seeding them adds complexity with no test value.

## PROPOSED rnd() SCOPE (recommendation, not a build decision)

Option A (simple, complete): wrap Math.random() globally → `function rnd(){ return Math.random(); }` with an optional seed override. Every site becomes seedable with one change. Downside: confetti also seeded (harmless).
