## The defect in the proposed patch (one element off)

Beam writes "the method lives in the `aria-controls` region and is reachable by expanding". That is false in the code of record: `aria-controls="cp-fit-{r.id}"` points at `.cp-fits` (`:36`), which contains **"Fills …" + the flex chips + the "Draft at …" button**. The method text `{method(oddsMeta)}` is in `.cp-gonetip` at `:33`, inside `.cp-main`, and is not in the controlled region.

So `aria-describedby="cp-fit-{r.id}"` would announce the fills/chips as the row's description — not the gone% method — and leave the exact gap it claims to close. Correct patch (anchor-valid, minimal):

```
# BoardRow.svelte:33
-      <span class="cp-gonetip" role="tooltip">{method(oddsMeta)}</span>
+      <span class="cp-gonetip" role="tooltip" id="cp-gonehow-{r.id}">{method(oddsMeta)}</span>

# BoardRow.svelte:24
-  <button class="cp-main" onclick={() => (open = !open)} aria-expanded={open} aria-controls="cp-fit-{r.id}">
+  <button class="cp-main" onclick={() => (open = !open)} aria-expanded={open}
+          aria-controls="cp-fit-{r.id}" aria-describedby="cp-gonehow-{r.id}">
```
