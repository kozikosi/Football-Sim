## Findings

1. **Hard dependencies not yet landed (confirmed absent):** `getTeamColor`, `getTeamLogo`, `--team-primary`, `--team-secondary`, `Cinzel Decorative`, `textShimmer`/`foil-shimmer`/`foilShimmer`. The proposal calls them without fallbacks. Must either (a) land P-004/P-040/P-110/P-111/P-183 first, or (b) ship with `var(--gold,#ffc43c)` fallbacks and a team-abbreviation placeholder for the logo. Recommend (b) so the card ships now and upgrades later — the Owner wants the beauty pass, not a dependency wait.

2. **"Three colour bubbles" ambiguity (unresolved since review #1).** The ASCII mockup shows three bubbles reading 98/95/92, but a single player has one OVR; the code renders one bubble. These cannot both be right. Decision needed: render **three team-colour swatches (primary/secondary/accent) under the OVR number, only when OVR ≥ 85**, keeping the single OVR value. The mockup should be redrawn to show swatches, not three OVRs. This is the only reading that satisfies "three colour bubbles only under OVR and only for 85+".

3. **"Bigger logos centred over their bubbles" is NOT implemented.** The proposed code puts the logo in a horizontal flex row beside the team name (l.99-103 of the proposal) with bubbles pushed right (l.92-95). Nothing is centred over anything. CSS confirms horizontal `flex`. Either reword the requirement or centre the logo over the bubble row; corrected CSS below does the latter.

4. **"No white text" vs shimmer gradient.** The proposal's `.pcard-name.shimmer` uses a gold→`#fff`→gold gradient (l.269). The midpoint is literally white, which requirement #8 forbids and which reads as white text on a dark panel. Use `var(--gold)` at all three stops (or `var(--accent)` gold). Same for `.pcard-ovr.shimmer`.

5. **Parentheses only removed in table view.** The card footer still renders `(${r.v.toFixed(2)})` (proposal l.128-133). The table view (l.442-444 of the proposal) removes them. Apply the no-parentheses rule to the card footer too: `${wavg(r.v)}` (no parens), consistent with the wins column.

6. **Missing helper signatures (or's point, still open).** The dependency list must state exact signatures so the Architect can implement without guessing:
   - `getTeamColor(teamName) → '#hex'` (primary; fallback `var(--gold,#ffc43c)`)
   - `getTeamLogo(teamName) → 'url or path'` (P-040; until landed, render the team abbreviation in a coloured chip)
   - `POS_DISPLAY[pos] → 'display string'` (exists, l.985)
   - `TEAM_ABBR[team] → 'abbr'` (exists, l.986)
   All four must be in the brief before the Architect builds.

7. **`topTag` green → gold (P-005, still unfixed).** `.toptag` CSS (l.196) uses `background:var(--good)` (green) + `color:#fff`. P-005: "TOP stays but dynamic gold, no green". Fix: `background:var(--gold,#ffc43c); color:#0d0a0e;` (dark text on gold). The FLEX VALUE badge in `flexTxt` (l.1714) also uses `background:var(--good)` — leave it green (it is a different badge, not TOP), or move it to gold if the Owner wants; flag for Owner ruling.

8. **OVR bubbles conditional.** The current card shows OVR for every player (`${r.p[3]} OVR`). The proposal renders a bubble only for ≥85. Keep the numeric OVR line for all players (it is data, not decoration), and add the three team-colour swatches only for ≥85. Do not hide the OVR number for <85.

9. **`fitNoteHTML` is a no-op (l.1663 returns `''`).** The proposal's `${fitNoteHTML(...)}` in the card header does nothing. Harmless; either remove the call or leave it (it will re-activate if P-067 re-enables fit notes). Note only.
