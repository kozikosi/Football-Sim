## REVIEW

The card redesign is specific and anchored. Two problems:

1. **`getTeamColor`, `getTeamLogo`, `POS_DISPLAY` are called but not defined anywhere in this file.** The proposal depends on P-004/P-110 for those helpers (l.486-490). That is fine as a dependency statement, but the Architect cannot implement this row without knowing the exact signatures. The dependency list should include the function signatures, e.g. `getTeamColor(teamName) → '#hex'`, `getTeamLogo(teamName) → 'url or path'`, `POS_DISPLAY[pos] → 'display string'`. Without them the snippet is not portable.

2. **The "three colour bubbles only under OVR and only for 85+" rule is ambiguous in card view.** The ASCII mockup (l.57-59) shows three bubbles reading 98, 95, 92 — but a single player has one OVR. The proposed code (l.91-95) renders exactly one bubble per card: `ovr >= 85 ? one bubble : ''`. So "three colour bubbles" must mean something else — likely the three team colours (primary/secondary/accent) rendered as three swatches. The mockup and the code disagree. The Architect needs to decide: three swatches of team colour, or one OVR bubble. They are not the same thing.

3. **"Bigger logos centred over their bubbles" (Owner requirement #4) is not implemented.** The code places the logo in a flex header row (l.99-103) beside the team name, with bubbles in the same row pushed right (l.92-95). Nothing is centred over anything. The CSS (l.208-223) confirms a horizontal `flex` layout. This requirement is currently unmet by the proposal.

4. **"No white text" (requirement #8) and "Numbers and text in selected team's palette" (requirement #9) are in tension.** The CSS sets `.pcard-ovr` (l.286-291) to `color: var(--gold)` and `.pcard-name.shimmer` to a gold-to-white gradient (l.269). The gradient's midpoint is literally white (`#fff`). On a dark panel this may read as white text, which requirement #8 forbids. The shimmer should use `var(--gold)` at both ends, not white.

5. **The `(2.24) without parentheses` change (requirement #6) is only addressed for the table view (l.442-444), not the card view.** The card footer (l.128-133) still renders `(${r.v.toFixed(2)})` with parentheses. Inconsistent.

## IMPROVEMENTS

- Add exact signatures for `getTeamColor`, `getTeamLogo`, `POS_DISPLAY`.
- Resolve the "three bubbles" ambiguity: state whether they are three team-colour swatches or one OVR bubble, and make the code match.
- Centre the logo over the bubbles, or reword the requirement.
- Change the shimmer gradient endpoints from `#fff` to `var(--gold)`.
- Apply the no-parentheses rule to the card footer too.
