## Additional findings vs review #1 (vl)

1. **Elimination check is on the wrong round (logic bug).** The proposal's `advancePlayoffRound` checks `games = seasonState.playoffRounds[rk]` (the CURRENT round) and `userAlive = games.some(g=>g.home===user||g.away===user)`. Since the user played in the current round, `userAlive` is always true — the elimination branch never fires. The check must determine whether the user WON their current-round game (i.e., is still alive for the next round). Fix: `const ug = games.find(g=>g.home===user||g.away===user); const userWon = ug && ((ug.result.homeScore>ug.result.awayScore) === (ug.home===user)); if(ug && !userWon) { ... eliminated ... }`.

2. **`simulateRemainingPlayoffs` re-simulates the current round.** It loops `for(let i=currentIdx; ...)` starting at the current round, calling `playGame` on games that are already played. This overwrites results. Should start at `currentIdx + 1` (the next unplayed round), or guard with `if(!g.played)` / `if(!g.result)`.

3. **`simPlayoffsBtn` handler drops `startPlayoffs()`.** The original handler calls `startPlayoffs()` first (to build the wildcard round). The proposal's replacement calls `simulateRemainingPlayoffs()` without ensuring `seasonState.playoffRounds` is populated. If clicked before playoffs are started, it crashes. Add `startPlayoffs()` before `simulateRemainingPlayoffs()`.

4. **`rest` handler (l.3965) same assumption.** It assumes playoffs are already started. The proposal's replacement has the same dependency. Verify the call chain — if `rest` can be clicked before `startPlayoffs`, add the call. (The original code also assumed this, so it's pre-existing, but the new code should be consistent.)

The defensive check is harmless but should be documented as defensive. Also fix the `userAlive` logic (finding #1) so it doesn't silently never-trigger.
