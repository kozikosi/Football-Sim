## Defects / risks
1. **"undefined" root cause is overstated.** The existing ternary `e.name ? ... : '—'` already returns '—' when e.name is falsy (undefined/null). The "undefined (70)" case UK describes would only occur if raw is an array with raw[0] undefined (flexed entry missing a name) — a narrower case. UK's fix (`name = e.name || '—'`) is still safer and worth applying; label the root cause as "defensive hardening", not "bug producing undefined".
2. **V23-only dependencies.** UK's changes C and D reference `foil-shimmer` class and `--team-${team}-primary` CSS variables. Neither exists in Pre-Colors (grep: 0 hits). Pre-Colors has `--good`/`--gold`/`--accent` and the `sf90`/`sfstar` classes. Recommend falling back to `--gold` with the existing `sf90` shimmer style, or flagging these as V23-only (depends on P-004 team theming + P-111 foil-shimmer style name).
3. **85+ vs 90+ conflation.** UK's requirement says "foil shimmer on ... every 85+ player", but starsFaceoffHTML already displays 85+ players; the `sf90` class (90+) adds the star+background. UK's change D keeps `x.ovr>=90` for the star but adds foil-shimmer to all 85+. Clarify: shimmer on 85+ (new), star on 90+ (existing). Don't drop the 90+ star.
4. **renderIdentityPanel change (E) is a behavior change.** renderScoutingHTML already calls with open=true, so the opponent report is already open by default. Only the user's own identity panel (open param) may be collapsed. Changing `<details>` to `<div>` removes the collapse affordance entirely — verify that's desired; otherwise keep `<details open>`.
5. **normalizeSlotEntry line numbers.** UK cites 3335-3338; actual is 3336-3340. Minor; fix in final.
