## Critical Findings for Colors v1

### 1. Ink/Contrast System (w37 R4) — **HIGH PRIORITY**
**Problem:** The bubble ink helper computed against `pk.acc3D/acc3L` (a solid team accent) but the bubbles paint the PAGE gold/rose (`--gold2`/`--rose`). The inline `color` was overridden by `.zpb-fm-ini b{color:var(--tn)}` — the team's LIGHT-theme ink on a dark-theme bubble = invisible names (Chiefs Gorden).

**Fix shipped in w37:** Ink now computed against the REAL bubble color per side per theme, applied through `--fmink`/`--fmsub` vars on each bubble. The 90+ shimmer keeps its `!important` team accent.

**Colors v1 action:** The team-color takeover (`:root[data-zpbteam]`) remaps `--rose` to the franchise's third color — a Chiefs defense bubble IS Chiefs red, not the page rose. The ink system MUST target the takeover-aware paint, not a static accent. This is a shell concern but the engine's `teamRatings`/`teamIdentity` output feeds the color map. Document the ink contract in the engine/UI seam.

### 2. Gone% 99% Cap (w37 R1) — **PRODUCT RULE**
**Problem:** Gone% shows 100% but the player is still available next round.

**Fix:** `Math.min(99, Math.round(x*100))` at the render choke point (`pctTxt()`). Model numbers untouched — display only.

**Colors v1 action:** Add to `PROJECT-KNOWLEDGE.md` as a product rule: "Gone% display capped at 99% in all three surfaces (draft table GONE column, position preview, mobile prow)." Not a protected constant.

### 3. Veil Opacity (w37 R5) — **CINEMATIC CONTRACT**
**Problem:** Veil fades IN over 1.1s — week-1 preview fully visible during fade.

**Fix:** `.zpb-prematch.zpb-prematch-veil{opacity:1}` — veil starts OPAQUE, only text animates, 3.1s JS fade-out reveals page. One rule covers ALL cinematics (SEASON OPENER, rivalry, every playoff round opener).

**Colors v1 action:** This is a shell CSS rule. The engine must not assume a transparent veil exists during cinematic startup. The cinematic contract in the handoff §3 should note: "veil is opaque at t=0; text animates; JS fades veil out."

### 4. Honors Before Confetti (w37 R10, w38 R10) — **STORY RAIL ORDER**
**Problem:** Celebration FX (confetti, "You made the playoffs!") fires before honors land.

**Fix (w37):** HONORS EARNED zone moves to FRONT of story rail; celebration waits `honors×0.9s + 1.5s`.
**Fix (w38):** SIM-SEASON books overlay renders review page BENEATH it; rail holds (animations paused) while overlay is up; Continue releases cascade.

**Colors v1 action:** The engine's `computeRegularSeasonAwards` output feeds the honors rail. The story rail order must be: honors first, then FX. The shell's `checkRewards()` gate must queue non-big rewards while cinematics are up.

### 5. Playoff Cinematic Gate (w37 R11, w38 R13) — **REWARD QUEUE LAW**
**Problem:** `checkRewards()` sees RESULT, fires confetti + banner DURING the pre-game intro (above the replay overlay).

**Fix:** Gate ALL FX while any full-screen cinematic is on screen (`.zpb-replay-ov`, `.zpb-prematch`, `.zpb-sbfin`, `.zpb-restov`). Queue rewards; drain at final whistle / close / Continue / 15s safety.

**Colors v1 action:** The engine's `playGame`/`simulateCurrentWeek` produces events. The shell's `checkRewards()` is the consumer. The gate logic is shell code but the event shape (`{q,t,pts,type}`) must carry enough context for the gate to know "this is a playoff win, queue it."

### 6. Skip Button → True Final (w37 R12, w38 R12) — **REPLAY INTEGRITY**
**Problem:** Skip during game → final 0-0 with empty log.

**Fix:** Skip flushes ENTIRE remaining play-by-play instantly (quarter cards, every play, last drives, blocks) then reads TRUE final (`finH/finA`), never partial live counters.

**Colors v1 action:** The engine's `playByPlay` must support a "flush remaining" mode. The replay is a shell view but the data comes from the engine's event log.

### 7. Dime (CB4) Slot (w38 R4) — **ROSTER/SLOT MAP**
**Problem:** Roster had NO CB4 slot → `zpbDimeOf` found nothing → Dime bubble empty/instant (no draft beat).

**Fix:** CB4 joins `ROSTER_SLOTS` after `CB3` (31→32 slots, draft runs 32 rounds). CB4 now a natural corner slot through EVERY map: `NATURAL_SLOT_MAP`, `STATIC_SLOTS`, `WV_SLOT_GROUP`, `SLOT_GROUP`, `SLOT_FAMILY`.

**Colors v1 action:** This is a PROTECTED CONSTANT change (`NATURAL_SLOT_MAP`, `STATIC_SLOTS`, `ROSTER_SLOTS` in `flex.json` REV 2). The Architect must:
- Add CB4 to the 32-spot table
- Re-pin hashes in `MERGE-MANIFEST.md`
- The 32-round draft supersedes the w33 31-round law (flagged for veto in W38-INTAKE-LEDGER.md)

### 8. Secondary Unification (w38 R5) — **DATA BASIS CONSISTENCY**
**Problem:** Three surfaces, three bases for Secondary:
- Your Breakdown: slot avg vs 32 draft boards
- Detail panel: top-6 CB/FS/SS (70-fill for missing 6th DB) vs REAL 32
- Strengths: reused whichever array fed them

**Fix:** CB4 slot removes the 70-fill; draft-review detail ranks against the 32 draft boards (same basis as Your Breakdown). Madden Rankings' REAL-team detail keeps real-32 basis (different roster, truthfully labeled).

**Colors v1 action:** The engine's `teamRatings` must produce consistent per-slot values. The shell's detail panel must read the SAME basis as the breakdown. Document the basis contract.

### 9. Player Name Coloring (w38 R1) — **UNIFIED NAME INK LAW**
**Rule:** Position Rankings page's player-name coloring format applied to EVERY player-name surface:
- Name wears team's text ink (light `txL` / dark `txd`)
- Number wears team accent
- 90+ keeps shimmer, 85+ vib

**Colors v1 action:** This is the "foil shimmer" / team ink law the Owner requested. The engine's `teamIdentity` must provide the three colors (`--team-primary`, `--team-secondary`, `--team-accent` — per P-004/P-110). The shell applies the law to all surfaces.

### 10. Advanced Stats Expansion (w38 R22) — **ENGINE DATA CONTRACT**
**New cards added:** Points/g, Total yards/g, Yards/play, Takeaways/g — all from data the engine already produces.

**Colors v1 action:** The engine's `generateGameSummary`/`playByPlay` must produce these aggregates. The shell's `teamAdvancedHTML` consumes them. Verify the engine's event shape (`{q,t,pts,type}`) sums to these totals.

### 11. Champions Timing (w38 R13/R14) — **BIG REWARD LAW**
**Big rewards** = every playoff-phase celebration (round wins, Conference Champions, Super Bowl champions). They queue unconditionally and drain ONLY at:
- Final whistle of the replay
- Books Continue
- Super Bowl stage's Continue
- 15s safety timer

Super Bowl champions animation plays at the stage's Continue, OVER the champion page, with badge cascade released beneath it.

**Colors v1 action:** The engine must emit a `bigReward` flag or the shell must infer from event type (`q:5`, `type:'TD'` in OT, etc.). The gate/drain split is shell code but the engine must not fire FX directly.

### 12. Tree Cards — Seed → Crest → Name (w38 R16)
**Change:** Seed chip before name, crest before nickname.

**Colors v1 action:** Shell markup change. The engine's bracket data must provide seed + crest path.
