REVIEW-OF: 20261031-1025-uk-P-186-homepage-details.md
VERDICT: rejected

The proposal identifies the right page areas, but its complete patch is not a reliable implementation plan: it references color data absent from the pinned build, contradicts current palette rules, and does not substantiate its claimed viewport measurements.

- **Defect (shown):** the JS patch calls `TEAM_COLORS[teamName]`, but `TEAM_COLORS` is not defined anywhere in Pre-Colors, and the proposal does not add that table or a tested dependency. Calling `updateSetupColors()` would therefore throw instead of applying colors. `TEAM_DATA` is present, but it is not the proposed color map.
- **Defect (shown):** the complete CSS patch uses blue and orange in the full-width hero gradient (`rgba(79,140,255,...)` and `rgba(255,107,74,...)`), and sets the active footer label to `color:#fff`. These conflict with the Owner's no-blue-panels/no-orange/no-white-text rulings.
- **Defect (shown):** the proposed “edge-to-edge” hero applies `width:100vw`, `left:50%`, `translateX(-50%)`, and `margin-left/right:-50vw` together. The negative margins and the separate left/transform centering both offset the element; this does not yield the claimed centered viewport-width box. The review requires a single full-bleed positioning method and measured output.
- **Defect (shown):** the DRAFT button is absolutely positioned relative to `#draftSetup`, a panel with `min-height:60vh`, not the viewport. `top:calc(50% - 1.5rem)` positions the button's top edge, not its center; it also leaves the controls in normal flow without space reserved for the absolute button. Thus the stated “half a button-length above window center” is not established.
- **Defect (shown):** the `.setup-controls` styling in the complete CSS patch has no matching wrapper in the actual `#draftSetup` markup. The suggested markup change is not included in the complete patch; its sample also inserts `speedInstantBtn` and `speedSlowBtn` IDs that already exist in `#draftLive`, creating duplicate IDs if copied.
- **Defect (shown):** the proposal says the header contains a moving 20-0 text, then only styles `.hero h1`; pinned Pre-Colors has a football icon and the static heading “NFL Draft Simulator” (plus tagline and stepper), not a 20-0 element or its animation. The patch neither adds the requested text nor creates its motion.
- **Risk:** when the team selector is switched to `__random`, the final JS resets the select styles but leaves the root `--team-accent` set by the prior team. Any UI using that root token can remain on the old team color. Define and test the reset policy, including the root property.
- **Risk:** option `white-space`, `overflow`, and `text-overflow` styles on native `<option>` elements are platform-dependent. The proposal supplies no Playwright/browser measurements or screenshots showing that long team names stay readable on both requested widths.
- **Not run:** a browser measurement at 1280px or 390px. The “computed positions” table is not a Playwright receipt: only sample code is supplied, and the listed footer height/button coordinates are not backed by output.
- **Weakest point:** the mock-up reports visual coordinates as computed, but the button is positioned relative to the setup panel and the hero's combined centering offsets are inconsistent with the claimed viewport measurements.
