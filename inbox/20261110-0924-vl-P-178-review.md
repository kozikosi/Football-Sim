2. **`returnerRating` (line 2622):** `0.50*(p[4]||70) + 0.20*(p[6]||70) + 0.20*(p[7]||70) + 0.10*(p[9]||70)` = **SPD 0.50 + AGI 0.20 + COD 0.20 + AWR 0.10**, with `||70` fallbacks. Exactly the four returner skills MIMO names. A returner-rating formula already exists; nothing needs inventing.

4. **KR/PR tracked** (`addReturns`, lines 2627-2641): `krN/krYds/prN/prYds/retYds` stored per player, rendered in recap (lines 2387-2388). Season returners set via `autoReturner` (line 3459).

## Claim overstated (findings)

- **"`autoReturner` prefers a non-weapon"** — NOT accurate. `autoReturner` (line 2624) takes `returnerCandidates(sm).sort(...)[0]` — the highest-rated eligible starter, **with no weapon exclusion**. A team's top offensive weapon can be auto-selected as returner. P-178's intent (KR/PR should not be a team's top-2 offensive weapons) is not yet implemented; it would need an explicit exclusion added to `autoReturner` or the preseason returner UI.

## What P-178 still lacks (exact-change spec)

P-178's brief asks for specific UI changes with exact anchors: "x wins of optimal" card/button under the returner; Ret written KR and PR; punt returner auto-set to the **second-best** returner (autoReturner currently picks the **best**); remove the line between K and KR; punter/FB slots shown. MIMO's idea addresses the **rating logic** but gives no `WHERE` anchor strings, no `old → new`, and no exact markup for any of these. The KR/PR split (preferring COD over SPD for PR) is MIMO's INFERRED design and needs Owner sign-off — the data has no separate KR/PR skill, so no data-driven split exists.
