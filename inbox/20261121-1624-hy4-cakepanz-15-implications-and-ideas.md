## 1. What the S15 close-out actually implies (the "further implications" asked for)

1. **The shell is now a receipt-bearing product, not just a UI.** S15 added generated artifacts (`SHELL-STATUS.md`, `CHECKSUMS.txt`/`MANIFEST.txt`, `gate-manifest`, side-by-side captures) that must be regenerated at the *same bytes* as the code. This creates a second quality dimension — **freshness**, distinct from integrity (a file can be hash-correct and still describe yesterday's build). My B1/B2 findings are exactly freshness failures, and they are the new dominant close-out risk. Implication: every generated artifact must be produced by a build step, never hand-edited, and a freshness gate must fail the release on drift.

2. **"Slices done" needs a definition.** The code landed; the hand-over didn't. Implication: define done as a conjunction — `acceptance-run.sh` exit 0 through step 17b + verify exit 0 at final bytes + filed side-by-side pairs + gate-manifest PASS — not "the batteries were green in a smoke run". Z.ai's own §12 agrees; the council should adopt the conjunction so the next close-out doesn't need a review to discover the gap.

3. **Selector churn is the recurring defect class.** Across S13→S15 the same drift appeared in ≥6 places (probe-w14, board/shell batteries, shell-status, selector note, laws, capture script). S15's probe re-point and N26 re-pin were each a manual fix. Implication: without a single source of truth for DOM hooks, every future re-skin re-breaks tooling. This is the highest-durability fix available (idea A).

4. **Pin drift is now the cutover blocker, not a doc nit.** Three live docs name three pins with three `colors/src` trees (`4ca9a071`, `d3bd81d2`, `408410477`; my lane §14). The delivered shell freezes `src/engine` at the third. Implication: cutover needs a single-truth pin record that docs *reference* rather than restate — otherwise the Architect's merge and the Owner's acceptance read different contracts. This is MUSE/Architect territory; I only propose the shape.

5. **The F27 tautology is a product lesson, not just a test lesson.** Laws L26/L27/L28 probed the post-walk page where the INTERIM display-rounded tie legitimately marks every row — so "exactly three" was trivially true and the UI's highlight had lost its meaning at that moment. Implication for UX: a highlight that can mark all rows is not a highlight; the display-rounded oracle caveat must stay (per the fence), but the *presentation* should distinguish "the three" from "all tied" without changing engine truth. This is an open Architect question, not a change I make.

6. **Delivery is zip-only; visibility is a council duty.** Z.ai cannot push (his START §5). My mirroring of this folder to `council/hy4@d601e63c5` is what makes "anyone can read it" true. ## 2. Ranked ideas for cakepanz / the shell (all shell-only; none edits the engine)

**A — One DOM-hook registry (highest priority).** `src/lib/ui-hooks.ts` exporting a frozen `HOOKS` map (`draftBtn`, `top3Row`, `whyCopy`, `topBadge`, `seedCode`, `savesPanel`, `shareBtn`, …). Batteries, probes, shell-status, capture script and node laws import keys instead of literal class strings; one node law asserts every selector literal in `scripts/`/`batteries/` resolves to a key. Cost: one sitting + a re-anchor pass. Impact: kills the whole recurring drift class before the Architect's merge re-labels anything.

**B — Generated-artifact freshness gate.** `scripts/artifact-freshness.mjs`: run every generator into a temp dir, diff against the committed files, fail on drift; wire as composite step 0 and 17c. Also enforce "one owner per checksum format" (D1's root cause: `verify-package` parsed md5 while `regen-manifest` wrote sha256). Cost: small. Impact: B1/B2-class failures become impossible by construction; directly serves the offline/release discipline.

**C — Resumable composite with byte-identity checkpoints.** Each step writes a receipt keyed by the tree's manifest hash; on resume, skip steps whose receipt matches current bytes and restart at the first mismatch. Add a mid-run byte guard that aborts (and names it) if any file changes while the composite runs — the exact mistake Z.ai self-reported in attempt 2. Cost: medium. Impact: three lost tails in this sitting alone; this is the tooling that makes a ~100-minute gate survivable across sittings.

**D — Owner "parity board" as a release gate.** A single static page generated by `side-by-side-s15.mjs`: LEFT (w89 bytes) vs RIGHT (candidate) for the 5 scenes × 2 viewports × 2 themes, with the in-code token assertions shown as pass/fail labels. The Owner flips scenes and signs off in one place; a missing pair is a named FAIL, not a prose caveat. Cost: medium (the capture script already exists; it died early twice). Impact: turns my M1 from a review finding into a gate.

**E — "Why this pick" provenance chip.** The Owner's `0020` verbatim asks for "the little description of the top 3 choices of why the user would select that player". S15's `whyFor` copy is generic board metrics; w89's chip carries plan text + % + "the math's pick" / "−X.X pts vs. best". Proposal: derive the chip text from the *same* VM/`planWhy` that drives the engine, so the UI explains real engine reasoning without inventing data — and keep the display-rounded-oracle caveat visible whenever the tie is INTERIM. Cost: small. Impact: closes the most visible gap between the shell and the Owner's stated visual target. (My reading of w89's exact presentation is REPORTED/INFERRED, not a verbatim demand — flag, do not silently change.)

**F — Spatial badge field + play-call card (Owner's north star, post-v1.1).** The Owner ruled `pfd-01` + `pfd-02` are "the real goals … but replace the player faces with more of a badge format", and bound anti-goals: no scouting, no full-GM, no faces. Both are *shell presentations of existing engine truth*: a frozen-ratings badge at each player's spatial position (name/pos, OVR/SPD/STR, slot/flex, team colours, gold higher-OVR marker) and a call card over `planWhy`/`applyOffPlan`/`applyDefPlan` with measured Engine Value default. Proposed next step is a **throwaway spike** (one screen, ~22 badges, no engine, no tests) so the Owner can say whether "badge format" means this — not a build. Cost of spike: small; product: post-v1.1, unbuilt.

**G — Small a11y/micro-copy polish.** `aria-describedby` on the Draft button, tokenised (not hard-coded) colour for the why-line, and a toast vocabulary that only speaks landed facts (S15's L31 already law-enforces the last one). Cost: trivial. Impact: incremental; lower priority than A–E.
