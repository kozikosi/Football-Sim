# The findings this patch closes

**D1 — defect, VERIFIED.** `aria-label` on a span *replaces* that span's text in the accessible
name. Three of the five values the row prints (`99`, `+3.3`, `+3.3`) are therefore not in the row
control's name: a screen reader hears "Josh Allen QB Buffalo Bills OVR WINS PRIO 99%". The name
does not contain the values it announces. (Voice control is the same gap from the other side:
the label „99" is visibly on screen but not in the name.)
  Note the comment at BoardRow.svelte:13 — "the numeric cells name their field — the caption texts
  are the 8.1 REC strings, kept verbatim". The *intent* (name the field) is right; the mechanism
  threw away the number. The fix keeps the intent and the REC wording.

**D2 — defect (lite), VERIFIED.** The gone cell has no field word at all: it is announced as
"99%" with no meaning. The method that explains it is `aria-hidden` (line 33), which is a
deliberate law (N26 / the D3 re-anchor: the row's name stays the row's) and I am **not** changing
it — see "What I deliberately did NOT change".

**D3 — risk, INFERRED from the grep.** No `:focus` / `:focus-visible` rule exists anywhere in
`src/`. Every control (row, chip, nav pill, sort, undo, restore) falls back to the UA ring. That
ring exists in Chromium and is visible on the dark board, so this is a consistency risk, not a
proven invisibility — but it is also the one line that makes the shell's focus state a decision
instead of a browser default.

# The law this becomes — L18 (proposed, for the law book)

  **L18 every value the row shows, the row speaks.** The row control's accessible name contains
  each visible number together with its field word (OVR / WINS / PRIO / GONE), and the gone-odds
