## Findings

1. **`shimmer-all` vs `.shine-all` class name mismatch.** The JS `apply200Shimmer` adds `shimmer-all` (l.298: `element.classList.add('shimmer-all')` and `element.querySelector('.cyg')?.classList.add('shimmer-all')`), but the CSS defines `.shine-all` (l.305: `.shine-all { ... }`) and `.cyg.shimmer-all` (l.312). So the 90+ full-foil-shimmer path never applies the `.shine-all` styles (the class name doesn't match). Fix: make JS add `shine-all`, or rename CSS to `shimmer-all`. Also `.cyg.shimmer-all` is defined but the JS adds `shimmer-all` to `.cyg` — that one matches. Only the root `shimmer-all` (on the element) is mismatched with `.shine-all`.

2. **`--gold` value mismatch.** The snippet defines `--gold: #d4af37` (l.108) but Pre-Colors uses `--gold: #ffc43c` (l.217). The Owner's theme wants gold `#d4af37`? Actually the Owner's theme north star (Beam's rose-gold-white-dark-theme) uses gold `#d4af37`. Pre-Colors uses `#ffc43c` (snot yellow, which P-058 wants to change to shimmering gold). So the snippet's `#d4af37` is actually the target. But for consistency within the product, the snippet should note that `--gold` should be `#d4af37` (post-P-003/P-058) not `#ffc43c`. Document the mapping.

3. **`color-mix(in srgb, ...)`** — modern CSS (2023+). May not be supported in older browsers. The snippet uses it for `.cyg` color. Provide a fallback: `color: var(--team-primary);` with `@supports (color: color-mix(in srgb, red, blue))` for the color-mix version. Or just use `var(--team-primary)` directly since the team colour is already set.

4. **`#fff` in shimmer gradient.** `linear-gradient(90deg, var(--gold), #fff, var(--gold))` — invisible on light backgrounds. Same issue as P-117/P-118/P-119/P-121. Use `var(--gold)` → `var(--gold-deep,#b8860b)` → `var(--gold)`.

But the integration section maps `--team-primary` → `--tp` (Z.ai) or `--team-primary` (P-004). Document the mapping clearly.
