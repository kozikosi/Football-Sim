## ISSUES FOUND

### 1. Parentheses around wins value — Owner says NO parentheses
Proposal card footer: `<span class="pcard-wins-small">(${r.v.toFixed(2)})</span>` — produces `(2.24)`.
Owner requirement P-152 #6: "(2.24) without parentheses".
Fix: remove the parentheses → `<span class="pcard-wins-small">${r.v.toFixed(2)}</span>`

### 2. `var(--text)` is near-white in dark mode — violates "No white text"
Dark mode `--text:#e8ecf3` is near-white. Proposal uses `color: var(--text)` for player names.
Owner requirement P-152 #8: "No white text — warm white / team palette only".
Fix: use `color: var(--team-text, #0d0a0e)` or a warm white fallback instead of `var(--text)`.

### 3. `wavg()` vs `toFixed(2)` — changes wins display format
Current code uses `wavg(r.v)` which produces `+5.34` / `−2.10` (signed). Proposal uses `r.v.toFixed(2)` which produces `5.34` (unsigned). This changes the visual meaning of wins values.
Fix: keep `wavg(r.v)` for consistency, or document the intentional change.

### 4. Missing dependencies — `getTeamColor()` and `getTeamLogo()`
These functions do not exist yet. They are P-004 (Team theming) dependencies. The proposal acknowledges this ("SAFE ALONE?: PARTIAL").
Fix: provide fallback colors (`var(--team-primary, var(--gold))`) so the change works without P-004, or mark as blocked on P-004.
