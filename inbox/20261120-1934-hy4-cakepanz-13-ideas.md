The single most important implication of S13 is that the **shell/engine seam has become a real,
testable contract** (the N34 seam golden) and the **falsifier has become a named-law discipline**
(13b closed on `DIED — FAIL L13`). Both are structural advances, not one-off receipts. The
ideas below push on that seam — they are ranked by (impact × feasibility); weak ones dropped.

## Tier 1 — do before / at cutover (highest leverage)

**1. Make the seam golden a standing cross-tree canary, not a cakepanz-only receipt.**
Today N34 snapshots boardVM/goneOdds/lineupFor for the *frozen* pin inside cakepanz. The real
cutover risk is Claude's live `colors/` engine drifting from that snapshot after the merge. Publish
the same canonical JSON as a test in the Architect's engine suite, so every engine commit asserts
its own output against the cakepanz golden. Then the merge cannot silently break the shell.
Blast radius: one test + a shared golden path; no engine logic. Check: change a flex constant in a
scratch checkout → the cross-tree test fails with the golden's sha, revert → MATCH. This converts
a one-time receipt into a continuous guard — the natural next step once the seam is formal.

**2. A two-tree diff harness so cutover is measured, not a leap of faith.**
The cutover checklist itself notes the slice battery's 3 DEFER items need both trees. Run the SAME
law suite against cakepanz's frozen-snapshot shell and Claude's colors tree via a `TREE_ROOT` env
var, emitting a side-by-side pass table. Same laws, two targets; any divergence is a merge defect
before it ships. Blast radius: runner-only, no product. Check: green on both trees at the pin →
identical per-law results; a planted UI divergence shows as a single-row diff. This is the direct
answer to "the golden MATCH is the first gate" — it makes the rest of the gate visible too.

**3. Fix the two citation defects in the delivery before the relay.**
The composite's `ACCEPTANCE-RECEIPTS.txt` is cut at step 13 while §1.8b claims END-TO-END, and the
13b receipt is cited at `deliverables/receipts/…` while it lives at `deliveries/receipts/…`. Both are
shown in my review. Cheap, zero-risk, and they protect the relay's integrity.

## Tier 2 — product/UX improvements to the shell

**4. State-based one-shot latch instead of the 380 ms timer (the residual R1).**
Key the staged-Confirm guard on the staged `(id, slot)` identity, not wall-clock time: a pick can
only dispatch once per staged item, and re-staging produces a new latch. Removes the "slow
double-click" window and the "fast legitimate second pick dropped" case at once. Small, reusable
as a `useOneShot` action. Check: a falsifier mutant that deletes the latch must make L22 die.

**5. Make a mid-draft board shareable, not just a finished brag.**
`?seed=b36:…` (D2/W12) reproduces a draft given team+slot+code. Extend the share handle to carry
the *draft state* — team, slot, picks made, sort — as a compact `?d=` blob, with engine replay as
fallback and the seed always written back. Today slice 5's cards are self-contained but a mid-draft
board is not replayable from a link; this closes the loop the seed work started. Check: open the
link on a clean profile → the exact board (same rows, same picks, same sort) reappears; a tampered
blob falls back to a random draw, never a wrong draft (the N35 lesson).

**6. Keyboard parity for the signature one-click ring.**
The top-three ring (L13/C′1) is the board's defining interaction but is highlighted for pointer
users. Add arrow-key + Enter navigation across the ringed rows with a focus ring consistent with
the N24 system-font work. Check: a keyboard-only pass drafts a ringed row with zero pointer events;
the visual battery's ring-present guard stays green.

**7. Turn model-first into an explainable UI surface.**
The engine's numbers (slotWins20-derived Wins/Priority, gone%) drive every row but stay implicit.
A small "why this board" panel that shows the engine's own values for the top rows — sourced from
the seam VM, never re-derived in the shell — makes the Owner's model-first doctrine visible and
makes the seam golden's data the single explanation. Check: the panel's numbers equal the VM's
exactly (a seam law), so it cannot drift from the engine.

## Tier 3 — hardening / council infrastructure

**8. Make the hard offline requirement measurable.**
The tent-in-the-woods rule is a stated hard requirement, but nothing asserts *zero network
requests* across a full draft+season run; the viewport matrix counts console/page errors only.
Extend the matrix to count and fail on any `request` event (CDN, font, telemetry) when running
`dist/single.html` from `file://`. Check: a planted CDN URL in a card makes the offline law die.

**9. Content-addressed delivery recipe to kill reconstruction drift.**
S13's first real catch was the c10/c11 byte-identical diff re-host silently reversing a patch.
Ship a `recipe.json` with each delivery naming the exact parent delivery hashes and operations,
plus a `reconstruct.mjs` that verifies the recipe against CHECKSUMS.txt. Then a reconstruction is
reproducible by hash instead of by prose — the same discipline the seam golden brought to data,
applied to the tree itself. (Tooling-level; no product change.)
