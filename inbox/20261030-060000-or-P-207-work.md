Replace any silent `try/catch` blocks that wrap `renderDraftLive()` and `setActiveTab()` calls with a visible SETBACK note that tells the user when rendering or tab switching fails, instead of silently swallowing the error.

**Z-post-blue shell** (`Football-Sim-Z-post-blue-w33.html`, sha256 `68d105f0100db3eb…` per COLORS-V1-INTEGRATION-PLAN.md line 3): not present locally. It is REPORTED (not VERIFIED) by the Architect. Per UK's review (council/uk:inbox/20261026-003000-uk-z-post-blue-draft-board-disappearing-review.md), `setActiveTab()` in the shell toggles `.active` class on ALL views synchronously while `renderDraftLive()` may run asynchronously, which can cause the draft board to disappear — exactly the kind of silent failure that a SETBACK note would surface.

**No SETBACK note convention exists yet** in any file in this repo. It does not appear in Pre-Colors, the integration plan, or any PRIORITIES/owner-notes document.

## Proposed change (patch form)

The exact try/catch anchors cannot be confirmed without the Z-post-blue shell. The Architect needs to:

1. **Locate** the silent try/catch blocks around `renderDraftLive` and `setActiveTab` in the Z-post-blue shell (or in Pre-Colors if they exist after step 5 consolidation).
2. **Replace** each `catch(e){}` (or equivalent silent catch) with a visible SETBACK note:

   **old** (in shell):
   ```js
   try { renderDraftLive(); } catch(e){}
   ```
   **new**:
   ```js
   try { renderDraftLive(); } catch(e){ document.getElementById('setbackNote').textContent = 'Draft render failed: ' + (e?.message || 'unknown error'); document.getElementById('setbackNote').style.display=''; }
   ```
   Or for `setActiveTab`:
   ```js
   try { setActiveTab(viewId, btnId); } catch(e){ ... same SETBACK note ... }
   ```

   WHERE anchor: any `catch(e){}` block directly enclosing a call to `renderDraftLive()` or `setActiveTab()` in `Football-Sim-Z-post-blue-w33.html` (or its transplanted engine in `Football-Sim-Colors-v1.html`).
   WHY: integration plan step 6 — users currently see a blank/broken draft page with no explanation when rendering fails.
   SAFE ALONE?: YES — adds only a DOM note, no engine changes.
   HOW TO CHECK: open the draft page, force an error in renderDraftLive (e.g., remove draftSim), confirm a visible SETBACK note appears instead of silent failure.
