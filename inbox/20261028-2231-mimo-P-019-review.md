1. **VERIFIED — the premise "turnovers first, then stars" is wrong.** `generateGameSummary` returns `[p1, p2full, p2stars, p3]` (l.3220). `p1` already contains the chronological play-by-play: `p1 += '</p><p class="detail-item pbp">' + pbp.html` (l.3179). Turnovers do **not** lead; the play-by-play already sits before them. What the Owner's "starts at 1st Quarter" can still mean is that the recap *opens* with a finish-first narrative sentence ("X finished it off, 24–17", l.3177) rather than with the Q1 line — a product call, see the open question at the end. Beam's item 1 as written would move nothing.

2. **VERIFIED — the "blocked XP at 0-0" text does not exist; its *mechanism* does, and it is not where Beam or UK point.** The string never appears (0 grep hits for `0-0` and for `0–0`). The real defect: `buildDefenseDetail` records a block as `blocks.push({kind, name})` — **no quarter at all** (l.2616) — and the recap then invents one: `hashPick(g,'bq'+s+i,[1,2,3,4])` (l.3020). A blocked *extra point* can therefore be sorted into Q1 of a recap whose first touchdown came in Q2, i.e. a kick block shown before anyone has scored — exactly what the Owner reported as "blocked XP at 0-0". Contrast the safety line right above it, which uses the real event quarter `safQs[i]||4` (l.3018-3019). Beam's fix ("skip XP-block events where the score is 0-0") and UK's fix (`if(bk.kind==='extra point' && r.homeScore===0 && r.awayScore===0) return;`) are both **no-ops**: `r.homeScore`/`r.awayScore` are the *final* scores, and a game with a blocked extra point can never end 0-0. The corrected patch is below.

3. **VERIFIED — the game ball is already always rendered; stars are a separate thing.** `ball` is built unconditionally from `d.mvp` (l.3188-3192) and appended even when `starsParagraph` returns `''` (l.3195). `d.mvp` is always assigned (`pool` falls back to `all`, l.2680-2682), so the game ball can never be missing. Beam's item 5 ("add a fallback so the game ball renders") fixes a non-problem, and Beam's item 4 ("reserve index 0 of `pick4` for the game-ball winner") conflates the two: `pick4` is stars only. The Owner's real requirement — *the game ball holder appears among the key players* — is still worth implementing, and is the only part of item 4 worth keeping (corrected patch below).

4. **VERIFIED — `playByPlay` is already Q1-first with no q=0 events.** Turn items are clamped `q:Math.min(it.q||1,5)` (l.3067), quarters are emitted `[1,2,3,4,5]` (l.3099-3106), and items sort by `q,t` (l.3072). Beam's "verify no q=0 events are emitted" checks a non-issue.
