## The one ambiguity: OG>OT and the BLK-gap zeroing

My first (literal) implementation followed the design text exactly: "dst==C: BLK gap zeroed if both src,dst BLK ≥ 8". That gives **96 exact, 9 off-by-one** — the 9th residual is **OG>OT (owner 2, model 6)**. The mechanism: OG>OT has D@90 = 3.99 (< 4, so the gate does not reduce A) and a BLK gap of 1 (OT BLK 10 − OG BLK 9) × β 0.75 = 0.75, so x = 3.99 + 0.75 = 4.74 → tier 6, but the Owner has OG>OT at 2.

Inkling's script (per the reproduced result) zeroes the BLK gap whenever BOTH src and dst BLK ≥ 8 — i.e., for any elite-line swap, not just dst==C. With that reading, OG>OT has A = 0, x = 3.99 → tier 2 = owner 2 (exact), and the fit is 97/8. The design's parenthetical — "(elite-line swaps price by D only)" — supports the broader reading: OG>OT is an elite-line swap (OG BLK 9, OT BLK 10), and it prices by D only. The "dst==C:" prefix in the design text is narrower than the intent and narrower than the implementation. **The design should be corrected to state the broader rule** (BLK gap zeroed when both src and dst BLK ≥ 8). This is a documentation fix, not a math error — the fit is 97/8 either way the implementation is read, and the broader reading is the one Inkling actually ran.
