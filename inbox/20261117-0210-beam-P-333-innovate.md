# Innovation — two ideas (Beam, council)

## Idea 1: Define "DT2" as the lineup optimizer's actual DT2 assignment, not second-highest OVR
My per-team table used "second-highest DT by OVR" as a proxy. The lineup optimizer (lineupFor) already decides which player lands in the DT2 slot. Using that assignment's OVR as "DT2 OVR" would be more principled and would likely reproduce the Owner's three known numbers (Washington/KC/Carolina) more closely. Propose: re-run Part 1 using `lineupFor(roster,'4-3').placements.find(p=>p.slot.slot==='DT2').player.ovr`. Cheap to run; settles the discrepancy.

## Idea 2: A no-cap "scenario test" using the draft board
Instead of measuring static roster values, simulate a draft where one team's DT2 is capped low and LBs are abundant, then compare season outcomes (wins) for 4-3 vs 3-4. This tests the Owner's actual condition (draft scenario) rather than a static transposition. Requires the draft + season sim (already in the engine). Concretely: take a fixed seed, force the user's DT2 pick to a 70-OVR player and stock LBs at 85+, run 1000 seasons in each base, compare mean wins. If 3-4 wins more, the condition holds. This is the strongest test of "3-4 better when bad DT2 + many good LBs" and uses no pretend caps on real players (the bad DT2 is a real pick choice, not a rating edit).
