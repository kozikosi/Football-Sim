# Team Select store change (P-317) — the acceptance checks, §5 form

**Authority to propose:** the superseding council prompt Part 4c. **The change itself is NOT made and must not be made by any seat** — this filing is the contract the Architect's implementation must satisfy. **Target build:** `65673a00` (or descendant); touches `colors/src/sports/nfl/app/store.ts` (`DraftStoreAction` START, `restoreDraft`, `toRecord`, `parseRecord`), `colors/src/sports/nfl/app/saves.ts` (`DraftPayload`, `WeekPayload`), and whatever envelope stamp the Architect chooses — the checks below assert semantics, not field names.

**Context (verified against the tip, not memory):** the engine already accepts the order — `newDraft(players, rng, cfg = DEFAULT_CONFIG, order: number[] = snakeOrder())` (engine/draft.ts:57; `resetOrder`/`pos` consume it). The UI is done (per the prompt; `orderWith()` in TeamSelect.svelte builds the full 1,024-pick sequence with round 1 re-headed to the chosen slot). The store is not: `restoreDraft` calls `newDraft(thawPool(rec.pool), makeRng(rec.seed).fork('draft'))` — no order argument, so the saved order is dropped and snake re-derives (**the exact defect the checks below detect**); `toRecord` writes only `seed/userTeam/picks/pool` — nothing of the slot or order; `DraftPayload` carries no slot stamp; `parseRecord` does no ordering validation; the appstate `START` action (appstate.ts:51) carries `saveId`/`now` for the envelope but no order/slot.

## The checks (each is a test the Architect lands; each MUST fail today, pass after the change)

1. **START with order → the draft persists the ORDER.** Dispatch START `{ seed, userTeam: 12, slot: 6, order: orderWith(12, 6) }` (whatever field names; semantics fixed): the record produced by `toRecord` round-trips through `parseRecord` with `order` deep-equal to the input (1,024 entries; round 1 equals round-1-with-team-12-at-index-5; rounds 2–32 equal `snakeOrder().slice(32)`). **Today: fails** — nothing stores it.
2. **restoreDraft uses the saved order.** `restoreDraft(rec-with-order)` returns a DraftState whose `order` is the saved order (element-wise), NOT the snake. **Today: fails** — snake is re-derived unconditionally. **This is the headline check:** it is the one the user feels — his pick is at his chosen slot or it is not.
3. **Snake fallback is byte-identical to before.** A record with NO order (any pre-change save, or `slot === null` → "let the league decide") restores `order` deep-equal to `snakeOrder()` exactly. **Regression guard** — must pass today and after.
4. **Slot bounds.** `slot ∈ 1..32 | null`; outside → START (or parse) throws a named error; never a half-started draft, never a wrapped index.
5. **Order validation refuses garbage.** A payload whose `order` is not a legal 1,024-entry sequence — wrong length; a team absent from a round or duplicated in round 1 beyond the single displaced swap; a team ≥ 32 — is refused at `parseRecord` (untrusted-input path) with a named reason; never cast-and-go. **Today: untested; the check exists because the whole 1024-entry claim rides on it.**
6. **The preview is the restored order.** `orderWith(t, s)` (the screen's own function) deep-equals `restoreDraft(rec).order` for every (team, slot) pair the picker offers — one sequence agreed by screen and resume, 32 slots × (spots the Architect samples; recommend the full 1,024-pick check on a few pairs, not an exhaustive cross-product).
7. **The slot stamp survives to the week envelope.** The chosen slot (the user's draft position) is stamped into the `DraftPayload` and carried forward into `WeekPayload` at kickoff (per the prompt: "DraftPayload/WeekEnvelope must carry the slot stamp"); after serialise→restore, the stamp equals the slot the user picked — including the legacy case (`null` → league decides) and the run-it-back case (`saveRevision` increments keep the stamp).
8. **Envelope round-trip is lossless.** serialize → parseEnvelope → parseRecord → serialize yields byte-identical canonical JSON for a draft saved at slot 6 (and for one at slot 1, and for `null`) — **the existing envelope asserts stay green**; the stamp is inside `payload`, so core/envelope.ts is untouched by this change.
9. **Determinism.** Two STARTs with identical (seed, team, slot) produce identical order arrays and identical `st.pos === 0` logs; the restore path draws nothing new (existing `restoreDraft` property, preserved by the change).

## The contract lines (what the implementation must respect even where tests can't see it)

- The order is **derived from the snake + the one swap at round 1** — the Architect must not re-rank teams or invent an ordering; `orderWith()` is the single source of the 1,024 sequence; the store consumes, never recomputes, never "fixes".
- **No slot in storage before START** — the stamp lands with the draft (P-317: the user's pick is a choice, not a default; `null` is a real choice).
- The resume contract from w74 stands: logged picks hold across builds (F5 ruling); **the order is part of the log's meaning — a save whose order was silently re-derived and re-saved is a lie about what the user chose; that is why #2 is the headline check, not a convenience check.**
