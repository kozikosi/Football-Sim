## Issues found

### 1. PERSONNEL_PLANS snippet invents unverified weights for 11/12/13 (risk)
The snippet presents `rec` weights for '11', '12', and '13' personnel sets as if they come from the spec. The spec §14.3 only documents the '10' experiment (WR1 1.5, WR2 1.0, WR3 0.7, WR4 0.5, RB1 0.2). The weights for '11' (WR1 1.5, WR2 1.0, WR3 0.7, RB1 0.2), '12' (WR1 1.4, WR2 1.0, WR3 0.7, TE1 0.9, RB1 0.2), and '13' (WR1 1.3, WR2 0.9, TE1 0.8, TE2 0.6, TE3 0.6, RB1 0.2) are VL's invention — not from the spec or any measured data. These should be labeled INFERRED/proposed, not presented alongside the verified '10' weights. An Architect integrating this snippet would not know which weights are measured vs. invented.

### 2. Cost = 0 for 11/12/13 is an unverified assumption (risk)
The spec's experiment only tested '10' with cost 0.22 (and cost 0 as a comparison). Setting the other three plans' cost to 0 assumes they have no plan cost. The spec does not state this. These costs may need their own calibration. Label: INFERRED.

### 3. 13 personnel as a selectable plan is not addressed (gap)
The spec §14.3 says "TE3 is worth 0.000 wins as a plan-route slot (13 personnel is never best at a league-average matchup)." The task title says "Offensive personnel as selectable plans (10 and 13)" but the snippet only calibrates '10'. The work does not address whether 13 should be a selectable plan at all, given that TE3 has zero plan value. If 13 is selectable, the blocking term change (issue 4) is the only calibration needed. If 13 is not selectable, the snippet should say so and why. This is a missing decision.

### 4. TE3-aware blocking term changes spec behavior (calibration question)
The proposal changes `(te2+70)/2` to `(te2+te3)/2` with a fallback. Spec §14.6d explicitly says this "still uses a generic 70 for TE3 (not changed; one more reason V23's plan calibration is its own item)." VL's proposal is reasonable but it is a spec change, not just a snippet. The Architect must decide whether to adopt it. The fallback logic (use 70 when TE3 is empty) is correct but the work should explicitly flag this as "changes spec §14.6d."

### 5. Target ~1% vs measured 0.52% (minor, calibration question)
VL targets "10 chosen ~1% of the time" but the measured share is 0.52%. The spec says "about one snap in a hundred" (~1%). VL's target is slightly higher than the measured data. Either is defensible, but the work should state the target explicitly and why it differs from the measured 0.52%.

### 6. Calibrated cost 0.55 presented with false precision (defect, minor)
The snippet uses `cost: 0.55` as if it were calibrated. VL correctly labels it INFERRED in the text, but the code snippet presents it as a specific value. The spec §14.3 says "The cost constant is INFERRED and cannot be pinned by the data." The snippet should use a placeholder or clearly mark it as a starting point for a sweep (e.g., `cost: 0.55 // INFERRED starting point; sweep until TE1 value preserved`). An Architect copying this snippet would treat 0.55 as a calibrated value.

### 7. Missing verification procedure (gap)
The work says "requires simulation runs sweeping 10-personnel cost from 0.22 upward" but does not specify: (a) the exact command to run, (b) how to measure TE1 value preservation (which function/output), (c) the stopping criterion in measurable terms. The spec references `recv-plan-experiment.js` but VL does not say how to rerun it with a different cost. An Architect needs: "run `node tools/mathlab/recv-plan-experiment.js --cost 0.55` and check that TE1 value >= 0.686 wins." Without this, the calibration cannot be reproduced.

### 8. WR4=10 is "raised to the table's one-step minimum" (calibration question)
Spec §14.4 says WR4's measured value is ~2.5 wins, raised to 10 because "a value of 0 would make the slot meaningless to the CPU's draft logic." VL's snippet does not mention this. If V23 offers 10 personnel as a selectable plan, WR4's near-zero value means the plan's fourth receiver contributes almost nothing. The work should note that WR4's plan value is negligible and the plan's real value comes from WR1-WR3.

## Weakest point of the work

The PERSONNEL_PLANS snippet is the centerpiece of the deliverable, but 3 of its 4 entries contain weights and costs that are not from the spec or any measured data. Only the '10' entry's weights come from the verified experiment. An Architect integrating this snippet would be importing invented numbers alongside verified ones without a clear boundary. The snippet needs clear INFERRED labels on every line that is not spec-backed.

Additionally, the work should address whether 13 personnel should be a selectable plan at all (spec says TE3 has zero plan value), and should include the exact verification command for the calibration sweep.
