The shared-card direction is useful, but the spec needs a consistent color rule and explicit adapters for the very different season-stats, leader, award, and draft-player records before it can guide Colors v1.

- **Spec conflict:** the card says non-user players use neutral name colors, then says names and OVR must use team-palette colors, not neutral. Choose one rule. To match the palette request and W38 direction, derive accessible text/accent tokens from each displayed player's team; keep the user's blue treatment where the Owner's style rule applies. Do not apply a raw primary hex to small text without contrast checks.
- **Data-shape gap:** `seasonStatLine(group, stats)` requires a group and stat object; season rows have `group`, `ovr`, `gp`, `_rating`, `_rank`, and `st`, but award rows often carry a preformatted `line`, and draft-board records are not season-stat records at all. Share the visual component, not a fictional common record: normalize each source to a card model with optional rating/rank, stat line, games, and award badge, and omit unavailable fields rather than filling them with invented values.
- **Non-player awards:** `renderRegularAwardsHTML()` has individual awards with `a.c`, but also team/coach entries with no player record. Use PlayerCard for actual player recipients; preserve coach/team awards in a separate award-result variant instead of forcing them into a player shape.
- **Glossary dependency:** the work says award explanations move to the Glossary, but gives no mapping of removed explanations to glossary entries. Do not delete the explanation content until the destination terms exist; this is a dependency, not just a card-style change.
- **Visual direction:** the heavy border and opaque panel defaults risk making every list a grid of boxes. Keep the requested cards but use an airy layout (light separators, spacing, restrained surface tint, hover lift) and reserve stronger accents for the user and award winner. This follows the Owner's earlier “more floaty and dynamic, less boxy” direction.
- **Shimmer behavior:** state exactly which element shimmers at 90+ (the OVR value is the cleanest choice), use the derived team accent, and disable the animation under reduced motion. The work specifies shimmer but no reduced-motion behavior.
- **Evidence:** inspected `userStatsInner()`/`seasonStatLine()` at lines 3632-3656, `leadersPane()` at 3702-3707, and `renderRegularAwardsHTML()` / `renderPlayoffAwardsHTML()` at 5851-5887. These confirm the different data shapes and the non-player award branch. The current source anchor for `userStatsInner()` is line 3651.
- **Not run:** a browser layout, 390px viewport, color-contrast measurement, or lint; this is a design-spec review without an implementation.
- **Weakest point:** derived team-color tokens and the exact non-player award layout need to be settled in the shared design system; the current proposal does not supply enough detail to verify those visually.

**Colors v1 takeaway:** define one typed view model for player cards and map each engine/result record into it at the UI boundary. Share the renderer while allowing absent season-only fields, and source team accents from one contrast-aware semantic theme object. This supports an eventual Svelte/React migration without coupling UI components to engine record layouts.
