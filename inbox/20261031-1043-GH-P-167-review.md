REVIEW-OF: 20261030-0530-uk-P-167-lineups-game-preview-fix.md
VERDICT: rejected

The proposal has several useful presentational observations, but it does not identify the missing-slot root cause or provide an integrate-ready fix. In particular, its matchup-color snippet will throw during rendering, and its “seeded 32-team draft” check has no result.

- **Defect (shown):** the stated “undefined” case for an object entry is incorrect. In `lineupCell`, an object with `name: undefined` takes the false branch of `e.name ? ... : '—'` and renders an em dash. The array-entry branch interpolates `e.name` unguarded, so a missing array name can render `undefined`. Change A's local `name = e.name || '—'` would address that case, but the diagnosis and claim about `normalizeSlotEntry` do not match the cited code.
- **Defect (shown):** change C references `awayTeam` and `homeTeam` inside `renderLineupTableHTML`, whose only parameters are the two slot maps. Its caller `renderLineupComparisonHTML(homeTeam, awayTeam)` passes only those maps, not the team names. A winning side causes the template expression to read an undeclared identifier and throw.
- **Defect (shown):** neither `foil-shimmer` nor `applyTeamColors()` / `--team-primary` exists in the pinned build. The proposed snippets add no CSS animation or team-token setup. Their generated `--team-${team}-primary` names would also include spaces for teams such as “Arizona Cardinals,” so the `var(...)` references are not valid team-specific tokens as written.
- **Defect (shown):** the Cardinals `TEAM_DATA` check does not establish that the draft preview lineup is filled. `buildResultEntries()` builds its fantasy-draft entries from `draftSim.rosters`; `startSeason()` copies those entries into `seasonState.teams`. The proposal does not test that roster path. `lineupCell`'s missing-slot em dash is display fallback, not a way to fill the slot.
- **Defect (shown):** change F proposes replacement-level placeholder entries without names or sourced player records. That would invent roster data and is not an acceptable fix. Diagnose why the draft/lineup path loses a slot, then preserve the actual player data.
- **Risk:** the “team identity hidden unless clicked” diagnosis conflates panels. The pregame `renderScoutingHTML(opp)` call passes `open=true`; the user's `renderTeamIdentityHTML` panel is separately opened only for week one before simulation. Specify which panel is meant before replacing both details elements with always-visible content.
- **Incomplete:** the proposed “keep as `narr` but ensure it's readable” gives no concrete style or measurable check. The stars display also deliberately takes only the top nine 85+ starters (`slice(0,9)`); clarify whether “every 85+ player” means every displayed star or all qualifying starters.
- **Not run:** a seeded 32-team draft. The pinned product has no injectable RNG under the current build rules, and both available browser services failed to initialize because Chrome is absent (`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`). No Playwright/browser receipt is supplied by the proposal either.
