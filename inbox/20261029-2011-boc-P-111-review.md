## Defects found (new, beyond vl/beam)

1. **`--gold` overridden to `#b8941f` in light mode conflicts with P-183.** P-183 says light mode needs a deeper gold *for small text* (contrast audit Q-V23-2), not a global token swap. Overriding `--gold` site-wide in light mode changes buttons, badges, draft-board accents, champion banners — all of which are designed around `#ffc43c`. Recommend keeping `--gold` as `#ffc43c` and adding a separate `--gold-text` (e.g. `#b8941f`) used only for small-text shimmer/numerics. (Refining vl #2.)

2. **Single-file constraint: relative `fonts/` paths break "one self-contained HTML file".** AGENTS.md §3: no split into several files, no build step for the user. Relative paths to `fonts/CinzelDecorative-Bold.woff2` require a `fonts/` folder next to the HTML — violates self-containment when the file is shared alone. Only two options: (a) base64-inline the WOFF2 (file grows ~200–400 KB on a 650 KB base), or (b) system serif fallback. The Owner must choose; recommend presenting both with size impact. (Reinforcing beam.)

3. **`foilShimmer` vs `textShimmer` naming split.** P-109/P-110 snippets use `textShimmer` for the same gold-sweep effect; P-111 names it `foilShimmer` (matching the Owner's "foil shimmer" term). Two keyframe names for one effect → duplication risk. Recommend standardising on `foilShimmer` as the canonical name (Owner's term) and updating P-109/P-110 references, or keeping `textShimmer` as an alias. Single name. (New.)

4. **`#fff` in `.foil-shimmer` gradients (4 places)** — violates no-white-text rule. Use `var(--text)` (same fix as P-109/P-110). (New.)

5. **Light-mode shimmer middle colour `#2a1a20` (dark) on a light background** — same questionable choice as P-109. On a white/light background, a dark middle colour produces a dark band, not a shimmer. Recommend `var(--text)` (dark text) which is correct for light mode, or a deeper gold. (New.)

6. **Cinzel Decorative for footer tab buttons and small UI** may be illegible at small sizes. Beam flagged ornate fonts for recaps. Recommend: Cinzel Decorative only for titles/headers/team names/champion/20-0 (per P-183 rule 3); body/recap/small UI stay on system stack. The snippet's application map puts Cinzel on too many small surfaces. (Reinforcing beam.)

7. **`!important` overuse** (snippet applies `!important` to font-family on ~40 selectors). Makes future overrides hard and can mask specificity bugs. Recommend a single class-based or variable-based approach: set `font-family: var(--font-display)` on a `.display` utility class and apply it where needed, rather than !important on every selector. (New.)

8. **`--rose` undefined** — used in `.foil-shimmer.rose` with fallback `#c97a8e`. Either define `--rose` in `:root` (Owner's rose palette) or drop the variable and use the fallback consistently. Recommend defining it since the Owner's theme is rose-dominant. (vl flagged; restating with recommendation.)

9. **`h4, h4` duplicate selector** (typo in the display rule). Remove duplicate. (New, minor.)

10. **`--font-body` includes Oxygen/Ubuntu/Cantarell** which are not bundled — they silently fall back. Harmless but noisy. Recommend trimming to the system stack already in use. (New, minor.)

11. **`html,body{font-size:14px}`** conflicts with `html{font-size:21px}` (l.2). The 21px base drives all rem/em sizing across the product. Changing to 14px shrinks everything. The Owner's request is about font *family*, not size. Keep 21px. (vl #1.)
