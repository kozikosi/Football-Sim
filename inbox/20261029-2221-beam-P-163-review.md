## Inaccurate claims (improved)
1. "quarterback play +3.3 pass protection" as a literal string does not exist. Matchup lines are generated by matchupLines() and combine shortUnit names; a line can contain both "quarterback play" (qb unit) and "pass protection" (olPass unit) only when those units are the paired swing. The proposed filter `.filter(line => !line.includes('quarterback play') && !line.includes('pass protection'))` removes EVERY line mentioning either substring, including legitimate QB/pass-protection matchup lines. Narrow it: filter only lines where both substrings appear, or exclude the qb↔coverage / olPass↔passRush swing entries by unit before generating lines.
2. `teamPalette(team)` using `TEAM_DATA[team].primary` is wrong: TEAM_DATA[team] is a roster slotmap with no `primary` field (verified). Team colours are NOT in Pre-Colors as a JS object — the Owner's 22 Oct colour table is the authority and is not embedded. The patch must either (a) embed the Owner's 32-team colour table, or (b) accept palette colours via CSS variables / a colour map. Without this, `palette` is undefined and stars render with no colour.
3. Cinzel Decorative is not loaded anywhere in Pre-Colors (no @font-face, no googleapis). The product rule forbids CDN. Either embed the font or fall back to Georgia/serif. The "project's display typeface (used on homepage/Draft button)" claim is true for V23/Z-post-blue but not Pre-Colors; anchoring to Pre-Colors, the font must be added in the same change.
4. The `@keyframes shimmer` CSS is new (not in Pre-Colors). The work lists it as an addition — fine, but it must be added; also honour `prefers-reduced-motion` per Owner ruling.
5. "Star emojis team-coloured and shimmering" — the existing `.sfstar` is gold (#ffc43c). Changing to team colour requires the colour source (item 2).
6. The work says "no drifting names" but the new card HTML puts `p.name` in a span with no animation — that's already the case in the proposal. Fine, but the shimmer must be confined to the ★ span only.
