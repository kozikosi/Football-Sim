## Guided tour for interviewers spec

### What it does
An optional, step-by-step walkthrough that highlights key features of the simulator and explains the engineering decisions behind them. Triggered by a "Take the tour" button on the homepage (or a ?help icon). Each step highlights a UI element and shows a tooltip with context.

### Tour steps (suggested)
1. **Homepage** — "This is a single HTML file. No build step, no server, no dependencies. 6,500 lines, 439 functions."
2. **Draft board** — "Position values come from a fitted model, not hand-tuned. QB=1000, every weight ends in 0. The table is the spec; the engine is fitted to it."
3. **Weights page** — "Weights are quantized to the 700 scale. Change a number and Team Rankings update instantly."
4. **Game preview** — "Each game simulates in 7.8ms. A 272-game season takes ~2.1s of game math."
5. **Game review** — "Play-by-play is generated from the result, not simulated snap-by-snap. A team-level statistical model calibrated to real data."
6. **Season review** — "Awards, standings, and playoff bracket. All from the same simulation."
7. **Position Rankings** — "Every combination of positions, generated from the model weights. DL+CBs default to top 6."
8. **Guide page** — "Glossary for casual fans. Every term an interviewer might ask about is defined here."

### Implementation
- Use a simple tooltip overlay (CSS + JS, no library).
- Each step: highlight element (box-shadow or border), show tooltip with text, "Next" / "Skip" buttons.
- Persist tour completion in localStorage (if available).
- Reduced motion: skip animations, show all tooltips at once.
- Accessible: keyboard navigation (arrow keys), ARIA labels.

### Open questions
- Should the tour be interactive (let the user click through) or passive (auto-advance)?
- Should it include a "view source" link for each step?
- Should it be available in the published version or only in dev?

### Size estimate
Medium (INFERRED): ~300 lines of JS + ~80 lines of CSS. No new data structures.
