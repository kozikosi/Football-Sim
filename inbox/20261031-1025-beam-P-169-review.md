## New findings

### 1. VL's `simSeasonBtn` old string doesn't match the code
VL quotes: `<button class="tabbtn" id="simSeasonBtn" style="width:auto;margin:0;padding:10px 24px;">Sim Rest of Season ▸ Review</button>`
Actual (lines 3891 and 3905): `<button class="tabbtn" id="simSeasonBtn">Sim Rest of Season ▸ Review</button>`
The actual buttons have NO inline style attribute. VL's old string includes `style="width:auto;margin:0;padding:10px 24px;"` which doesn't exist. The anchor string must be corrected before patching.

### 2. Banner CSS class conflict — `.fxbanner` overrides compact inline styles
VL proposes inline `cssText` for a compact banner: `padding:6px 14px;font-size:0.9rem;position:fixed;top:10px;...`. But the `.fxbanner` class (line 106) has `font-size:1.7rem;font-weight:900;padding:18px 26px;border-radius:16px;animation:fxpop 4.2s ease forwards,fxshine 1.6s linear infinite;background:linear-gradient(100deg,#ffd75e...)`. Inline styles win on specificity for most properties, but:
- `animation` from the class would still apply → compact banner would animate with gold shimmer + fxpop scale-up.
- `background` inline (`var(--panel)`) wins over class gradient.
- `border-radius` inline (8px) wins over class (16px).
The `fxpop` animation scales the element up, which conflicts with "compact". Recommend: either (a) remove `.fxbanner` class and use a new `.fxbanner-compact` class, or (b) add `animation:none` to the inline cssText. Option (a) is cleaner.

### 3. Banner duration: 4300ms → 3000ms not specified by Owner
VL reduces duration from 4300ms to 3000ms. The Owner's P-169 brief says "compact one-line banners ... small and horizontal" but doesn't specify duration. The original 4.2s animation (`fxpop 4.2s ease forwards`) is designed for the full-screen celebration. If the banner is now compact, the animation should be removed or shortened. Recommend: keep 3000ms for compact banners, but remove the `fxpop`/`fxshine` animation entirely (or use a simple fade-in/fade-out).

### 4. SUPER BOWL emoji removal — not required by P-168 style law
VL removes 🏆 emojis from the SUPER BOWL banner, citing "P-168 style law" (no emojis in badges). But P-168 says "no emojis in badges" — the SUPER BOWL banner is not a badge. The Owner's P-169 brief doesn't mention emoji removal. This is a design choice, not a requirement. Recommend: keep the decision open for the Architect; the emojis are celebratory and consistent with the game's tone.

### 5. "Play the <team>" button — `resetbtn` style may be too prominent
VL proposes `class="resetbtn"` for the "Play the <team>" button. `resetbtn` (line 247) has `background:linear-gradient(90deg,var(--accent),#6aa6ff)` — a blue gradient with glow shadow. The Owner's theme says "no blue panels". A blue gradient button for "Play the Titans" might conflict with the rose theme. Recommend: use a more neutral style (e.g., `tabbtn` or a new `.playbtn` class) that aligns with the theme.

### 6. "SEASON" banner insertion point not specified
VL says "Add when regular season completes" but doesn't specify where. The regular season completes when `S.phase==='regularReview'` (phase transition). The banner should fire at that transition, not on every render. Recommend: add the banner call in the phase-transition code (where phase changes to 'regularReview'), not in `renderRegularSeasonView`.

### 7. "CAN YOU GO 20-0?" banner — streak===17 fires during regular season
VL adds this in `checkRewards()` when `streak===17`. `checkRewards()` is called during regular season games. A 17-game win streak means the user has won every game (perfect season). This is correct timing. But `checkRewards()` also fires for other streaks (3, 5, 7, 10, 13). The "CAN YOU GO 20-0?" banner should only fire once (the `done('perfect17')` guard handles this). OK.

### 8. simSeasonBtn CSS selector is shared

### 9. `.mtag-div` blue gradient (related to P-168)

### 10. `banner()` is also called by `FX.play('conf')` and `FX.play('sb')`
