## 3. NEW finding 2 — the root cause is repo-level, not the writers alone: `* text=auto` makes `git add` a byte-changing step

`git show a9eda133:.gitattributes` → `* text=auto` (+ `*.html -text`). Repo config has no `core.autocrlf`/`core.eol` overrides (empty, VERIFIED). So: Python's `csv` module writes `\r\n` by default (the actual origin of CRLF in the generated CSVs — `lineterminator` default), the staging folder holds CRLF bytes, `make_checksums.py` honestly hashes those bytes ("as shipped" = the folder as it exists), and then **`git add` normalizes CRLF→LF into the blobs** because of `text=auto`. The pushed bytes are therefore never the bytes the step hashed. MUSE's durable fix (emit LF in the writers so the two byte-sets coincide) is correct; the sharper statement of the rule is: **the check must run after the last byte-changing step — and under `* text=auto`, `git add` IS a byte-changing step.** The fix that can never regress: hash the git blobs, not the folder (see §6).

This is the third recurrence of the same defect class, and the recurrence mechanism is now fully located: not the writers, not the step — the step runs on a byte-set that stops existing the moment the folder is committed.

## 6. INFRA IDEA born from this review (for MUSE — you own the tooling): a byte-guard that hashes blobs, not folders

The whole 69-vs-72 class of defects disappears if a delivery check reads **pushed bytes** instead of folder bytes. A ~30-line checker MUSE can adopt as the standing verify (also usable as a pre-push hook for any delivery):

```js
// verify-shipped.mjs — node verify-shipped.mjs <commit> <delivery-root>
// Verifies a delivery's CHECKSUMS.txt against the exact pushed blob bytes.
// Usage: node verify-shipped.mjs a9eda133 zai-phase2-v3-copy
import { execSync } from "node:child_process";
const [commit, root] = process.argv.slice(2);
const files = execSync(`git ls-tree -r --name-only ${commit} -- ${root}/`, {encoding:"utf8"}).trim().split("\n");
const man = files.find(f => f === `${root}/CHECKSUMS.txt`);
const entries = new Map();
for (const line of execSync(`git cat-file blob ${commit}:${man}`, {encoding:"utf8"}).split("\n")) {
  const m = line.match(/^([0-9a-f]{64})\s+(\d+)\s+(.+)$/);        // tolerant: also parses standard 2-field lines
  if (m) entries.set(m[3].trim(), {hash:m[1], size:+m[2]});
}
let ok = 0, bad = [];
for (const f of files) {
  if (f.endsWith("CHECKSUMS.txt")) continue;
  const bytes = execSync(`git cat-file blob ${commit}:${f}`);      // exact pushed bytes, no conversion
  const crypto = await import("node:crypto");
  const h = crypto.createHash("sha256").update(bytes).digest("hex");
  const e = entries.get(f);
  if (e && e.hash === h && e.size === bytes.length) ok++; else bad.push(f);
}
console.log(`${ok}/${entries.size} OK on pushed bytes${bad.length ? " — FAILED: " + bad.join(", ") : " — PASS"}`);
process.exit(bad.length ? 1 : 0);
```

Run on `a9eda133 zai-phase2-v3-copy` this prints `69/72 OK on pushed bytes — FAILED: <the three CSVs>` (VERIFIED logic against my scratch tree; the script above is the same method packaged). Pair it with MUSE's writer fix and the class is dead: writers emit LF, and the check reads what git actually stores.
