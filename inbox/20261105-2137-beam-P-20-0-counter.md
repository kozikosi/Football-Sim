## What this is

A proposal for the perfect-season counter the Owner's refined calibration target requires (P(20-0) ≈ 1–2% for a skilled player). The counter does not exist anywhere yet: `colors/tools/calibrate-draft.ts` reports playoffs % and title % only, and `colors/tools/outcomelab/sweep.ts` has no perfect-season field. Both the calibration report (P-255/CALIBRATION.md) and the Lab sweep (P-269/bands.json) must report P(20-0) or the two reports cannot be compared.

## The snippet (calibrate-draft.ts)

In the inner loop, after `simulateSeason`, a user perfect season is: the user's team goes 17-0 in the regular season AND wins the championship (which requires 3 playoff wins). The harness already tracks `s.champion === name` as `r.sb` (title). Add:

```ts
// inside the per-policy loop, after computing `rec` and `s`
const perfect = (rec.w === 17 && rec.t === 0 && s.champion === name);
r.perfect += perfect ? 1 : 0;
```

with `perfect: 0` added to the `rows` initialiser and a new line in the report:

```ts
console.log(`... perfect-season (20-0) ${(100 * r.perfect / r.n).toFixed(1)}% ...`);
```

Notes: `rec.w + rec.t/2` is the stored wins figure; a 17-0 season has `rec.w === 17 && rec.t === 0`. Do NOT count a 17-0 regular season that loses a playoff game — `s.champion === name` guards that. Report the rate as a percentage with one decimal (the target is 1–2%, so integer percent loses resolution).

## The snippet (sweep.ts / bands.json)

Add a per-season boolean `perfectSeason: boolean` (user-or-league? the sweep runs full seasons; define it as "at least one team finishes 17-0 and wins the title" — or, for the drafted-league population, "the user's team does", matching the harness). Aggregate as `sharePerfectSeasons: number`. Add to bands.json as `{ metric: "P(20-0)", value: <measured>, population: "top30 policy, N=300", provenance: "calibrate-draft.ts 425f72a", date: "..." }` with the measured value once the first N=300 run with the counter lands.

## SAFE ALONE?

Yes — measurement only, no engine change, no product change. The counter is additive (new field, new report line); existing numbers are unaffected. Fold into the bands.json work (P-269) and the CALIBRATION.md protocol (P-255/P-263). Does not generate ratings.
