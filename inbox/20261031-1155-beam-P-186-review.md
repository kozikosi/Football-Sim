## Findings

### 1. `TEAM_COLORS` doesn't exist in Pre-Colors
uk's JS references `TEAM_COLORS[teamName]` (section 2.1 and 5). This variable has 0 occurrences in the product. The Owner's color table exists in `beam/notes/team-color-theming.md` and Z.ai's `ZPB_TEAM_COLORS`, but neither is in the product. The Architect must add `TEAM_COLORS` (or `ZPB_TEAM_COLORS`) to the product before this JS works. Also `--team-accent-rgb` doesn't exist (0 occurrences).

### 2. "No logo in pick dropdown" — correct, but verify is redundant
uk says "No change needed — verify no logo/image". The code at lines 1099-1105 populates options with text only (`o.textContent='Pick '+i`). No logos. Correct. The verification grep would return empty. OK.

### 3. "No scrollbar on setup panel" — panel already has no scrollbar
The setup panel (lines 383-395) is a `.panel` div. `.panel` has no `overflow` property (defaults to `visible`). The `overflow: visible !important; max-height: none !important;` is redundant. The panel doesn't scroll. No change needed. The `!important` is unnecessary.

### 4. Hero full-width (`100vw`) may cause horizontal scroll
uk proposes `width:100vw; left:50%; transform:translateX(-50%); margin-left:-50vw; margin-right:-50vw;`. The `.wrap` has `max-width:1200px;margin:0 auto;padding:20px 16px 60px;`. The `100vw` includes scrollbar width on some browsers, causing horizontal scroll. Also, the `margin-left:-50vw` might not fully counteract the container's auto margins. Recommend: use `width:100%; margin-left:calc(-50vw + 50%);` or test thoroughly. Also, the `.hero::after` pseudo-element (radial gradient) might overflow.

### 5. Footer pinning (`position:fixed`) is a major layout change
The current footer is in-flow (`margin:34px auto 0`). Pinning it fixed requires:
- `.wrap` bottom padding change from 60px to 72px (uk proposes 72px). But the `.wrap` padding is `20px 16px 60px`. Changing to `20px 16px 72px` adds 12px. OK.
- But the `.footnav` currently has `max-width:max-content`. Pinning it full-width with `max-width:none` changes the visual. The Owner's brief says "pinned at the very bottom" — so full-width is correct.
- However, `z-index:100` might conflict with other fixed elements (detail panel, etc.). Check.

### 6. Footer capitalization — correct per brief
uk changes "Simulator" → "SIMULATOR", etc. The Owner's P-186 brief says "footer labels fully capitalised". Correct. But note: the current footer has a `.footlabel` "More" span before the buttons. uk's HTML patch doesn't mention removing it. The brief doesn't mention it either. Keep it or remove? The brief says "SIMULATOR, MADDEN RANKINGS, PLAYER BROWSER, POSITION RANKINGS, TEAM COMPARISON, GUIDE" — these are the button labels. The "More" label is separate. Keep it.

### 7. DRAFT button `calc(50% - 1.5rem)` assumes container height
The button is `position:absolute; top:calc(50% - 1.5rem)` inside `#viewDraft > .panel:first-of-type` which has `min-height:60vh`. On a 390px viewport, 60vh = ~506px. The button would be at ~253px - 24px = ~229px. That's reasonable. But on very short viewports (e.g., 667px height), 60vh = 400px, button at 200px - 24px = 176px. Might be too high. Recommend: use `min-height: 50vh` and test.

### 8. `--team-accent-rgb` doesn't exist
uk's CSS uses `rgba(var(--team-accent-rgb, 79, 140, 255), 0.2)` for focus ring. This variable doesn't exist. The fallback `79, 140, 255` is the default accent blue. But `rgba()` with a CSS variable containing commas works in modern browsers. However, if `--team-accent` is a hex color (e.g., `#E31837`), you can't use it in `rgba(var(--team-accent-rgb), 0.2)` without converting to RGB first. Recommend: use `color-mix()` or define `--team-accent-rgb` alongside `--team-accent`.

### 9. The `updateSetupColors` function has a fallback bug
When `teamName === '__random'` or `!TEAM_COLORS[teamName]`, the function resets styles. But it doesn't reset `--team-accent` on `document.documentElement`. Also, the `__random` team selection means a random team is chosen — the dropdown should reflect that team's color. But `updateSetupColors` returns early without setting colors. The random team's color won't be shown. Recommend: resolve `__random` to the actual team name first.

### 10. The computed positions table is theoretical, not measured
uk's "COMPUTED POSITIONS" table gives theoretical values (e.g., "Hero width: 1280 (full)"). These are CSS calculations, not Playwright measurements. The brief asks for "computed positions at 1280 and 390 px (Playwright)". uk provides Playwright commands but not actual results. The review should note that these need to be verified.

### 11. The `appearance: none` on selects removes the native dropdown arrow
uk adds a custom SVG arrow via `background-image`. This is fine but the SVG uses `stroke='currentColor'` which inherits from the select's color (team color). The arrow would be team-colored. Nice touch. But the `background-size:16px` and `padding-right:40px` need to ensure the arrow doesn't overlap text. OK.

### 12. The `#draftSlotSelect option { white-space:nowrap; }` is redundant
Select options don't wrap by default in most browsers. The `white-space:nowrap` is unnecessary. Not harmful, just redundant.

### 13. Missing: `prefers-reduced-motion` for the button hover transform
The `#startDraftBtn:hover { transform: translateX(-50%) translateY(-2px); }` adds a hover lift. Under `prefers-reduced-motion: reduce`, this should be disabled. uk's "HOW TO CHECK" mentions reduced motion but the CSS doesn't include a reduced-motion rule for the new hover effects.
