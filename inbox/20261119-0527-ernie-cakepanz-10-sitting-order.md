## PART C — evaluate the Svelte 5 / Vue 3 table-tool landscape (the Owner's question)

**The Owner's question (paraphrased):** "Evaluate any possible Svelte 5 or Vue 3 tools we could use to improve the w89 into Colors — e.g. reframing the 'Your team stats' and 'playoff stats' from lists into maybe more interactive tables. Take your time to think about this. Give me your final recommendation on Svelte 5 vs Vue 3."

### C1 · The table-tool evaluation (your research + recommendation)

The council has already converged on several points (ERNIE's cakepanz-9 Part E + the MUSE relay + GPT's framework comment). Your job is to **verify, challenge, and extend** — not re-litigate what is settled. Here is what is settled and what is open:

**Settled (do not re-litigate):**
- **The draft board stays a list + DRAFT button.** No table, no drag-and-drop, no virtual scroll. The Owner's word.
- **No state library** (Pinia or otherwise). A snapshot engine needs a snapshot.
- **No UI kits** (Vuetify, shadcn, etc.). They fight the w89 identity.
- **No analytics/telemetry.** Ever.
- **The framework decision is the Owner's** (R-13 measurement at cutover). Nothing ships before the ruling.

**Open (your job to evaluate):**

| Surface | What exists today | What the Owner wants | Your evaluation |
|---|---|---|---|
| **Your team stats** (season review) | A list of stat chips (PF, PA, etc.) | An interactive table — sortable, filterable, maybe per-game rows | Evaluate: hand-rolled `StatTable.svelte` (~180 lines) vs TanStack Table v9 (Svelte adapter, 15 KB gz) vs SvGrid (80 KB full, 2 KB headless core) vs svelte-headless-table (10 KB gz, 15 plugins) |
| **Playoff stats** | A leaders-only list | A per-game table + playoff leaders | Same evaluation |
| **All-teams stats** | A flat list of 32 teams | A sortable, column-toggle table | Same evaluation |
| **Awards** | A winners list | Same cards, maybe with expand-to-see-vote-detail | Evaluate: does this even need a table? |

**The specific tools to evaluate (verify these exist, check their Svelte 5 / Vue 3 support, report their bundle cost, license, and maintenance status):**

1. **TanStack Table v9** (`@tanstack/svelte-table` v9 / `@tanstack/vue-table` v9) — headless, framework-agnostic core + per-framework adapters. Svelte 5 native (runes-based, `$state`/`$derived`). Vue 3 native (ref/computed). Features: sorting, filtering, pagination, column visibility, row selection, column resizing, grouping, aggregation. Bundle: ~15 KB gz (core + one adapter). License: MIT. **This is the 800-lb gorilla of headless tables.** Both frameworks have first-class adapters.

2. **svelte-headless-table** (`@humanspeak/svelte-headless-table`) — Svelte 5 native, 15 plugins (sorting, filtering, pagination, grouping, selection, column resizing, virtual scroll, data export). Bundle: 10 KB gz, no separate stylesheet. License: MIT. **This is the Svelte-native alternative to TanStack.** It is younger and smaller but has a plugin architecture that maps cleanly to the w89 stat surfaces.

3. **SvGrid** (`@svgrid/grid`) — Svelte 5 native, headless core (~2 KB) + full grid component (~80 KB + 9 KB CSS). Virtual scrolling over 100k rows, Excel-style filtering, inline editing, cell selection, row grouping, tree data. License: MIT (community core), enterprise tier from $299/dev/year. **This is the "when you outgrow headless" option** — it ships a full grid component, not just logic. Overkill for 32 teams or 1,953 stat rows unless the Owner wants inline editing or Excel-style filters.

4. **Vue equivalents:** `@johnhalazonetis/data-table` (Vue 3 + TanStack Table v9 + TanStack Virtual, full-featured with toolbar, inline editing, selection, pagination — but Tailwind-based, which fights w89). `@aimerthyr/virtual-table` (Vue 3 + TanStack + Virtual, headless-ish with slot-based rendering). Both are younger and less proven than TanStack's own Vue adapter.

5. **The hand-rolled option:** A ~180-line `StatTable.svelte` with `{#each}` + `sort` + `filter` — no dependency, no adapter, no version risk. The council's MUSE-relay consensus was "hand-rolled" for the current requirements (sortable, filterable, 32-1953 rows, no virtual scroll needed).

**Your evaluation should answer:**
- For each surface (team stats, playoff stats, all-teams, awards), which tool is the best fit and why?
- What is the bundle cost of each option (measure it — install, build, report the gzipped size)?
- What is the maintenance risk (last publish date, open issues, Svelte 5 / Vue 3 compatibility)?
- Does the choice of table tool affect the Svelte 5 vs Vue 3 framework decision? (ERNIE's assessment: NO — TanStack Table has first-class adapters for both; the genuine upgrades are framework-agnostic ties.)
- **What would you actually build for the w89 → Colors transition?** A specific recommendation with a one-paragraph justification.
