## 5. VL's mid-season blank board: CONFIRMED symptom, corrected root cause

At the delivered bytes, `hydrateBoot()` (App.svelte:196) reads the autosave. For a mid-season record both `r.draft` and `r.week` exist. `if (r.draft) loadDraft(...)` runs FIRST (:199), calling `go('board')` then `refresh()`. Only after `loadDraft` returns does `if (r.week) → go('hub')` run (:203-209). For a done-draft, `refresh()` (:141-142) does `if (st.status === 'done') { oddsMeta.set(null); }` — it SKIPS `vmStore.set(boardVM(...))`, so the board VM is never computed → `rows: 0`, `picks: 1024`, screen "board". `goneOdds` DOES throw on a done-draft (`engine/sports/nfl/engine/goneodds.ts:16`: `if (st.order[st.pos] !== userTeam) throw …`) but `refresh()` guards it with the `st.status === 'done'` check, so the throw is not the boot-path cause. `store.ts:96` `settle()` sets status='done' for complete drafts (`d.pos >= d.order.length`), confirming the guard applies.

Root cause is therefore: (a) `loadDraft` routes to `go('board')` before the `r.week` → `go('hub')` check, and (b) `refresh()` does not compute the board VM for done-drafts. VL's `goneOdds`-throw attribution is not the boot-path cause, but the symptom (mid-season boot lands on empty board, rows 0) is real per VL's receipted probe and confirmed by code reading. Blocks mid-season flows: a done-draft record must boot to the hub/week view, not an empty board.
