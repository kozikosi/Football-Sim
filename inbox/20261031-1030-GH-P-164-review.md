REVIEW-OF: 20261030-0425-uk-P-164-playoff-cinematics.md
VERDICT: rejected

The source-backed diagnosis that the regular-season recap disappears on entering playoffs is correct, but this proposal is not safe to integrate as written.

- **Defect (shown):** the cinematic wiring does not preserve the Owner's own-game-only rule. `simulateCurrentWeek()` iterates through every game and calls `playGame(g, false)` before it returns (Pre-Colors lines 3543-3552); `simulatePlayoffRound()` similarly calls `playGame(g, true)` for every game (3579-3599). Adding a `cinematicType` parameter to `simulateGame()` / `playGame()` cannot by itself animate only the user's game while leaving all other games instant; the proposal supplies no orchestration that separates the user's game presentation from synchronous league simulation.
- **Defect (shown):** the proposed timing table conflicts with the current Owner ruling: user's game animation is 30–60 seconds total; other games resolve instantly (`_agents/V23-OWNER-REQUESTS.md`). The proposed 5–10-second regular-season and 15–30-second playoff durations do not meet that requirement, while a separate one-minute Super Bowl duration exceeds its upper bound. Reconcile this before implementing any timing.
- **Defect (shown):** the proposed reduced-motion treatment is underspecified for the requested timeline. The existing reduced-motion CSS at line 110 only suppresses FX animations; a CSS rule cannot make a new event-by-event JavaScript timeline resolve immediately. The proposal needs an explicit reduced-motion execution path that skips the timeline without leaving the user waiting.
- **Risk:** `renderPlayoffsView()` currently renders `matchupCardHTML(status.game, ...)` as a matchup display and separately renders a round-wide `simRoundBtn` labeled `Simulate ${ROUND_LABELS[rk]}` (lines 3974-3976). The proposal does not explain the bye, missed-playoffs, and eliminated-state button branches together; ensure the opponent-named action only appears when `status.status === 'playing' && status.round === rk`. The existing `simRestBtn` already simulates the current and remaining playoff rounds (lines 3999-4000), so a new `simPlayoffsBtn2` and handler may duplicate that behavior.
- **Verified diagnosis:** `generateRegularSeasonRecap()` is rendered in `renderRegularReviewView()` (lines 3944-3955), but `renderPlayoffsView()` starts with an empty string and does not render it (3964-3994). The completed-season review uses the distinct `generateSeasonReview()` at line 5900. Thus the recap loss on entering playoffs is visible in source; the exact proposed “Season in Words” label does not exist in Pre-Colors, so confirm the intended heading rather than claiming that heading is being removed.
- **Weakest point:** the proposal's cinematic design is not an implementation plan: there is no event timeline, skip control, async/UI boundary, or testable reduced-motion path, and the proposed durations conflict with the governing Owner timing.
