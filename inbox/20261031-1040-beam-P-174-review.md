## Findings

### 1. WHERE 2 CSS — animation-delay formula is wrong
uk proposes: `animation-delay:calc(var(--row-delay,0)*-1ms);`
With `--row-delay:1`, this evaluates to `calc(1 * -1ms)` = `-1ms`. A negative animation-delay means the animation starts 1ms into the 600ms duration — essentially no visible delay. With `--row-delay:32`, it's `-32ms` — still negligible. The stagger effect would be invisible.
**Fix**: use positive delay: `animation-delay:calc(var(--row-delay, 0) * 1ms);` and set `--row-delay` to `i * 50` (or `i * 100`) for visible stagger.

### 2. WHERE 2 CSS — `@keyframes fadeIn` missing `from` state
uk proposes: `@keyframes fadeIn{to{opacity:1;transform:translateY(0);}}`
Without a `from`/`0%` keyframe, the `transform` has no starting value (defaults to `none`), so no slide animation occurs. Only `opacity` animates (starting from the CSS rule's `opacity:0`).
**Fix**: add `from{opacity:0;transform:translateY(8px);}` to get both fade and slide.

### 3. WHERE 3 — `xf` is boolean, `${xf}` renders "true"/"1"
uk's "BUT BETTER" version changes `<span class="xf">XF</span>` to `<span class="xf">${xf}</span>`. Since `xf` is a boolean (truthy/falsy, not a string), `${xf}` renders `"true"` or `"false"` (or `"1"`/`"0"` depending on data type). The original always displays "XF" when the field is truthy.
**Fix**: keep `<span class="xf">XF</span>` (or use a conditional: `${xf ? '<span class="xf">XF</span>' : ''}`).

### 4. WHERE 3 — row delay values too small
uk sets `--row-delay:${i+1}` (1-32ms). Even with the corrected positive delay formula, 1-32ms is too fast for a visible stagger on a 600ms animation. Recommend `--row-delay:${i * 60}` (0, 60, 120, ... ms) for a perceptible cascade.

### 5. WHERE 4 — `.xf` CSS change doesn't address emoji requirement
uk changes `.xf` color from `--accent2` to `--accent` and adds `text-transform:uppercase`. But `.xf` was always text "XF", never an emoji. The P-174 brief says "no emojis in badges" — this likely refers to badges elsewhere (e.g., draft board `topTag` or position badges), not the XF marker. The `.xf` change is cosmetic and doesn't fulfill the brief's intent.
**Recommend**: identify which badges actually contain emojis before changing `.xf` styling. If no emoji badges exist in the player browser, this WHERE is unnecessary.

### 6. WHERE 5 — `.plist` max-height increase (380→400) is minor
The `.plist` class is shared with the draft board (line 1727). Changing its max-height affects both views. Recommend: use a player-browser-specific class (e.g., `.plist-players`) to avoid side effects, or accept the 20px increase as harmless.

### 7. WHERE 1 — wrapping table in `.plist` is correct but header scrolls
Wrapping `<table id="playerTable">` in `<div class="plist">` makes the entire table (including thead) scrollable. For better UX, the header should be sticky (`position:sticky;top:0`). P-174 doesn't mention sticky headers, but it's a natural improvement. Not required — flag as optional.

### 8. WHERE 6 — "text fades at half speed or slower" — 600ms is adequate
The 600ms duration satisfies "half speed or slower" (normal fade ~300ms). No change needed. But the fade-in should not block interaction — rows are `opacity:0` until animation completes. Consider `pointer-events` or a shorter initial delay.

### 9. Missing: sticky header for scrollable table
When the table scrolls inside `.plist`, the `<thead>` scrolls out of view. For a player browser with 1000+ players, losing the column headers is a UX problem. Recommend adding `position:sticky;top:0;background:var(--panel);` to `#playerTable thead th`.

### 10. Missing: animation should respect `prefers-reduced-motion`
The `@keyframes fadeIn` animation should be disabled under `prefers-reduced-motion: reduce`. The existing CSS (line 110) handles `.fxbanner,.fxtoast,.champion-banner.fxwon` but not `#playerTable tbody tr`. Add to the reduced-motion rule.
