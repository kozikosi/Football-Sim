# E3b: exact field mapping RunState <-> WeekPayload (engine/shell save seam)

## Scope note
`RunState` (colors/src/engine/seasonrun.ts) is the engine's full season state. `WeekPayload` (colors/src/app/envelope.ts) is the "week" save at a game preview. They are not 1:1: WeekPayload also carries user-specific frozen data (userTeam, roster, ratings, plan, statsRecorded) and a derived `gameSeed` that RunState does not store. The seam therefore needs two adapter functions plus the user inputs, not a pure cast. Engine fields must round-trip byte-for-byte; user fields are owned by the app layer.

## RunState -> WeekPayload (toWeekPayload)
Inputs: state: RunState, userTeam: string, roster: FrozenPlayer[], ratings: Record<string, unknown>, plan: Record<string, unknown> | null, statsRecorded: boolean.

| RunState field | WeekPayload field | Transform |
|---|---|---|
| seed | seed | direct |
| year | year | direct |
| run | run | direct |
| (derived) | gameSeed | gameSeed(state.seed, state.nextWeek, fixtures(state)[0].home) — recomputed; not stored in RunState |
| nextWeek | nextWeek | direct |
| (not in RunState) | userTeam | supplied by app |
| (not in RunState) | roster | supplied by app (FrozenPlayer[]) |
| (not in RunState) | ratings | supplied by app |
| schedule | schedule | map Game -> { week, home, away, kind } (kind already on Game) |
| scores | scores | map Score -> GameScore: { week, home, away, hs, as, round?, htd?, atd? } (round only if present; htd/atd optional) |
| (not in RunState) | plan | supplied by app |
| (not in RunState) | statsRecorded | supplied by app |

Notes: `prevRank`, `homeField`, `playoffs`, `seeding`, `champion` are NOT in WeekPayload. A week save is a rolling preview save; playoffs/seeding/champion only exist after the regular season, so they live in SeasonPayload (or are recomputed from scores). `playoffs` scores are NOT carried in WeekPayload.scores? WeekPayload.scores is "results so far" — for a week save during the regular season, scores = regular-season scores only (RunState.scores). Playoff scores (RunState.playoffs) are carried only once the save becomes a SeasonPayload.

## WeekPayload -> RunState (fromWeekPayload)
Inputs: payload: WeekPayload, plus derived/optional: prevRank?: Record<string, number>, homeField?: number, playoffs?: Score[], seeding?: Seeding | null, champion?: string | null. For a pure regular-season week save, playoffs=[], seeding=null, champion=null, and prevRank/homeField must be supplied by the app (or defaulted: prevRank = initialRanks, homeField = undefined).

| WeekPayload field | RunState field | Transform |
|---|---|---|
| seed | seed | direct |
| year | year | direct |
| run | run | direct |
| nextWeek | nextWeek | direct |
| schedule | schedule | map { week, home, away, kind } -> Game (direct; kind is GameKind) |
| scores | scores | map GameScore -> Score: { week, home, away, hs, as, htd, atd, round? }. htd/atd default to 0 if absent (WeekPayload marks them optional); round passed through. |
| (not in payload) | prevRank | supplied/defaulted |
| (not in payload) | homeField | supplied/defaulted |
| (not in payload) | playoffs | supplied (default []) |
| (not in payload) | seeding | supplied (default null) |
| (not in payload) | champion | supplied (default null) |

gameSeed, userTeam, roster, ratings, plan, statsRecorded are app-layer fields and are NOT restored into RunState (RunState carries no user data).

## Round-trip test (proposed, for colors/test/seasonrun.test.ts or a new seam test)
```
import { rt } from ...; // JSON round-trip
test('RunState <-> WeekPayload round-trips engine fields', () => {
  const teams = league(7);
  let s = startSeason(teams, { seed: 7, year: 2026 });
  for (let i = 0; i < 4; i++) s = playWeek(teams, s).state;
  // to payload (app supplies user fields)
  const payload: WeekPayload = toWeekPayload(s, 'Kansas City Chiefs', roster, ratings, null, false);
  // payload gameSeed must match the stored seed of the next game
  const f = fixtures(s)[0];
  assert.equal(payload.gameSeed, gameSeed(s.seed, s.nextWeek, f.home));
  // from payload back to RunState (supply the non-carried fields)
  const s2 = fromWeekPayload(payload, { prevRank: s.prevRank, homeField: s.homeField, playoffs: s.playoffs, seeding: s.seeding, champion: s.champion });
  assert.deepEqual(rt(s2), rt(s));   // engine fields identical
  // replay equivalence: stepping from s2 gives the same next week as stepping from s
  assert.deepEqual(JSON.stringify(playWeek(teams, rt(s2)).games), JSON.stringify(playWeek(teams, rt(s)).games));
});
```
The test must also cover: playoff weeks (nextWeek 19..22) where schedule is empty in WeekPayload? Actually WeekPayload.schedule carries the regular-season schedule (frozen). For a playoff preview save, scores includes playoff GameScores with round set; RunState.playoffs must be reconstructed from those with round. The adapter should split WeekPayload.scores into RunState.scores (round === undefined) and RunState.playoffs (round !== undefined) on reverse. And RunState.schedule is the full regular-season schedule (same as payload.schedule).

## Open questions for the Architect
1. Should WeekPayload.scores include playoff scores during the playoffs, or only regular-season? The type says "results so far" (ambiguous). Recommend: include all played games (regular + playoff) and split on reverse by presence of `round`.
2. prevRank/homeField are not in WeekPayload. Recommend the app re-derives prevRank from the previous season's standings (or stores it in SeasonPayload only). For a week save mid-season, prevRank is fixed from season start; if not stored, default to initialRanks (may change opponents on resume — a latent bug). Recommend adding `prevRank` to WeekPayload in a future schema bump, OR storing the full schedule (which already encodes opponents) so prevRank is not needed for resume. Since schedule is already frozen, prevRank is only needed for run-it-back; recommend keeping it out of WeekPayload and documenting that resume uses the frozen schedule.
3. roster/ratings/plan are app-owned and never enter RunState. Confirm no engine code reads them from RunState.
