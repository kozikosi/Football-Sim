# Part 9 — innovation proposals

## Proposal 1 — Push-after-every-file + preserve gate at session end (council-adoptable)
**Problem:** Seats time out on long prompts; unpushed work dies in timed-out chats; stashes are invisible to every branch and push (the 23 Oct shared-tree loss).
**Idea:** Make two actions mandatory: (a) push after every finished file to your own branch only, verified with `git ls-remote`; (b) run `node tools/preserve.mjs check` at the end of every chat and before any clean-up (it exits 1 if any work exists only locally). No `git stash` ever — set work aside with a WIP commit.
**How to check:** `git ls-remote origin council/<seat>` shows the file's commit; `node tools/preserve.mjs check` exits 0 (no local-only work). A seat that skips either has unpushed/dying work — visible in the next seat's council-sync.
**Owner needed?** No — council-adoptable (already in the prompt; this makes it explicit and checkable).

## Proposal 2 — Denominator discipline on every inc:downs figure (council-adoptable)
**Problem:** The 4th-down numbers have two denominators; the round already burned one flag on confusing them (§0: per-incompletion pools~68%/GLM~24% vs per-4th-down-pass-play pools~24%/GLM~8.8%). A figure without its denominator is not a figure.
**Idea:** Every filing that cites an inc:downs figure must name its denominator in-line ("per-4th-down-pass-play" or "per-incompletion"); council-sync rejects filings with bare percentage figures lacking a denominator label.
**How to check:** grep inbox/ for `%` figures not adjacent to a denominator keyword; zero bare figures is a clean check. This round's own filings comply (P-342 §6 battery names both denominators).
**Owner needed?** No — council-adoptable.

## Proposal 3 — No citing unverified drafts as council findings (council-adoptable)
**Problem:** MUSE drafts are drafts, not reviews; the prompt explicitly says "do not cite a MUSE draft as a council finding until it is verified," yet reviews-of-reviews pile up and drafts get nodded through.
**Idea:** Every claim in an inbox filing carries one of VERIFIED / REPORTED / INFERRED / UNKNOWN. Council-sync flags any claim without a label and any "VERIFIED" claim without a pasted command+output receipt. A MUSE draft counts as a council review only after a non-author seat verifies it (receipt filed).
**How to check:** `node tools/check-tasks.mjs` / a label-lint over inbox/; verified count should match receipts pasted.
**Owner needed?** No — council-adoptable.

## Proposal 4 — Convention-not-measurement as the model for Owner-protected constants (council-adoptable)
**Problem:** The λ round shows a cleaner split than re-litigating values: the dial is accepted as designed, the band [0.3902,0.4032) is the constraint, and the shipped value is *convention, not measurement* (midpoint 0.3967). The same pattern fits other Owner-protected constants (DEFAULT_WEIGHTS, FLEX, NATURAL_SLOT_MAP, etc.): re-pin the hash when they change, but let the ship value be a labelled convention.
**Idea:** Adopt "ship an in-band value as convention, not measurement" as the default posture for every protected constant whose exact value is the Owner's lock: re-pin the hash in MERGE-MANIFEST.md on change, label the shipped value convention, and don't pretend it's measured.
**How to check:** MERGE-MANIFEST.md hash lines re-pinned in the same commit as any protected-constant change; shipped values labelled convention.
**Owner needed?** No for adopting the posture; yes only if a specific constant's value is at issue (that's his lock).
