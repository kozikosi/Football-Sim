FINDINGS (improved over Beam's version):
1. "ILB2 (a second MIKE)" slot does not exist. The roster slots are MIKE, WILL, SAM, LB4. There is no second MIKE slot. D-012 says 3-4 trades DT2 for "a second ILB (MIKE value)", but implementing that requires either a new roster slot or reusing LB4 (which is a depth/flex slot with weight 5 and GROUPS "Linebackers"). Beam's proposal assumes infrastructure that doesn't exist and understates the scope. The Architect must decide: add an ILB2 slot (roster + weights + labels, protected-constant implications) or reuse LB4 as the 3-4 MIKE2. This is a product call, not a measurement.
2. Averaging is position-based, not slot-based. groupAvgFromPool filters by position (p[1] is the position family: DT, MIKE, etc.), not by slot name. Beam's "mark slots active/inactive based on base; averaging skips inactive slots" (option b) does not map to the actual code — there are no slot names in the averaging path. The real change is base-aware GROUP_DEFS (n values or pos filters) or a base-aware position filter inside groupAvgFromPool. Option (a) — dynamic GROUP_DEFS — is actually closer to the code than option (b).

5. Missing base state. The proposal has no state variable for the selected base, no persistence (draft resume / preseason), and no UI for the toggle beyond "preseason page". Since no base concept exists anywhere, the Architect needs to define where base lives (team config? draft setup? preseason?).
