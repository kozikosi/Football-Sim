## Findings

### 1. Proposal references non-existent functions (`zpbWelcomeCine`, `zpbKick`)
uk's integration code says: "REPLACE the cinematic block (around line where zpbWelcomeCine is called)". But `zpbWelcomeCine` has 0 occurrences in Pre-Colors. There is no existing cinematic to replace. The proposal is written for Z-post-blue (which has the cinematic), not for Pre-Colors. The integration point needs to be rewritten: `startDraft2()` has no cinematic call. The new `showWelcomeCine(onComplete)` should be called at the end of `startDraft2()` setup, before `processUntilUserTurn()`.

### 2. `finish()` doesn't actually remove the overlay
The `finish()` function adds `welcome-cine--exiting` class and listens for `transitionend`. But:
- No CSS defines `.welcome-cine--exiting` (no transition property).
- `onComplete?.()` is called immediately, not after the transition.
- The overlay element remains in the DOM indefinitely.
**Fix**: either (a) use `cine.remove()` directly in `finish()`, or (b) define a CSS transition for `.welcome-cine--exiting` and call `onComplete` in the `transitionend` handler.

### 3. `sr-only` class doesn't exist in Pre-Colors
The `announce()` function creates divs with `className = 'sr-only'`. This class has 0 occurrences in Pre-Colors, so the announcement divs would be visible on screen. **Fix**: either add `.sr-only { position:absolute; width:1px; height:1px; overflow:hidden; clip:rect(0,0,0,0); }` to the CSS, or use `aria-hidden` and rely on screen reader live regions without visual hiding.

### 4. `welcome-hold` keyframe is a no-op
The `welcome-hold` animation only sets `opacity: 1` in both 0% and 100%. Since `welcome-fade-in` already has `forwards` (holding opacity at 1), the hold animation is redundant. It doesn't cause bugs but adds unnecessary CSS. Recommend: remove it or explain why it's needed.

### 5. Multiple animations on the same element can conflict
`.welcome-cine__text--welcome` has three animations: `welcome-fade-in`, `welcome-hold`, `welcome-fade-out`. When multiple animations target the same property (opacity, transform), the last one wins. The timing (800ms, 1000ms delay 800ms, 800ms delay 1800ms) should work sequentially, but the `forwards` fill mode on each means they all hold their final states. This can cause flickering or stuck states. Recommend: test thoroughly or use a single combined keyframe.

### 6. The DRAFT shimmer uses `--accent` which may be blue
The `.welcome-cine__text--draft` uses `linear-gradient(90deg, var(--accent) 0%, #fff6c4 25%, ...)`. In Pre-Colors, `--accent` is `#4f8cff` (blue). The Owner's theme says "no blue panels" and "gold shimmering for exciting text". The shimmer should use `--gold` (#ffc43c) or the Owner's gold (#d4af37), not `--accent` (blue). Also, `#fff6c4` is a warm cream, not gold. Recommend: use `var(--gold, #d4af37)` and `#fff6c4` (or `#ffd700`).

### 7. The `skip` overlay has `pointer-events` issue
`.welcome-cine { pointer-events: none; }` is on the container. The `.welcome-cine__skip` overlay doesn't override this, so it would inherit `pointer-events: none` and wouldn't receive clicks. **Fix**: add `pointer-events: auto;` to `.welcome-cine__skip`.

### 8. The `aria-hidden="true"` on text divs conflicts with screen reader announcements
The text divs have `aria-hidden="true"` (so screen readers don't read them). But the `announce()` function creates separate `aria-live` divs for screen readers. This is the correct approach. However, the `sr-only` class issue (finding #3) means the announcement divs would be visible. Also, the `aria-hidden` on the text means the visual text is hidden from AT, which is fine since the announcements provide the same info.

### 9. The timeline total is ~4700ms, not ~4500ms
uk's table says "Total: ~4500ms default". But the last phase (DRAFT fade-in) ends at 4700ms (4200 + 500). The total should be ~4700ms. Minor arithmetic error.

### 10. The `will-change` on all text elements is excessive
`will-change: transform, opacity` is set on `.welcome-cine__text` (all three text elements). This hints the browser to optimize for animations. But all three elements are animated at different times, so `will-change` on all of them wastes GPU memory. Recommend: add `will-change` only to the currently animating element, or remove it (modern browsers handle this automatically).

### 11. The `text-shadow` on text is heavy
`text-shadow: 0 4px 24px rgba(0,0,0,0.3)` on all text elements. This is a large shadow that might look odd on light backgrounds. The Owner's theme has light mode. Recommend: reduce to `0 2px 8px rgba(0,0,0,0.15)` or make it theme-aware.

### 12. Missing: the cinematic should only show once per session
uk's code has `window._welcomeCineShown` to prevent double-run. But this is a session-level flag. If the user starts a new draft, the cinematic won't show again. The Owner might want it to show every time. Or maybe once per session is fine. Not clear from the brief. Flag for Architect decision.

### 13. `zpbStartDraftWatchdog` doesn't exist in Pre-Colors
uk's integration code calls `zpbStartDraftWatchdog()`. This function has 0 occurrences in Pre-Colors. The call would throw a ReferenceError, caught by the try/catch, which falls back to `zpbKick()`. But `zpbKick` also doesn't exist. So the fallback would also throw. The integration code needs to be rewritten for Pre-Colors.

### 14. The `finish()` function calls `onComplete` before the overlay is removed
In `finish()`, `onComplete?.()` is called immediately, not after the overlay is removed. This means the draft starts while the overlay is still on screen. The overlay has `pointer-events: none` (finding #7), so it won't block interaction. But the overlay element remains in the DOM. Should remove it: `cine.remove()` instead of waiting for `transitionend`.

## Verdict summary
uk's cinematic proposal is well-designed (timeline, keyframes, reduced-motion, accessibility). But:
- References non-existent functions (`zpbWelcomeCine`, `zpbKick`, `zpbStartDraftWatchdog`).
- `finish()` doesn't remove the overlay (no CSS transition for `welcome-cine--exiting`).
- `sr-only` class doesn't exist.
- `pointer-events: none` on container blocks skip overlay clicks.
- DRAFT shimmer uses blue (`--accent`) instead of gold.
- `aria-hidden` + `sr-only` conflict (visible announcement divs).
- Timeline total is ~4700ms, not ~4500ms.

RECOMMEND: improved (fix the 14 points above before the Architect builds).
