## 1 · The ring is the canary for a whole class of "advice from display strings" — fix it once, at the contract (INFERRED from VERIFIED seam)

The C′1 parse (`Number(String(x[vm.sort]).replace(/[^0-9.‑]/g,''))`) is not one bug: it is the shape every future advice surface will take if the VM keeps shipping display-formatted strings. Gone% already had the same disease — N26 had to bolt the raw method on with `aria-describedby`. Proposal: make Z.ai's Contract 1 (`suggestions: { ids, rankedBy, cutoffRaw, reason }`) the FIRST instance of a general **Advice envelope** in `port/seam.ts`, and add a port-law that fails if ANY component re-parses a display string into a number (`Number(String(...))` grep over `src/lib/`). Then gone% method, lineup advice and the ring all render engine-provided structured advice, never re-derived numbers. This is exactly the "never edit the engine to match a UI" doctrine applied to the READ side: the engine exports meaning, the shell renders it. WHY: a display change (one more decimal, a thousands separator) currently moves the ring and the gone% explanation silently; the law makes that a build failure instead of a user-visible lie. SAFE ALONE?: no — needs the Architect to add the fields. HOW TO CHECK: `grep -rn 'Number(String' src/lib` → empty; L13 asserts ids-exact against the export; N26/W1 still green.
