2. **Real inconsistency (the actual "broken Priority"):** sort by Priority uses `r.score = pri*m` (star-weighted), but the Priority column displays `fmtWar(r.pri)` (unweighted). So the sort order does not match the displayed number — a user sorting by Priority sees rows ordered by a number that is not on screen. Fix: make sort and display use the same value. Two options — (a) sort by `r.pri` (displayed number) and keep stars as a visual-only indicator, or (b) display `r.score` (weighted) in the column. Recommend (a): the displayed "Priority" should be the value the tooltip describes ("Value here minus what you'd still find"), and stars should re-order via a separate star-weighted key if the Owner wants them to affect ordering. Either way, document the choice. Also fix the negative-priority branch: `pri>0 ? pri*m : pri/m` divides negatives by m (inflating them toward zero); for a must-fill position a negative priority should arguably be *more* negative, not less. Recommend `pri * m` for all signs, OR keep the asymmetric form only if intended — flag for Owner ruling.
