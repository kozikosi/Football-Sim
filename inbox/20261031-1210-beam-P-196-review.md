## Findings

### 1. League-wide percentages sum correctly
Base + Nickel + Dime:
- 2023: 21.22 + 67.16 + 9.87 = 98.25% ✓
- 2024: 23.29 + 65.21 + 9.88 = 98.38% ✓
- 2025: 29.64 + 59.04 + 9.36 = 98.04% ✓
Remaining ~2% is quarter/goal line/other. OK.

### 2. `DIME_USAGE.base` naming is misleading
uk's code uses `base: 0.094` (9.4%) for the overall DIME average. But "base" implies "base personnel package" (which is 29.64% in 2025). The variable should be named `overall` or `average` to avoid confusion with the "Base" personnel package. This is a naming bug that could cause implementation errors.

### 3. `COVERAGE_MULTIPLIER.dime = 2.5` is not supported by the data
uk proposes `dime: 2.5` as "2.5x base rate on obvious passing downs". But the data shows DIME usage on 3rd-and-long is 43%, which is 43/9.4 = 4.6x the overall average. The 2.5x multiplier seems arbitrarily chosen and doesn't match the usage data. If the multiplier represents importance (not usage), it needs justification. The brief asks to "propose the leverage with arithmetic" — uk doesn't show the arithmetic for 2.5.

### 4. `DIME_BY_SITUATION` values are estimated, not sourced
- '1st': 0.05 — no source cited.
- '2nd': 0.07 — no source cited.
- '3rd_short': 0.10 — no source cited.
- '3rd_med': 0.25 — no source cited.
- '3rd_long': 0.43 — cited (PFF).
- '4th_short': 0.15 — no source cited.
- '4th_long': 0.50 — no source cited (estimated higher than 3rd_long).
- '2min_drill': 0.40 — no source cited.
Only `3rd_long` has a source. The rest are estimates. The evidence label says "VERIFIED" but 7 of 8 values are unsourced estimates. Should be labelled as estimates or UNKNOWN.

### 5. Rams data inconsistency (32.4% vs 34.6%)
uk lists both "32.4% dime" (TheRams.com) and "34.6% dime per Next Gen Stats" (TheRams.com). These are different sources reporting different numbers for the same team/season. uk doesn't reconcile them. The difference is 2.2 percentage points, which is significant. Should note which source is more authoritative.

### 6. "13 teams <5%" with "0-25 snaps" is unclear
uk says "13 teams | <5% | 0-25 snaps". The "0-25" range is ambiguous — does it mean 0 to 25 snaps each, or 0-25 total? If 13 teams × 25 snaps = 325 total, that's more than the Rams' 218. The phrasing should be clearer (e.g., "0-25 snaps each" or "fewer than 25 snaps").

### 7. Dime EPA by team table has only 2 entries
The "DIME EPA by Team" table lists Chiefs (-0.12) and "League avg (~0.00)". But uk cited Rams data showing 5.5 yds/play allowed (which implies positive EPA on run). The table should include Rams if data is available, or note that Rams EPA isn't cited.

### 8. Missing: Dime on run vulnerability
uk's data shows Dime is vulnerable to run (Rams: 5.26 YPA on 39 snaps). But the `DIME_BY_SITUATION` and `COVERAGE_MULTIPLIER` don't account for run vulnerability. The coverage multiplier should be lower on run-heavy downs. The Owner's engine uses coverage rating for pass defense; Dime should boost coverage but the run defense penalty should be noted.

### 9. The 10% snap share (Owner) vs 9.4% (PFF 2025)
The Owner's flex guide says Dime "plays around 10% of the snaps". PFF 2025 says 9.36%. These are close (10% vs 9.4%). uk uses 9.4% in the code but the Owner said 10%. The difference is minor (0.6pp) but should be noted. Recommend: use the Owner's 10% as the design target and note PFF's 9.4% as the empirical value.

### 10. Missing: how Dime fits into the coverage rating calculation
The Owner's engine uses coverage rating (CB, S, Nickel, Dime). The flex guide says Dime is "the 6th DB slot". But uk's evidence doesn't explain how the Dime slot's coverage rating is weighted in the overall coverage unit. Is it:
- Simple average of all DBs on the field (including Dime)?
- Weighted by snap share (Dime only counts 10% of the time)?
- Separate rating that's added to coverage?
The evidence should clarify the integration model.
