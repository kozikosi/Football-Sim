## New findings (defects — VERIFIED by execution; neither prior review caught these)

**D1 (defect, shown): every FB and P player shows +0.00 wins on the draft board and in season grading.** `playerWar()` reads `STATIC_SLOTS[p[1]]`, which has **no `FB` and no `P` key** (19 keys), so it returns `{war:0, slot:null}`. `playerWar` feeds:
- the draft-board table's **Wins column** (`wavg(r.w)` in the table row, line ~2956 of the extracted script): all 8 FB and 32 P players render `+0.00` while their real slot values are 0.003–0.54 (Juszczyk FB 88: real +0.059 shown as +0.00; Dickson P 85: real +0.541 shown as +0.00). Cards view and the Priority column show the real value (`r.v`), so the board contradicts itself between views;
- **sorting by Wins** sinks every FB/P player to the bottom;
- the season **"Your Players" grading table** (`gradeOf` → `playerWar(pl).war`): +0.00 for drafted FB/P players.

This falsifies the §7b claim "the draft board … honest for FB/P with no display-only special case" for the board's Wins column and season grading. What IS honest (VERIFIED): depth chart (`winsAt`: Ingold +0.0126 at FB, Bailey +0.1304 at P), cpuPick (uses `slotWins` directly), `modelWeights`/lineup advice/flex matrix (`slotWinsPerOvr` covers FB 0.0033, P 0.0188, K 0.0361, RB1 0.0333 wins/OVR).

**D2 (defect, shown): season grading peers are wrong for FB/P.** `gradeOf` uses `WV_TAG_GROUP[pos]`, which has no FB/P entries → `tg=undefined` → peers = every player whose tag maps to undefined, i.e. **FB+P+LS pooled**: an 88-OVR fullback is letter-graded against Michael Dickson (P), Josh Harris (LS) and Andrew DePaola (LS) (executed top-8 shows the mix).

**D3 (calibration question): PUNT_PTS comment arithmetic is wrong.** The constant is 1.6 with the comment "59 return yards a game × 0.04 points per yard" — that product is **2.36**, which is `RET_PTS`, not 1.6. The measured P figures match the 1.6 constant, so the number is right and the comment appears copied from the returner term. Which rationale is intended for a punter (1.6) is a design note for the Architect.

**D4 (risk, masked): replacement-level distortion.** `replacementLevels` demand now counts FB slots into the RB group (96 league-wide vs 89 HB supply → `repl.RB` = worst HB, 70) and P slots into the K group (64 vs 32 K → `repl.K` = worst K, 71 — same worst either way with exactly 32 kickers). Masked in `cpuPick` by the `Math.max(repl, 76)` floor, so no user-visible effect today; latent if that clamp ever changes. `staticReplacement` has no callers (dead code).

**D5 (calibration question for the Owner): punters list at the kicker slot.** `POS_SLOT_MAP['P'] = ['K','P']` (the free K↔P flex ties on penalty 0 and K precedes P in depth-chart order), and K-slot wins dominate P-slot wins, so the board shows every punter at slot K with kicker value (Dickson +0.541 at K vs +0.33 at P), and CPU teams can draft a punter to kick. This follows the Owner's "K<->P free" rule literally — flagging for an intent check, not calling it a defect.
