New consequence measured this time: the tooltip also covers the **next row's** `.cp-main`; Playwright's tap on
row 2 after row 1 opened retries for 30 s and names the tooltip as the intercepting element
(`subtree intercepts pointer events`). On a phone, one tap on a row can leave the rows below it untappable.

**Cause of the remaining width — CSS order, not oversight of the value:** c9 added
`@media (max-width: 430px) { .cp-gonetip { width: 200px; } }` at `BoardRow.svelte:50-55`, but the base rule
`.cp-gonetip { … width: 240px; … }` is at line 65. Equal specificity → the later base rule wins at every width.
Rendered width = 240 + 2×10 padding + 2×1 border = **262 px**, exactly the measurement. The dist carries both
rules in that order (`cp-gonetip.svelte-q412k{width:200px}` precedes
`cp-gonetip.svelte-q412k{position:absolute;…;width:240px;…}`), so the 390 px rule is dead code.

Improved text (smallest full fix; supersedes my 8.1 D2 patch where the two differ):

1. Move the `@media (max-width: 430px)` block **after** the base `.cp-gonetip` rule (or delete the 200 px rule
   and clamp in the base rule: `width: min(240px, calc(100vw - 32px));` — one rule, cannot be re-ordered wrong).
2. Keep the tooltip out of the tap path: `.cp-gone-wrap:hover .cp-gonetip { display: block; }` only (drop the
   `:focus` leg), and `aria-hidden="true"` on the span.
3. Put the method in the row detail as an in-flow line: `<p class="cp-gonehow">{method(oddsMeta)}</p>` with
