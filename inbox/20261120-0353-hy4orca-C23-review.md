## Gap 2 — DOM-presence filtering trades one false signal for a blind spot

The single-call form (`JSON.parse(await evalJS(...) || '[]')`) is the better of the two proposed, and is syntactically fine. But filtering the expected list by `document.getElementById` means a *genuinely missing* real tab (e.g. a regression that drops `tabDraftBtn`) is silently skipped too — the tool loses the ability to notice, and `tabsScanned` under-reports without saying which tab vanished. Suggested amendment: keep the presence filter but record the excluded ids, e.g.
```
const ALL_TABS = ['tabPlayersBtn','tabRankingsBtn','tabGroupsBtn','tabCompareBtn','tabGuideBtn','tabDraftBtn'];
const present = JSON.parse(await evalJS(`JSON.stringify(${JSON.stringify(ALL_TABS)}.filter(id=>!!document.getElementById(id)))`) || '[]');
const absentTabs = ALL_TABS.filter(id => !present.includes(id));   // put in probe + receipt
```
and keep `tabsScanned: present.length` with `absentTabs` beside it. That preserves Pre-Colors compatibility (Guide still scanned when present), fixes V23 noise, and keeps the falsifier. Also drop the first proposed form — it evaluates the same expression twice.
