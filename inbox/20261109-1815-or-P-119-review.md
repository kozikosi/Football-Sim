## New findings

**Finding D-019 — `getTeamColor(r.player[2])` and `POS_DISPLAY` referenced but not defined.**
The proposal uses `r.player[2]` for team index and `POS_DISPLAY[r.player[1]]` to get display names like "QB · KC". Both must be confirmed against Pre-Colors' data model or supplied by the Architect. The reviewer should check what array/string indices `pickCritique()` returns — verify the array structure matches the indices used (`[teamIndex]`, `[posCode]`, `[name]`, `[ovr]`, etc.).

**Finding D-020 — 7-column grid (`grid-template-columns: 80px 1fr 100px 80px 1fr 80px 100px`) is too wide for 390 px.**
On 390 px, 7 columns × 80px + gaps = 620 px minimum. The cards will overflow horizontally. On mobile, the proposal does a responsive stack (1 column) which is correct, but it should test the desktop view at ≥760 px per AGENTS.md §10 requirement ("no horizontal scroll at 390 px"). The grid needs a smaller fixed width on mobile or a more compact layout.

**Finding D-021 — Summary header shows "regret" as wins left (negative numbers), but the Owner's P-119 spec doesn't mention summary stats.**
The summary header includes "WINS LEFT" showing negative regrets (e.g., "-0.15"), but the Owner only asked for "fully visual: no paragraph text, no table lines" and "colours read good vs bad picks." Adding aggregate summary stats is a design addition beyond the Owner's spec — it may be too much or not match the Owner's intent of just replacing table rows visually.

**Finding D-022 — `pickCritique()` function signature assumed.**
The proposal calls `pickCritique()` with no args and assumes the return is an array of objects with `.round`, `.pickInRound`, `.v`, `.slot`, `.wasBest`, `.best`, `.regret`, `.flex`, `.player[]`. The existing `pickCritique()` in Pre-Colors returns an array of `{pick, round, player, spot, v, best, wasBest, regret}`. VERIFIED: the indices match the existing function. Good defensive coding.

**Finding D-023 — No 390 px verification in the proposal.**
The proposal has mobile media query `@media (max-width: 760px)` with column stacking, but doesn't verify: foil shimmer text fill doesn't break on very small screens (letter-spacing), verdict badge padding (4px × 10px = ~44px total height might squeeze), insight list text length at 390 px, reduced motion shimmer disabled correctly.

**Finding D-024 — "Left wins" shown as negative number with minus sign, but AGENTS §3 says "integers only."**
The summary shows `r.regret.toFixed(2)` which produces decimals like "-0.15". The style law rule states integers only. This contradicts the Style Law (P-183). The absolute win count could be displayed as an integer (number of picks), while the regret value is a separate metric.
