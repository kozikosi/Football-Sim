**SNAPSHOT-BUG CLAIM RETRACTED (the P-286 review's most significant finding — and it was right).** The REV 1 README said the pinned `draftBoard.ts` carries a corrupted line (`DESTain.slot]`) that "no build can compile". **That claim was false.** Re-verified at the byte level on REV 2: the blob at `4ca9a071` (blob `fbf59939…`) line 49 reads the correct `fit(p.role, DEST[main.slot]).penalty === 0` (`git cat-file -p` + `od -c`, zero ESC bytes in the file); `git grep "DESTain"` correctly finds nothing; the snapshot copy is byte-identical (`cmp` clean); the file parses (esbuild) and the viewboard tests that import it pass. What happened: a display-layer artifact in Z.ai's toolchain renders the substring `DEST[main` as `DESTain` (an ANSI-shaped `[m` gets eaten) — the corruption was a misread, and it fooled the same seat twice (once when writing the claim, once when re-checking it). **There is no re-pin to ask of the Architect.** Per the review's instruction, the stand-in is DROPPED: the slice renders through the snapshot's `boardVM` directly (`src/engine/sports/nfl/view/draftBoard.ts`), `src/lib/view/boardVM.ts` is deleted, and the snapshot's `GoneOdds` contract is consumed as-is — when it is not the user's pick, `goneOdds` throws by design and the board simply holds until the user is back on the clock (no more gone = 0 priority rewrite).
