## 1. Principles
1. **Local first.** localStorage stays the source of truth for play. The server is a replica plus history. Offline play always works; sync never blocks an action (`dispatch` is synchronous; persistence is write-behind, Q9 of 5 Nov).
2. **Whole envelope, never a field merge.** No CRDT, no mutation log, no replay.
3. **Sign-in is optional.** No account = today's behaviour, unchanged.
4. **Every user-owned query goes through one `scopedDb(userId)` module.** A route handler cannot name another user's id.
5. **The server never trusts a client number.** Stats are recomputed from accepted envelopes (Q8).

## 2. Identity and the conflict rule
Server key per save: `(user_id, sport, slot)`. Client key: the existing storage key. Lineage: `saveId`.

Each server row carries a **`server_rev`** (integer, +1 on every accepted write). A client write says which `server_rev` it was based on (`base`, or `null` for "I have never seen this slot"). The server does a compare-and-swap:

- `base == server_rev` (or the slot is empty and `base == null`) → accept, `server_rev + 1`.
- otherwise → **409** with the server's current metadata (no envelope). The client then resolves:

| Case | Rule | Loser |
|---|---|---|
| same `saveId`, remote `saveRevision` higher | pull remote, replace local | local envelope archived as a rung-back |
| same `saveId`, local higher | push with the new base | remote archived as a rung-back |
| same `saveId`, equal `saveRevision`, different `savedAt` | later `savedAt` wins (client clocks can lie: I accept this only as a tie-break) | the other, archived |
| different `saveId` (a **fork**) | **keep both**: the incoming lineage takes a free slot A/B/C if one exists, and the user sees it | if no slot is free: the older lineage is kept as a rung-back and the UI offers "restore it into a slot" |

Why `saveRevision` and not wall-clock "last write": P-254's words are "last-write-wins on the whole save"; two offline devices advancing the same lineage have comparable progress counters but unreliable clocks. This is my **interpretation** (I); it never merges fields and never loses a lineage. If the Owner meant literal wall-clock order, one line changes.

**Rung-back:** keep the last **3** archived envelopes per `(user, sport, slot)`; older ones are deleted when a fourth arrives. History is written only on a conflict, a soft-delete or an explicit restore, never on an ordinary save (write budget, section 7).

**Soft delete:** `DELETE` sets `deleted_at`; the row stays 30 days (I), then a scheduled cleanup removes it. A delete also needs `base`, so a stale device cannot erase a newer save.

**Account switch on one device (the dangerous case).** The client keeps a small record `sim:nfl:sync` = `{ userId, deviceId, serverRev per slot }`, outside the frozen envelope. On sign-in:
- no record, or same `userId` → normal reconcile (section 5);
- record names a **different** user → **do not merge**. Ask: "These saves belong to another account on this device." Options: keep them separate (stay local, signed in as the new user with an empty slate) or import into this account (explicit, per slot). Never silent.

## 3. Tables (D1)
Auth tables (`user`, `session`, `account`, `verification`) are generated by Better Auth's own migration, not hand-written; I record their names only. Everything below is mine. All times are ISO-8601 UTC text. No secondary index unless a query below needs it (each index is an extra row written, V d1/platform/pricing).

```sql
CREATE TABLE saves (
  user_id TEXT NOT NULL, sport TEXT NOT NULL, slot TEXT NOT NULL,
  save_id TEXT NOT NULL, save_revision INTEGER NOT NULL, server_rev INTEGER NOT NULL,
  kind TEXT NOT NULL, schema_version INTEGER NOT NULL,
  engine_version TEXT NOT NULL, data_version TEXT NOT NULL,
  device_id TEXT, saved_at TEXT NOT NULL, updated_at TEXT NOT NULL, deleted_at TEXT,
  envelope TEXT NOT NULL,                       -- the whole envelope JSON, opaque to SQL; <= 256 KB (section 7)
  PRIMARY KEY (user_id, sport, slot)
);
CREATE TABLE save_history (                     -- rung-backs; <= 3 per (user, sport, slot)
  user_id TEXT NOT NULL, sport TEXT NOT NULL, slot TEXT NOT NULL, archived_seq INTEGER NOT NULL,
  save_id TEXT NOT NULL, save_revision INTEGER NOT NULL, reason TEXT NOT NULL,   -- 'conflict-lost' | 'deleted' | 'restored-over'
  archived_at TEXT NOT NULL, envelope TEXT NOT NULL,
  PRIMARY KEY (user_id, sport, slot, archived_seq)
);
CREATE TABLE runs (                             -- the stats ledger; one row per finished run, written once
  user_id TEXT NOT NULL, sport TEXT NOT NULL, save_id TEXT NOT NULL, run INTEGER NOT NULL,
  franchise TEXT NOT NULL, year INTEGER NOT NULL, outcome TEXT NOT NULL,
  w INTEGER NOT NULL, l INTEGER NOT NULL, t INTEGER NOT NULL, pf INTEGER NOT NULL, pa INTEGER NOT NULL,
  undefeated INTEGER NOT NULL, perfect INTEGER NOT NULL,     -- 17-0 flag and 20-0 flag, both recorded (Owner)
  conf_seed INTEGER, engine_version TEXT NOT NULL, data_version TEXT NOT NULL, recorded_at TEXT NOT NULL,
  detail TEXT NOT NULL,                         -- JSON: userResults, playerLines (sparse), pickOverall, seed; ~3-5 KB
  PRIMARY KEY (user_id, sport, save_id, run)
);
CREATE TABLE shares (                           -- immutable snapshots, read-only by token
  id TEXT PRIMARY KEY, token_hash TEXT NOT NULL UNIQUE,   -- SHA-256 of a 128-bit random token; the token itself is never stored
  user_id TEXT NOT NULL, sport TEXT NOT NULL, kind TEXT NOT NULL,   -- 'run' (brag card) | 'save'
  created_at TEXT NOT NULL, expires_at TEXT, revoked_at TEXT, snapshot TEXT NOT NULL
);
CREATE INDEX shares_by_user ON shares (user_id);                   -- list/revoke own shares
```
The `runs` primary key makes a retry or a local-migration replay a no-op (`INSERT OR IGNORE`). Career stats are **folds over `runs`**, never stored counters; a new stat later is a new fold over old rows. Whole-league awards are not stored in v1.

## 4. Routes (all under `/api`; JSON; the Worker runs first for `/api/*` only)
| Route | Auth | Behaviour |
|---|---|---|
| `/api/auth/*` | Better Auth | GitHub (and Google if the spike passes). **No credential routes**: `emailAndPassword` off, asserted by test. |
| `GET /api/saves` | session | Metadata for the caller's slots (no envelopes): slot, saveId, saveRevision, server_rev, kind, savedAt, deleted. |
| `GET /api/saves/:sport/:slot` | session | One envelope. Someone else's row, or none: **404**. |
| `PUT /api/saves/:sport/:slot` | session | Body `{ envelope, base }`. Validates with the same `parseEnvelope` the client uses plus the sport's inner check. 200 `{ server_rev }`, 409 `{ current }`, 413 too big, 422 invalid, 426 if `schemaVersion` is newer than the server knows (never overwrite a newer build's save). |
| `DELETE /api/saves/:sport/:slot` | session | Body `{ base }`; soft delete. |
| `POST /api/saves/:sport/:slot/restore` | session | Restores a rung-back into a slot (body: `archived_seq`, `base`). |
| `POST /api/runs` | session | Body: one or an array (≤ 50) of run records. Server **recomputes** the derived columns from `detail` and ignores client-sent flags that disagree. Idempotent. |
| `GET /api/stats` | session | The folded career summary (legend, first Super Bowl per franchise, top player seasons, best records, 17-0 and 20-0 counts). |
| `POST /api/shares` · `DELETE /api/shares/:id` | session | Create/revoke. Returns the token once. |
| `GET /api/share/:token` | **public** | Read-only snapshot; any other method on this path: **403**; revoked/expired: **410**. Exposes no email, no user id. |

Errors are `{ error: <code>, message }`; unknown route 404. Every response carries `x-api-version: 1`.

## 5. Client sync (local-first)
- **When to push:** end of draft, each committed week, elimination (a run record), `pagehide`/sign-out, and a debounce of ≥ 10 s per slot for anything else. Coalesce: only the latest envelope per slot is sent.
- **When to pull:** on sign-in, on app focus after ≥ 60 s hidden, on a 409.
- **Offline:** a failed push is a `failed` save-status chip, retried on reconnect with backoff (retriable only for network/5xx; 4xx stops and surfaces).
- **First sign-in (local → account migration):** for each slot, local-only → push with `base: null`; remote-only → pull; both → the table in section 2. Runs: send all unrecorded local runs; replay is safe (idempotent). Nothing local is deleted by migration. Old local profile counters, if any exist, import as **one** row marked `legacy-import` in `detail`, never as invented runs (U: I have not yet read `nfl/app/profile.ts` for what it holds).
- **Sign-out:** local saves stay (offline-first, the device's own copy); the sync record is kept so the next sign-in as the same user reconciles instead of re-importing.
- **Session lifetime (Q9):** long-lived refresh, offline play always works, re-auth only on a successful reconnect. Session cookie `HttpOnly; Secure; SameSite=Lax`; Better Auth's `session.expiresIn` 30 days with sliding refresh (I; the exact setting is confirmed in the spike).

## 7. Caps, budget, failure mode
- **Envelope ≤ 256 KB** (largest known: draft pool ≈ 90 K chars, REPORTED; season ≈ 25 KB, REPORTED). Over → 413. A season `detail` ≤ 16 KB.
- **Per user:** 3 slots × 1 sport (v1), history ≤ 3 per slot, runs ≤ 5,000, active shares ≤ 20. Over → 429 with a plain message.
- **Rate limit:** sync routes ≤ 60 requests/min/user. Whether Cloudflare's Rate Limiting binding is available on the Free plan is **U**; if not, the client cadence (section 5) is the limit and the 429 caps above are the backstop. I accept this at hobby scale.
- **Write budget (D1 Free, V):** 100,000 rows written/day; 5 M read; 5 GB total; 50 queries per invocation (a `batch()` is one). An ordinary save is one `UPDATE` (PK only, no secondary index) ≈ 1 row; a run record ≈ 2 rows; a conflict ≈ 3–4. A heavy user doing ten seasons a day is ≈ 250 writes (I), so ≈ 400 such users/day before the free limit. Reads are not the constraint.
- **When the free limit trips:** D1 errors until midnight UTC (V, changelog 2026-09-01). The Worker maps that to **503 `sync-paused` + `Retry-After`**; the client shows "Sync paused, saving on this device" and keeps playing. No data is lost (local is truth). The Owner decides whether to pay ($5/month Workers Paid) if it ever happens.
- **Migrations:** a numbered `migrations/` folder applied with `wrangler d1 migrations apply`; the Worker refuses to serve if `d1_migration` is behind what the code needs (a `/api/health` check reports it).

## 8. Tests (node:test, Miniflare + real D1 binding; engine untouched)
1. **Boundary:** users A and B; for every route A touching B's slot/run/share gets 404 (never 403); no session or a tampered cookie → 401. A mutation test removes the `user_id` predicate and must fail this.
2. **One door:** a source test fails if any SQL naming `saves`, `save_history`, `runs` or `shares` appears outside `scopedDb`.
3. **Share scope:** a token reads exactly one snapshot; write methods → 403; slot X's token cannot read Y; revoked → 410; the response contains no email or user id.
4. **No credential routes:** list all `/api/auth/*` routes; only OAuth start, callback, session, sign-out. `emailAndPassword` off.
5. **Conflict table:** every row of section 2 as a case, plus "stale delete cannot erase a newer save", "newer `schemaVersion` → 426", and "rung-back keeps exactly 3".
6. **Idempotence:** replaying a migration (saves and runs) twice changes nothing.
7. **Recompute:** a run record with a lying `perfect` flag is stored with the server's value.
8. **Caps:** 257 KB → 413; the 5,001st run → 429.
9. **Offline suite unchanged:** the existing suite, run with no session and the network blocked, stays green.
10. **Free-limit mapping:** a simulated D1 limit error becomes 503 `sync-paused`, not a 500.
