# Ratings data gate (Architect, 23 Nov 2026): how the suite runs with the ratings file hidden

**Why.** Owner, 22 Nov: `data/nfl/madden27-ratings.csv` and `madden27-raw-paste.txt` stay out of the first public cutover repo until a specific ruling/NOTICE (`claude/rulings/2026-11-22-owner-via-pickle-76pancakes-name-ratings-hide.md`). Measured on a scratch copy without them (V): 327 tests registered, 315 pass, 12 fail. Twelve test files crash at import (5 read the CSV directly, 7 through `test/nfl/fixture.ts`), and the 107 tests behind them vanish, so a bare green would hide a 119-test loss.

**What was built (no `colors/src` byte changed; no test file edited).**
- `colors/tools/test-gate.mjs`; `npm test` now runs it. **CSV present = full gate:** it spawns the exact old command (`node --test --experimental-strip-types "test/**/*.test.ts"`), output unchanged. **CSV absent = public gate:** runs every file except those in `colors/test/DATA-GATED.json` and prints `DATA-GATED, NOT RUN: 12 files, 119 tests` plus each file's count.
- `colors/test/DATA-GATED.json`: 12 files, 119 tests (boxscore 5, draft 6, legacyprovider 5, lineup 35, playerids 6, players 6, recap 11, resume-determinism 5, store 15, valueprovider 10, versions 7, viewboard 8).
- `npm run test:gate-verify` (needs the CSV): recounts each gated file on its own; fails if the manifest is stale or a file is missing or red. `node tools/test-gate.mjs --record [files]` rewrites the manifest.

**Receipts (V, scratch copy, Node 22.23.5).** Full gate 434/434, exit 0. Public gate 315 pass / 0 fail, exit 0; **315 + 119 = 434**. `tsc:check` 89 (pinned 89), build OK, engine subtree hashes `core ce75f04c`, `sports a9792de4`, `platform dcd97f20` unchanged. Three mutations, each caught: a gated file removed from the manifest = public gate exit 1 (`not ok players.test.ts`); a manifest entry naming a missing file = exit 1; a wrong count (draft 6 to 7) = `--verify` exit 1.

**Rules.** (1) The cutover receipt is the identity above: public pass + manifest total = the full-gate count of the same commit; the new repo's README says "N pass, K data-gated, 0 fail", never "434/434". (2) A new test file that needs the CSV must be added with `--record`; if it is not, the public gate fails it loudly. (3) Adding tests to a gated file needs `--record`; adding tests elsewhere needs nothing. (4) When the Owner rules and the file returns, delete `DATA-GATED.json` entries (or the file) and the gate becomes the plain full run.

**Not covered / U.** `tools/mathlab/*` and `colors/tools/*` read the CSV and fail loudly without it (lab tools, not gates). The gate keys only on `madden27-ratings.csv`: `data/nfl/free-agents-old-ratings.csv` (12 rows, same ovr/spd/str fields) and `player-ids.csv` (names/positions/teams, no ratings) are not hidden by the ruling as written; Owner to say whether the 12-row file is in scope. `data/packs/*.json` (4.6 MB + 3.0 MB fitted pools) were not inspected for per-player values. Whether the merged UI runs with no ratings file is unchecked, and `dist/` is not affected by this change.
