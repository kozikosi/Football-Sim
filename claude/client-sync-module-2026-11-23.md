# Client sync module (Architect, 23 Nov 2026)

**What.** `colors/src/sync/` implements the client half of `claude/account-sync-contract-2026-11-21.md` sections 5 and 9. It imports `core/` only (envelope outer shape, keys, `StorageModule`); nothing from `sports/`, no UI framework, and no `core`/`sports`/`platform` byte changed (V: `git diff HEAD` on those three is empty). Storage, transport, clock, timers and ids are all injected.

**Files.** `types.ts` (`SyncTransport`, `Failure`, `SyncStatus`), `transport.ts` (fetch implementation; classifies every status), `record.ts` (the `sim:nfl:sync` record: `userId`, `deviceId`, `serverRev` per slot, `runsSent`), `sync.ts` (`createSync`, `decide`).

**What the UI wires (Z.ai, after the merge).**
- `createSync({ storage, transport: createFetchTransport(fetch), now: Date.now, setTimer: setTimeout, clearTimer: clearTimeout, newId: crypto.randomUUID, onPulled })`.
- `signIn(userId)`; `needs-account-choice` means show "These saves belong to another account on this device." with `resolveAccountSwitch({action:'keep-separate'})` or `{action:'adopt', slots}`.
- After each local save lands call `notifySaved(slot, 'draft-end' | 'week' | 'elimination' | 'edit')`. `pagehide` calls `flush()`; focus calls `onVisible(hiddenMs)`; `online` calls `onOnline()`; sign-out calls `signOut()` (local saves and record stay).
- `subscribe(fn)` drives the sync chip (idle, syncing, failed + retriable, paused, needs-account-choice, newer-schema). `onPulled(slot)` means a slot changed under the app: re-hydrate it.

**Behaviour (contract rows, each has a test).** Push sends `{envelope, base, deviceId}` with `base` = last `serverRev` seen or `null`. Edits debounce 10 s per slot; draft end, week and elimination push now; notifies coalesce and the latest bytes are read at push time. A 409 refetches the list and applies the conflict table: remote higher pulls (local kept as a local rung-back), local higher pushes, equal revision later `savedAt` wins, different `saveId` keeps both in a free slot (the pulled lineage is rewritten to the free slot) or else the older lineage becomes a rung-back. Network/5xx retry with 1, 2, 4 ... 60 s backoff; `online` retries now; paused waits for Retry-After; other 4xx stop and surface (426 = newer-schema). A local or server envelope that is unreadable or from a newer schema is never overwritten. Finished seasons (`statsRecorded`) go to `/api/runs` once (`runsSent`), and one rejected season does not block the others. Local rung-backs: 3 per slot under `sim:nfl:sync-archive:<slot>:<n>`.

**Receipts (V, scratch copy, Node 22.23.5).** Full gate 460/460 (434 + 26 new); public gate 341 pass + 119 gated = 460; `tsc:check` 89 (pinned 89); build OK; layer tests pass. 26 unit tests against a fake server that implements the base/`server_rev` rules, plus `server/test/client-sync.test.ts` driving the real module and fetch transport through the real API handler on the SQLite D1 stand-in. Six mutations each caught (push without base, equal-revision tie, account guard removed, runs resent, no coalescing, no debounce). One real bug found by a test and fixed (backoff never doubled).

**Not done / U.** (1) Local deletes are not propagated and a slot deleted on another device is not removed here (nothing local is ever deleted); `DELETE`, `restore`, shares and `/api/stats` have no client method yet. (2) `legacy-import` row: `nfl/app/profile.ts` not read. (3) `deviceId` lives in the sync record, not the envelope (the optional envelope field waits for the post-merge re-pin). (4) "Keep separate" only disables sync for the second account on this device; separate local namespaces per account would need engine key changes. (5) `pagehide` delivery depends on the browser; keepalive is used for bodies under 60 KB and the local save is the truth. (6) Not run against real Cloudflare, Better Auth or a real browser. (7) No jitter on backoff. (8) The sync record and archive keys are new `sim:nfl:*` keys; anything that enumerates that prefix must tolerate them.
