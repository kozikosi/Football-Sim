## Ask 3: critique of the plan
- **Right:** Tier 1 and Tier 4; "Z.ai builds, seats verify, Architect reads the diff, never a direct push".
- **Wrong: the tiers divide by task type; the risk is by path.** Evidence: P-317 was labelled "small, anchored" Tier 2 store wiring. VERIFIED it is not: `restoreDraft` rebuilds the draft from the saved record with the default snake order and throws "out of order" when a pick's team differs. Passing `order` in START alone would work live and break every reload. The real fix needed a new record field (`pickSlot`), a validator change in `saves.ts` and an order helper. A "UI wiring" task reached the save format.
- **What would break first:** (1) a Tier 2 patch that looks UI-only and touches persistence; (2) Tier 3 UI built on view-models I am still changing, and on a framework (Svelte vs Vue) that is parked until the R-13 measurement: rework risk; (3) green receipts read as test evidence.
- **Missing:** a path fence (suggest: `colors/src/core/**`, `colors/src/sports/nfl/engine/**`, `app/saves.ts`, `data/**`, `tools/mathlab/**` are fenced; a Z.ai branch touching them fails a check); a patch format (diff stat, test names, fenced-path report) so I read the cheap summary first; a rollback rule; the fact that review is not free.
- **Refuse:** direct pushes to my branch; Z.ai editing fenced paths; his re-pin verification counting as a re-pin; any seat declaring final acceptance.
- **What I would do instead (MEDIUM confidence):** divide by interface, not by task. Z.ai owns the UI tree entirely against a view-model contract I publish and freeze (types plus contract tests); I review contract changes, not UI diffs. That cuts my review cost more than Tier 3 does. Cost: the view-model API must be frozen first, and cutover integration needs one joint pass. Prerequisite: the framework decision, or a framework-neutral contract.
- **What the seats can prepare so my time goes to the engine:** receipts and fresh-clone gates per commit; per-patch diff-stat and fenced-path reports; merge dry-run conflict inventory; manifest regen; claim checks that report numbers match the JSON; one-page digests of relays.
