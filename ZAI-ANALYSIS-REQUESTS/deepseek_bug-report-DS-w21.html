3. Reported Bug Cluster A — Draft Board Broken

3.1 Reported symptoms

On first page load, clicking DRAFT produces:

#Symptom
A.1Wins and Priority columns of the draft board show dashes or disappear entirely
A.2CPU never starts drafting, even when user is at pick 1.32 (userIndex = 31 — 31 CPU picks should run before user)
A.3After the user picks, the player is not added to the depth chart
A.4CPU still doesn't resume drafting after the user's pick
User's original report: "the priority and WINS numbers have disappeared and the computer doesn't start drafting until my first selection even though I'm 1.32. Even after I select players they are not added to my depth chart and the cpu doesn't start drafting. This glitch has happened before."

3.2 Root-cause hypothesis

renderDraftLive() wraps the board render in try/catch:

try { renderDraftBoard2(); } catch(err) { try { zpbFallbackBoard(err); } catch(e2){} }

On any throw, zpbFallbackBoard(err) fires — a minimal board with no Wins, no Priority, and only conditional Draft buttons. This exactly matches A.1.

A separate try/catch around renderDraftRoster2():

try { renderDraftBoard2(); } catch(err) { ... }
try { renderDraftRoster2(); } catch(err) {}

Means if renderDraftRoster2 throws, the depth chart stays frozen at nothing → A.3.

The state machine freeze (A.2, A.4) has three independent candidates: (a) wave-13 didn't load so zpbWelcomeCine is missing but the try/catch fails to fall through; (b) cpuBias/cpuNoise/cpuMiss corrupt global draftSim, making simRecs() return garbage; (c) the watchdog 25s deferral never force-starts.

A3 — pk.r1 / pk.r2 / pk.r3 are undefined

zpbPackFor() returns a pack with properties:

raw, accL, accD, acc2L, acc2D, acc3L, acc3D, txL, txd, sud,
hairL, hairD, bgL, bgD, on, onD,
g1..g6, b1..b6, o1..o4, d1..d2  (+ dark variants)

There is no r1, r2, or r3. But two functions reference pk.r1:

// zpbLeagueBarsHTML
const uv = pk ? '--zrb:' + pk.accL + ';--zr1:' + pk.r1 + ';' : '';

// zpbMetricsHTML
const uv = pk ? '--zrb:' + pk.accL + ';--zr1:' + pk.r1 + ';' : '';

Result: --zr1:undefined; is set as a CSS custom property. Browsers treat "undefined" as a valid custom-property value, so var(--zr1, fallback) resolves to the string "undefined" instead of using the fallback — the whole gradient / box-shadow declaration is invalid at computed-value time and silently drops.

Fix: Use the same value zpbRowVars uses:

function zpbR1(pk){
  return zpbRgba(window.zpbLift ? zpbLift(pk.accL, 0.58) : pk.accL, 0.12);
}
const uv = pk ? '--zrb:' + pk.accL + ';--zr1:' + zpbR1(pk) + ';' : '';

Or better: add r1, r2, r3 fields to the pack object inside zpbPackFor so both paths share one source of truth.

A6 — cpuBias / cpuNoise / cpuMiss corrupt global draftSim

function cpuBias(teamIndex, group){
  draftSim.bias = draftSim.bias || {};
  const b = draftSim.bias[teamIndex] = draftSim.bias[teamIndex] || {};
  if(b[group] == null) b[group] = ...;
  return b[group];

function cpuMiss(teamIndex){ draftSim.missP = draftSim.missP || {}; ... }

These mutate the global draft even though cpuPick(ti, st) accepts a st parameter.

During simRecs(), the board render runs cpuPick 12 times with st = sim, each trial drafting ~31 picks = ~372 cpuPick calls per board render — all writing to the real draftSim.bias, draftSim.noiseSd, draftSim.missP.

Because bias magnitude drives the v values that feed simRecs().later (which feeds pri), random-walked bias flattens all priorities toward zero. This is a strong candidate for "Priority disappeared on first try".

Fix — thread st through:

function cpuBias(teamIndex, group, st){
  st = st || draftSim;
  st.bias = st.bias || {};
  const b = st.bias[teamIndex] = st.bias[teamIndex] || {};
  if(b[group] == null) b[group] = Math.random() < 0.33 ? 0.003 + Math.random()*0.03
                            : Math.random() < 0.35 ? 5 + Math.random()*8
                            : Math.exp(0.5*randNormal());
  return b[group];
}
function cpuNoise(teamIndex, st){
  st = st || draftSim;
  st.noiseSd = st.noiseSd || {};
  if(st.noiseSd[teamIndex] == null) st.noiseSd[teamIndex] = 0.1 + Math.pow(Math.random(), 1.0) * 4.0;
  return st.noiseSd[teamIndex];
}
function cpuMiss(teamIndex, st){
  st = st || draftSim;
  st.missP = st.missP || {};
  if(st.missP[teamIndex] == null) st.missP[teamIndex] = Math.pow(Math.random(), 0.9) * 0.95;
  return st.missP[teamIndex];
}

A9 — winsAt / effOvr can throw for edge players

winsAt → effOvr → flexPenaltyFor → flexRule. For P and FB players, POS_SLOT_MAP exists but FLEX doesn't cover every slot, so flexPenaltyFor can hit EMERGENCY_PENALTY (fine). But slotWins(slot, ovr) for slots the player can't legally occupy may return NaN if p[3] is undefined.

Fix:

function winsAt(p, slot, base){
  if(!p) return 0;
  const ovr = effOvr(p, slot);
  if(!isFinite(ovr)) return 0;
  return slotWins(slot, ovr) - slotWins(slot, base == null ? WINS_BASE : base);
}

F7 — zpbDraftRecover guarantees progress

function zpbDraftRecover(err){
  try { console.warn('Z-post-blue draft auto-recover:', err); } catch(e){}
  try {
    const feed = document.getElementById('draftRecentPicks');
    if(feed && !feed.children.length)
      feed.innerHTML = '<div class="narr">The draft engine hiccuped once — retrying.</div>';
  } catch(e){}
  try { processUntilUserTurn(); return; } catch(e2){}
  try { renderDraftLive(); } catch(e3){}
  try { zpbFallbackBoard(err); } catch(e4){}
  if(typeof draftSim !== 'undefined' && draftSim && !draftSim.awaitingUser
     && draftSim.pos < draftSim.order.length){
    draftSim.pos++;   // skip the offending pick — one bad pick never freezes the draft
    try { processUntilUserTurn(); } catch(e5){
      try { slowTimer = setTimeout(stepSlow, 750); } catch(e6){}
    }
  }
}
