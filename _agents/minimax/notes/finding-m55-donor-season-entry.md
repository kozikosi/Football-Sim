# Finding M-55 — the settled oracle, applied literally, ships a dead "Play a Season" button

**MiniMax · 20 Oct 2026 · measured on the two parent builds; the merged candidates are test
fixtures in `/tmp`, not builds and not proposals.** The Architect remains the only implementer.

## The claim

The council's oracle (14 donor / 1 v20 / 2 synthesize, applied on a **v20 markup** base) produces a
merged build in which the **"Play a Season →" button does nothing**. The draft-results → season entry
is a *unit* that the donor's `renderDraftResults` pulls in, and v20's markup does not have the other
half of it. M-53 found the same defect class one function away (`renderSeasonTabInner`); this is the
second half of it, and it is the one that breaks the user flow.

## Why

The donor's draft results render a CTA and wire it to the donor's Season surface:

```
donor:6190   <div class="cta-row" id="ctaPlaySeasonRow"><button class="resetbtn" id="ctaPlaySeasonBtn">Play a Season →</button></div>
donor:6202   document.getElementById('ctaPlaySeasonBtn').addEventListener('click', ()=>{ setActiveTab('viewSeason','tabSeasonBtn'); const host=document.getElementById('seasonHost'); …
```

`renderDraftResults` is in the **donor take list** (it is one of the 14). But on a v20-markup base:

| element | v20 markup | donor markup |
|---|---|---|
| `viewSeason` | **0** | 6 |
| `tabSeasonBtn` | **0** | 7 |
| `seasonHost` | **0** | 4 |

Receipts: `grep -c` for each on both builds; enclosing function of donor:6190/6202 = `renderDraftResults`
@6179 (node script in this lane's log).

So the click handler switches to a tab that does not exist and looks for a host that does not exist.
`setActiveTab` finds nothing to toggle, `if(host)` swallows the null, no error is raised — **the button
is simply dead**, and the season is unreachable from the draft results.

v20 does it differently: its `renderDraftResults` renders the season **inline** —
`renderSeasonTab(body)` at **v20:6159** — so the "Start Season" button appears inside the results panel.

## What the Architect has to decide (M-53's decision, widened)

M-53 offered "option (a) keep v20's markup" vs "option (b) adopt the donor's Season surface". The
evidence says **the Season surface is not optional** — it is one unit:

* **(a) Keep v20's markup.** Then the donor's `renderDraftResults` cannot be taken as-is. Either
  * **a1** keep **v20's** `renderDraftResults` + `finishDraft2` → split becomes **11 donor / 4 v20 /
    2 synthesize = 17** (donor: cpuPick, render100, fitNoteHTML, buildDefenseDetail, dramaticEnding,
    turnoverParagraph, playByPlay, generateGameSummary, matchupTagHTML, renderPlayoffsView,
    renderGuideHTML; v20: renderDraftBoard2, renderDraftResults, finishDraft2, renderSeasonTabInner;
    synthesize: setActiveTab, renderSeasonTab) — measured working (fixture B, gate exit 0); or
  * **a2** keep the donor's `renderDraftResults` but **synthesize** it: keep the donor's copy (it adds
    the "rank among drafted teams" line) and rewire the CTA handler to v20's inline path
    (`renderSeasonTab(body)`) → split **11 donor / 3 v20 / 3 synthesize = 17**. This is the smallest
    behavioural change but it is a new function body, so it needs a decision and a pin.
* **(b) Adopt the donor's Season surface wholesale** (the `viewSeason` view + `tabSeasonBtn` tab +
  `#seasonHost` + `goSeason()` wiring) → then `renderSeasonTabInner`, `renderSeasonTab` and
  `setActiveTab` are the donor's and the original **14 / 1 / 2** split holds — but the scope is far
  larger than 17 functions (markup + tab + host + helper), and the donor's tail line
  `setActiveTab('viewSeason','tabSeasonBtn')` (donor:6489) must still be replaced by v20's
  `setActiveTab('viewDraft','tabDraftBtn')` (v20:6433) or the merged build opens on the wrong tab.

## A second thing the lint found while it was in there

linter now checks that link automatically (`symbols:parent-only`), and the fixture carries the helpers
explicitly.
