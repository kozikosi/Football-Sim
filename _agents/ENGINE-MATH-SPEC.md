## 1. Principle
The integer table in §2 **is** the specification. The engine is fitted so each spot's measured value equals its weight in one fixed unit: **1 weight point = 0.00254 wins over a 70→90 upgrade** (QB 1000 = 2.54 wins). The unit is a calibration constant, not a ranking rule.

## 3. Engine changes (exact literals generated, not typed: `tools/mathlab/results/engine-patch-2026-10-26-dime.js.txt`, `flex-engine.js.txt`; the same text is applied to Pre-Colors by `apply-math-patch.mjs`)

- **QB run + WR block** (new, OVR-based so static wins stays a function of the player's OVR): `QB_RUN_C = 0.0194` pts per QB OVR point; `WR_BLK_C = 0.01147` on the mean of WR1–3. About 8% of QB value and 0.04 wins per WR at 70→90. **INFERRED magnitudes** (P-192).
- **Punter:** `PUNT_PTS 1.6→1.084` (P 70→90 = 0.25 wins, half a kicker). **Fullback:** unchanged `olRun.FB`; measured 0.077 wins at 70→90 (Z.ai's brief quotes 0.034, which matches an 80→90 step, INFERRED).
- **DIME (new slot #29, `DEF_SPECS.covDime`, `DIME_W = 0.15`):** the Owner's description (≈10% of snaps, 3rd/4th and long, late in games) is modelled as a **fixed situational share of the coverage rating**, not as a third package in `DEF_OPTS`. Reason (VERIFIED by construction): the engine picks the best package per game, so a package option would run dime on every snap and overvalue the slot about tenfold. `coverage = (1−0.15)·coverage_pkg + 0.15·covDime`, with `covDime = {CB1 1.4, CB2 1.15, CB3 1.0, DIME 1.0, SS 0.8, FS 0.8, MIKE 0.4}` (WILL and SAM are off the field). `0.15 = 10% snap share × 1.5 passing-down leverage`; **the 1.5 is INFERRED** (P-196). Applies to coverage only: dime snaps are passing snaps, run defense is untouched. Sensitivity (VERIFIED, before refit): w 0.10 → DIME 0.06 wins (20), 0.15 → 0.09 (40), 0.20 → 0.12 (50); other spots move ≤ 20 points. WILL drops ~20 because it loses coverage share on those snaps, SAM is already near zero. **DIME is a slot, not a dataset position** (tags in the 1,200 players: no DIME): the 4th CB, or a flexed S/CB/WR, fills it; empty = 70. **Draft length becomes 29 rounds** (`TOTAL_ROUNDS = ROSTER_SLOTS.length`), was 26 starters (+FB, P = 28).
- **Returners** (design, not fitted; a post-draft assignment, so no draft-slot effect): keep total `RET_PTS 2.36`, split **kick 1.50 / punt 0.86**. `krScore = .50spd+.20agi+.20cod+.10awr` (today's `returnerRating`); `prScore = .30spd+.25agi+.25cod+.20awr`. Default KR = best `krScore` among eligible starters; **default PR = second best by `krScore`** (Owner); the user may pick any eligible starter for either role. Term: `KR_PTS·(exp((kr−82)/45) − exp((lg.kr−82)/45)) + PR_PTS·(…pr…)`. A player excellent at both is worth ~0.3 wins, less than one great kicker. **The 2.36 total and the split are UNKNOWN-calibrated** (P-191).

## 11. Defensive aggressiveness: cautious / balanced / aggressive (Owner, 26 Oct)
**What the Owner asked:** aggressive = blitz-heavy, more sacks and takeaways, more big plays given up; cautious = the opposite. **Built as engine math (VERIFIED, lab only; no product file touched); the UI is Z.ai's.** Exact code: `tools/mathlab/results/defposture-product.js.txt` (the lab runs that same text), one anchor in `matchupModel`'s return.
- **Interface:** `plan.def.aggr` ∈ `cautious | balanced | aggressive`. Omitted = balanced = **bit-identical to the engine today** (test A1), so every existing caller, the slot-value table and the fit are untouched. It is **not** a package in `DEF_OPTS`: the best-plan search would otherwise always pick the better end and distort the position values.
- **Effects, linear in b (cautious −1, balanced 0, aggressive +1), so the two ends are exact mirrors:** sacks × (1 + 0.22 b) · takeaways × (1 + 0.13 b) · passing yards allowed × (1 + 0.059 b · (1 − 0.25 zc) · (1 + 0.20 zq)) (these are the big plays) · spread of outcomes × (1 + 0.06 b). Run yards untouched. `zc` = this defense's coverage vs league ÷ 10; `zq` = the opposing QB vs league ÷ 10 (each clamped ±1.5).
- **Measured at a league-average matchup:** points allowed change 0.00 for both ends (the big-play constant is solved so the net is zero; solved 0.0587, shipped 0.059). Per game: sacks 1.73 / 2.22 / 2.71, takeaways 1.06 / 1.22 / 1.38, passing yards 203 / 215 / 228, spread 7.5 / 8.0 / 8.5 (cautious / balanced / aggressive).
- **It is a matchup choice, not a free lunch (VERIFIED):** points allowed vs balanced, aggressive: own coverage +10 → −0.47 (good), −10 → +0.59 (bad); facing a QB +10 → +0.40 (bad), −10 → −0.35 (good). Cautious is the mirror. Seeded game simulation (4,000 games, equal teams, same random numbers for each posture): home win% 55.8 / 56.6 / 55.6 (within noise); away sacks 1.68 / 2.21 / 2.70, takeaways 1.06 / 1.20 / 1.40, passing yards 191 / 203 / 215, points-allowed spread 7.1 / 7.5 / 8.2, 330-yard passing games 0.5% / 1.3% / 3.2%. Against a 92 QB the 330-yard share reaches 13.9% when aggressive.
- **CPU rule, measured on the 32 real rosters (992 matchups):** a pure best-response by win probability picks cautious ~50% / aggressive ~50% / balanced ~0.5% (balanced is never optimal at the margin), and the best choice depends on the opponent for all 32 teams. **Recommended rule: pick the best posture only if it gains ≥ 0.5 win-probability points, else balanced:** 30% cautious / 48% balanced / 22% aggressive. Mean gain from choosing well is +0.67 points, up to +3.4, so it matters at the margin and cannot dominate. The user's setting is always their own.
- **Tests (all PASS, `node tools/mathlab/defaggr.js <html> 4000`):** A1 identity · A2 EV-neutral (< 0.02 pts) · A3 aggressive ordering · A4 cautious mirror · A5 symmetry within 1% · A6 coverage/QB interactions · A7 seeded sim agrees · A8 no free lunch (N ≥ 4000) · A9 no page errors. **Break test (VERIFIED):** flipping the takeaway sign fails A2, A3, A4, A6, A7, A8.
- **INFERRED, needs evidence (P-197):** the sack (+22%), takeaway (+13%) and big-play (+5.9% yards) magnitudes, the 0.06 spread, and the interactions (0.25, 0.20). The shapes follow the Owner's description; the sizes are mine. Run yards could also move (blitz exposure to big runs); not modelled.
- **Not measured:** the game recap text (what the box score says about the blitz), the 3-4 case (same formula), late-game script interaction.
- **What the build does:** `simulateGame` sets `plans.<side>.def.aggr` from `seasonState.dAggr[team]` (user choice, else the CPU rule); the guide and recap read `m.posture` (`{b, zc, zq, dPass, dSack, dTO, net}`) to explain the choice.
