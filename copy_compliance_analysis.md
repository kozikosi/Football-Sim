## The "Hidden, Not Deleted" Trap

**Owner instruction:** *"Realism audit"* and *"Does the model predict real results?"* leave the screen but **the numbers are still computed and stored** — so those two blocks must be **hidden, not removed**.

A copy pass that greps those strings out of the file would break the computation.

- The table contains projected vs real record comparisons, threshold stats, etc.
- **Computation happens in: league100/agg functions, NOT in this rendering**

**Block 2: "Does the model predict real results?"**
- Rendered by: `sec('Does the model predict real results?', <p>...</p>)` at position ~633379
- Creates: `<details class="panel">` with summary "Does the model predict real results?"
- Contains: correlation 0.66, Spearman 0.69, typical miss 2.6 wins, spread 2.5 vs 3.4
- **Computation happens in: the 20-season projection comparison, NOT in this rendering**

### How to Hide (not remove):

The `sec()` function creates `<details class="panel">` elements. To hide these blocks
from the UI while keeping the computation intact:

**OPTION A (RECOMMENDED):** Add `hidden` attribute to the `<details>` element:
- Change: `<details class="panel" style="margin-bottom:14px;">`
- To: `<details class="panel" style="margin-bottom:14px;" hidden>`
- This is the most targeted approach — only affects these two panels
- The computation remains intact because the numbers are generated by separate
  simulation functions, not by the rendering

**OPTION B:** Modify the `sec()` function call to pass hidden mode
- Would need a 4th parameter or a different mechanism

**OPTION C:** Add CSS to hide closed details panels
- `details.panel:not([open]) { display: none; }`
- Affects ALL details panels on the page

**RECOMMENDED: Option A** — add the `hidden` attribute specifically to these two
`<details>` elements.
